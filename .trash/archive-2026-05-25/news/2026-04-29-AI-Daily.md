## 重点事件

### 1. Anthropic 发布 Claude for Creative Work — 五大创意软件 connector
- **来源**: [Anthropic News](https://www.anthropic.com/news/claude-for-creative-work)
- **发生了什么**: Anthropic 联合 Blender、Autodesk、Adobe、Ableton、Splice 推出一组 connector，让 Claude 直接读写这些创意软件的工程文件、调用其原生功能（建模、合成、采样调度等）。
- **背景**: Anthropic 此前主打 coding 与企业知识工作场景，创意领域基本是 Adobe Firefly / Runway / Suno 等专用模型的天下。这次直接绕过"AI 自己生成像素"的路线，改走"AI 操纵专业工具"的路线。
- **分析**: 这是 MCP 战略的延伸：与其和 Adobe 比图像质量，不如让 Claude 成为 Blender/AE 里的"会写脚本的实习生"。对专业用户的吸引力 > 通用生图模型，因为输出仍然是"工程文件"而非"成品像素"，可控、可改、可商用。Adobe/Autodesk 愿意合作说明它们也意识到必须把 LLM 接入而不是自建模型。Splice 入场预示音乐 sample 调用将走 agentic 路线。
- **影响与关注点**:
  - 关注 connector 的 MCP server 实现细节是否开源（决定第三方能否复刻）
  - 评估 Claude + Blender 在批量 3D 资产生成场景的成本曲线
  - 我们的 agent 工具链可以参考其 connector 设计模式

### 2. Claude.ai / API / Claude Code 全线宕机 78 分钟
- **来源**: [Claude Status](https://status.claude.com/incidents/9l93x2ht4s5w)
- **发生了什么**: Apr 28 17:34–18:52 UTC，Claude.ai、Console、API、Claude Code、Cowork、Gov 全线 elevated errors，登录路径首当其冲。
- **背景**: 过去一个月这是第二次大规模 auth 问题，叠加上周 Anthropic 一直在做 Sonnet 4.5/Opus 4.7 的流量切换。
- **分析**: 单点鸡蛋越来越多——Claude Code 把后台依赖深度绑死在 claude.ai 登录链路上，一旦 auth 出问题，本地 IDE agent 也跟着死。这是"全栈 agent 平台"的副作用：可观测性变差，故障半径扩大。对依赖 Claude Code 跑 CI/cron 的团队是真实生产风险。
- **影响与关注点**:
  - 我们的 cron / agent 任务对 Anthropic 的依赖必须有 fallback（OpenAI/本地模型）
  - 评估在 Claude Code 之外预留 OpenCode / Codex CLI 的双轨

### 3. OpenAI 上架 AWS Bedrock — Azure 独占时代结束
- **来源**: [Stratechery 访谈](https://stratechery.com/2026/an-interview-with-openai-ceo-sam-altman-and-aws-ceo)
- **发生了什么**: AWS 与 OpenAI 宣布 Bedrock Managed Agents，把 OpenAI 前沿模型打包进 AWS 原生 agent runtime（identity、权限、状态、日志、治理一体）。
- **背景**: 2023 年 OpenAI 与微软的独占协议本质是"算力换股权"。随着 OpenAI 自建数据中心 + 与 Oracle/Broadcom 合作，独占早已名存实亡，本次只是补上 AWS 这块版图。
- **分析**: 对企业客户是好消息——数据不用搬出 AWS 就能跑 GPT。对 Azure 短期是利空（OpenAI 收入分成减少），但长期反而健康（不用再无限补贴 OpenAI 推理）。真正的赢家是 Bedrock 的 agent runtime 层：身份/权限/审计这些"无聊但必要"的能力比模型本身更有粘性。
- **影响与关注点**:
  - Bedrock Managed Agents 的 API 形态值得对标（与 OpenAI Assistants/Anthropic MCP 对比）
  - 多云策略下，"agent runtime"层会成为锁定客户的新战场

### 4. GitHub Copilot 转向 usage-based billing — agent 经济学绷不住了
- **来源**: [Where's Your Ed At](https://www.wheresyoured.at/ais-economics-dont-make-sense/)
- **发生了什么**: GitHub 宣布 Copilot 从 $10/月 包月转向按量计费，官方理由是"agentic 用法成默认，单次自主编码会话可能跑数小时，无法继续补贴"。Ed Zitron 援引内部数据：今年前几个月 Copilot 平均每用户净亏 $20+/月。
- **背景**: Copilot 一年前还只是 IDE 内补全，现在已经是能在整仓库迭代的 agent 平台。每次 agentic 任务消耗的 token 是补全场景的 100x 起。
- **分析**: 这是整个行业的预演：所有"$20 包月 unlimited"的 agent 产品都撑不到 2027。下一波要么涨价、要么按量、要么模型小型化。OpenAI/Anthropic 自己的 Pro 套餐也面临同样压力（已经有 weekly limit 了）。对自建 agent 链路的团队是利好——本地 7B/14B 模型 + 选择性调用前沿 API 的混合架构性价比拉开差距。
- **影响与关注点**:
  - 重新评估我们 cron/daily 任务的 token 成本，识别可降级到本地模型的环节
  - 若依赖第三方 agent SaaS，预算需按"token 量"而非"人头"重做

### 5. Augment Code 研究：AGENTS.md 写得好抵一次模型升级
- **来源**: [Augment Blog](https://www.augmentcode.com/blog/how-to-write-good-agents-dot-md-files)
- **发生了什么**: Augment 用内部 AuggieBench 对比加/不加 AGENTS.md 的 PR 质量，发现优质 AGENTS.md 带来的提升相当于把 Haiku 升级到 Opus，而劣质的反而比没有更糟。
- **背景**: AGENTS.md 已是 Cursor / Claude Code / Codex / OpenCode 的事实标准。
- **分析**: 关键模式："progressive disclosure" — 100~150 行高层概览 + 按需加载的 reference files，比一篇 2000 行万事屋更好。这与 skill 系统的设计哲学完全一致：上下文窗口是稀缺资源，把详细内容放在可加载文件里。
- **影响与关注点**:
  - 审计自己仓库里的 AGENTS.md / CLAUDE.md，凡 >300 行的拆分到 references/
  - skill 写作规范应明确"主文件保持简洁，细节放 linked files"
