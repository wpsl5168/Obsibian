# AI Daily — 2026-05-04

## 一句话总览
五一假期周一，三大厂的"代理工程化"叙事进一步收敛：OpenAI 推 Symphony 编排开源规范并把 Codex/Managed Agents 接入 AWS；Anthropic 强化 Claude Opus 4.7 与"创意工作"产品化；Google 一口气铺开 Gemini 3.1 全家族 + Gemma 4。安全侧 Mercor 4TB 语音样本泄露给所有用 RLHF/标注外包的团队敲了警钟。

## 重点事件

### 1. OpenAI 发布 Symphony — 开源代理编排规范
- **来源**: [OpenAI News](https://openai.com/news/) (Apr 27, 2026)
- **发生了什么**: OpenAI 发布 Symphony，一个面向多代理工作流的开源 orchestration spec；同期宣布 OpenAI 模型、Codex 与 Managed Agents 上线 AWS（Apr 28），并与 Microsoft 进入"下一阶段合作"，结束独占与收入分成（Bloomberg）。
- **背景**: GPT-5.5 (Apr 23) 之后，OpenAI 把战略重心从"单模型"切换到"代理执行 + 多云分发"。Microsoft 独占的解除是 2019 协议以来最大变化。
- **分析**: Symphony 是想抢 LangGraph / OpenAI Swarm / Anthropic MCP 留下的"代理编排标准"空位，复用 OpenAI 的开发者势能。AWS 落地意味着企业客户终于可以在自己 VPC 里跑 Codex/Agents，监管/数据驻留这条最后一公里通了。Microsoft 关系松绑后，Azure 不再是默认平面，OpenAI 走向"多云 + SaaS"双轨。
- **影响与关注点**:
  - 评估 Symphony 是否值得替换我们当前的代理编排栈（vs LangGraph/MCP）
  - 若有合规客户需求，AWS 上的 Managed Agents 可立即纳入选型
  - 关注 OpenAI API 在 AWS Bedrock 上的定价与 SLA

### 2. Google DeepMind 一周连发 Gemini 3.1 全家族 + Gemma 4
- **来源**: [DeepMind Blog](https://deepmind.google/discover/blog/) ; [Gemma 4](https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/)
- **发生了什么**: 短时间内推出 Gemini 3.1 Pro / Flash / Flash-Lite / Flash TTS / Flash Live、Nano Banana 2（图像）、Lyria 3 Pro（音乐）、Gemini Robotics-ER 1.6，外加开源 Gemma 4 主打"byte-for-byte 最强开源模型"，研究侧发表 Decoupled DiLoCo（分布式训练）。
- **背景**: Google 在保留闭源旗舰的同时，用 Gemma 4 抢回开源叙事，回应 Llama / DeepSeek / Qwen 的压力。
- **分析**: 命名密集到刻意——这是产品节奏战，不是技术拐点。真正值得看的是 Decoupled DiLoCo（弱网/异构集群训练，对自建训练栈有意义）和 Gemma 4（如果 byte-level tokenizer 跑分坐实，多语言/代码场景会很香）。Robotics-ER 1.6 是 Gemini 多模态向具身智能的延伸，但短期商业化弱。
- **影响与关注点**:
  - 把 Gemma 4 加入本地推理候选，对照 Qwen3 / Llama 4 跑一轮 benchmark
  - Gemini 3.1 Flash-Lite 价格如果再降，长上下文召回类任务可考虑迁移
  - DiLoCo 对我们 GRPO 类训练实验的弱机房环境有参考价值

### 3. Anthropic：Claude Opus 4.7 + 创意工作产品线
- **来源**: [Anthropic News](https://www.anthropic.com/news) (Opus 4.7: Apr 16; Claude for Creative Work: Apr 28; Amazon 5GW: Apr 20)
- **发生了什么**: Opus 4.7 在 coding / agents / 多步任务上明显增强；Claude Design 与"Claude for Creative Work"把产品扩展到设计/原型/幻灯片等长尾创意场景；同时与 Amazon 签下最高 5GW 算力扩容。
- **分析**: Anthropic 的策略一直是"少而准"——一个旗舰 + 几个垂直产品。5GW 算力（约相当于 5 个核反应堆）说明 Anthropic 押注未来 18 个月的训练需求会再翻一个数量级。Claude Code/Design 这条产品线已经形成"代码 + 设计 + 写作"三件套，对个人开发者比 GPT 更黏。
- **影响与关注点**:
  - Claude Code for Web 在 Simon Willison 等高产用户手里已经能"在手机上构建工具"，值得在我们的 Hermes skill 体系里对齐
  - Opus 4.7 在长上下文 agent 上换 GPT-5.5 做 A/B
  - 关注 5GW 算力对未来 Sonnet/Haiku 价格的下行压力

### 4. Mercor 数据泄露：4TB 语音样本被盗
- **来源**: [Oravys blog](https://app.oravys.com/blog/mercor-breach-2026) (Apr 27, 2026)
- **发生了什么**: AI 数据标注/合同工平台 Mercor 被披露泄露 40,000 名 AI 承包商的 4TB 语音样本。
- **分析**: 这是 Scale/Mercor 这类"人类反馈数据"中介必然要面对的责任。语音样本意味着声纹克隆、社工攻击的攻击面被打开。所有依赖外包标注/语音 RLHF 的产品方都该重新审视供应商的数据隔离与销毁链路。
- **影响与关注点**:
  - 审计我们使用的外部标注/数据采集供应商的 SOC2 与数据驻留条款
  - 若产品有语音功能，加上 liveness / 声纹反欺诈层
  - 关注后续是否触发监管行动，参考 GDPR/CCPA 罚则

### 5. Codex CLI 0.128 引入 `/goal` 指令 & Specsmaxxing 兴起
- **来源**: [Simon Willison](https://simonwillison.net/) ; HN: [Specsmaxxing](https://acai.sh/blog/specsmaxxing) (146 points)
- **发生了什么**: OpenAI Codex CLI 0.128 加入 `/goal` 指令，允许声明意图后让代理自主拆解；社区开始推 "Specsmaxxing"——用 YAML 写 spec 而不是 prompt 的工程化范式，HN 热议。
- **分析**: 趋势很清晰：从 prompt engineering → spec engineering。当代理能力够强后，人类输入的最佳形态是"结构化目标 + 验收标准"，而不是自然语言指令。这跟我们 plan / writing-plans skill 的方向一致。
- **影响与关注点**:
  - 把 `/goal` 模式映射到 Hermes 的 plan + subagent-driven-development 工作流
  - 评估在 Hermes 内置 YAML spec 模板（验收 / 边界 / 约束三段式）
