# AI Daily — 2026-05-03

## 一句话总览
开源权重模型 Kimi K2.6 在第三方编程竞赛中力压 GPT-5.5/Claude Opus 4.7/Gemini Pro 3.1 拿下冠军；同日 xAI 放出 Grok 4.3、IBM 开源 Granite 4.1、PyTorch Lightning 出现 Shai-Hulud 恶意依赖供应链攻击，整条 AI 供应链既"卷上去"又"塌下来"同步进行。

## 重点事件

### 1. Kimi K2.6 在 Word Gem Puzzle 编程竞赛拿下冠军
- **来源**: [thinkpol.ca 报道](https://thinkpol.ca/2026/04/30/an-open-weights-chinese-model-just-beat-claude-gpt-5-5-and-gemini-in-a-programming-challenge/) | HN 296 分讨论
- **发生了什么**: Rohana Rezel 主办的 AI Coding Contest 第三方实测中，Moonshot 的开源权重模型 Kimi K2.6 以 22 分（7-1-0）登顶，第二名是 Xiaomi 的 MiMo V2-Pro（20 分），西方旗舰 GPT-5.5 第三、Claude Opus 4.7 第五、Gemini Pro 3.1 与 Grok Expert 4.2 并列第六。
- **背景**: 比赛任务是 10×10 到 30×30 的滑块组词游戏，每轮 10 秒墙钟，强制模型在 TCP 协议下实时读盘+决策。Kimi 采用贪心滑动+词价回填的稳态策略，在 30×30 高扰动盘面上把对手甩开；Claude 和 MiMo 完全不滑动，靠初始扫描，盘越乱越拉胯。DeepSeek V4 直接因协议错乱垫底。
- **分析**: 这次评测的价值不在排名本身（赛题偏特定），而在于揭示了"工程容错+协议鲁棒"已经成为前沿模型的隐性维度——不会滑动 ≈ 不会用 tool；发不出合法 JSON ≈ agent 直接死。开源权重在头部任务上能压住闭源，意味着 Anthropic/OpenAI 的护城河已经从"模型能力"明显移到"产品+生态+harness"。Moonshot/Xiaomi/Zhipu 三家中国实验室同时进前四，是个结构性信号。
- **影响与关注点**:
  - 评估自家 agent 时，加一条"协议健壮性"基准（malformed JSON 比例、超时回退）
  - K2.6 权重值得拉本地跑一遍，对比 Codex/Claude 在我们真实 codebase 上的表现
  - 开源权重 + 自托管推理的 TCO 重新评估窗口又开了一次

### 2. xAI 发布 Grok 4.3
- **来源**: [docs.x.ai/developers/models/grok-4.3](https://docs.x.ai/developers/models/grok-4.3) | HN 395 分
- **发生了什么**: xAI 官方 docs 上线 Grok 4.3 模型卡，作为 4.2 系的常规更新进入 API。
- **背景**: 上面那场编程竞赛里，Grok Expert 4.2 只拿到第六，4.3 应是回应。xAI 仍在补齐 tool use 与长上下文稳定性。
- **分析**: 节奏快但没看到突破性 benchmark 跃迁——和 GPT-5.5、Claude Opus 4.7 一样，进入"季度小步快跑"阶段，单次升级带来的相对优势越来越小。这进一步印证上一条的判断：模型层正在商品化，差异化要往 harness/agent/产品体验走。
- **影响与关注点**:
  - 短期不必为 4.3 切换主力模型，等社区做完 lmsys/coding 实测再说
  - 关注 4.3 的 tool calling 失败率是否真的下降

### 3. PyTorch Lightning 训练库被植入 Shai-Hulud 风格恶意代码
- **来源**: [Semgrep 安全公告](https://semgrep.dev/blog/2026/malicious-dependency-in-pytorch-lightning-used-for-ai-training/) | HN 462 分
- **发生了什么**: Semgrep 披露 PyTorch Lightning 上游某个被广泛用于 AI 训练的依赖被注入 Shai-Hulud 主题的恶意代码（与之前 npm 蠕虫同源），开发者 pip 安装后会被窃取 token、扫描云密钥。
- **背景**: 这是 2025 年开始的 Shai-Hulud npm 蠕虫家族向 Python AI 生态的横向扩散。AI 工作站通常持有 W&B、HF、AWS、OpenAI 等多份高权限 token，回报率极高。
- **分析**: 训练机=高价值靶子已经被攻击者 pricing in。Lightning 这种"必装"的 trainer 被污染，意味着一切以"先 pip install 再说"的 ML 工作流都需要重新审视。建议训练环境强制走 lockfile + sha256 pin，token 全部短期化、按项目隔离。
- **影响与关注点**:
  - 立即审计本机/集群的 Lightning 版本，对比官方公告的受影响 hash
  - HF / W&B / OpenAI key 全部 rotate；训练 VM 与日常开发 VM 物理隔离
  - 加一条 CI 检查：对所有 ML 依赖跑 `pip-audit` + Semgrep supply-chain 规则

### 4. IBM 开源 Granite 4.1：8B 稠密模型对标 32B MoE
- **来源**: [IBM Research Blog](https://research.ibm.com/blog/granite-4-1-ai-foundation-models) | [HN 321 分讨论](https://firethering.com/granite-4-1-ibm-open-source-model-family/)
- **发生了什么**: IBM 放出 Granite 4.1 家族，主推一个 8B 稠密模型在多项基准上追平 32B 级 MoE，全系 Apache-2.0 商用友好。
- **背景**: IBM 的策略一直是"够用 + 可控 + 企业合规"，针对的是不能用 OpenAI/Anthropic API 的金融/政府/医疗场景。
- **分析**: 8B 稠密能逼近 32B MoE，对边缘部署、私有云、单卡推理是实打实的利好。不会撼动头部，但企业合规市场会持续吃下这一类模型。和 Kimi K2.6 一起，构成"开源权重前沿全面追赶"的本周双证据。
- **影响与关注点**:
  - 内部"轻量推理 + 隐私敏感"场景把 Granite 4.1 加入候选池
  - 关注其量化版（GGUF）社区进度

### 5. Uber 4 个月烧光 2026 全年 AI 预算在 Claude Code 上
- **来源**: [briefs.co 报道](https://www.briefs.co/news/uber-torches-entire-2026-ai-budget-on-claude-code-in-four-months/) | HN 397 分
- **发生了什么**: Uber 内部全员铺开 Claude Code，4 个月把全年 AI 预算花完。
- **背景**: 这是大厂 coding agent 真实使用强度的第一手数据点之一，规模化采购侧的真实信号。
- **分析**: 一方面证明 coding agent 已经过了 PoC 阶段，进入"每个工程师每天都在烧 token"的常态消耗；另一方面是 Anthropic 在企业市场对 OpenAI 形成的实质性挤压（Codex 没拿到这种现象级单子）。也意味着 token 成本曲线压力极大，谁先把单位任务成本砍下去，谁就拿下下一波。
- **影响与关注点**:
  - 我们自己的 agent 工作流也要建立 per-task 成本仪表盘，别被复利烧穿
  - 评估 Kimi K2.6 / Granite 4.1 等开源权重做"长尾任务降级方案"
