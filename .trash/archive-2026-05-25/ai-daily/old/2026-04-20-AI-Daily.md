# AI Daily — 2026-04-20

## 重点事件

### 1. Vercel 4 月安全事件登顶 HN（717 分，今日）
- **来源**: [BleepingComputer 报道](https://www.bleepingcomputer.com/news/security/vercel-confirms-breach-as-hackers-claim-to-be-selling-stolen-data/) | [Vercel KB](https://vercel.com/kb/bulletin/vercel-april-2026-security-in)
- **发生了什么**: Vercel 确认遭入侵，攻击者声称在出售窃取的数据；事件位列 4 月最受关注的开发者工具安全事故。
- **背景**: 2025 末以来，针对开发者基础设施（PyPI、NPM、本月初的 Axios maintainer 社工）的供应链攻击持续升温；Vercel 是大量 AI 应用（含 Next.js、AI SDK 用户）的默认部署面，影响半径大。
- **分析**: 这不是孤例，而是「AI 应用栈」攻击面成熟的标志——前端托管、构建脚本、env secrets、AI 网关 token 同处一个账号体系。OpenAI 同周专门发文回应 Axios 事件并推 cyber defense 计划，说明大厂已把基础设施安全视为对抗性主战场。短期内任何把 OpenAI/Anthropic key 放进 Vercel 项目环境变量的团队都该假定密钥泄露并轮换。
- **影响与关注点**:
  1) 立即检查并轮换托管在 Vercel 的所有 LLM/数据库密钥
  2) 给生产部署强制开启短期 token + 出口 IP 白名单
  3) 把"AI 应用安全审计"列为下季度固定动作

### 2. Claude Opus 4.7 上线，系统提示泄露"agent 哲学"转向（304 分）
- **来源**: [Simon Willison 详解](https://simonwillison.net/2026/Apr/18/opus-system-prompt/) | [git diff](https://github.com/simonw/research/commit/888f21161500cd60b7c92367f9410e311ffcff09)
- **发生了什么**: Anthropic 4 月 16 日发布 Opus 4.7，并按惯例公开系统提示。Simon Willison 比对 4.6→4.7 的 diff，发现新增"少问多做（action over asking）"、`tool_search` 强制查询、对话不挽留、儿童安全严格化等系统级行为约束；并新增 Claude in PowerPoint 工具，与 Excel/Chrome 凑齐 Cowork 三件套。
- **背景**: Anthropic 是唯一长期公开 chat 系统提示的大厂；4.7 是继 2 月 4.6 之后的工程迭代版本。
- **分析**: 这次提示更新的工程含义比模型权重升级更值得读：Anthropic 在用提示工程把"过度澄清、半途停止、答非所问"这些 agent 痛点系统性压制。`tool_search` 由提示层强制使用，意味着 agent 平台正在把"工具发现"标准化成一等公民——这对我们做 MCP/Tool 集成的设计有直接借鉴：工具列表应支持懒加载与按需检索，而不是一次塞进 prompt。
- **影响与关注点**:
  1) 我们自家 agent 的 system prompt 应吸收"少问多做 + 完成到底"的措辞模板
  2) 评估给 MCP server 加 tool_search 检索能力
  3) 跑一轮 4.7 vs 4.6 的回归对比，重点看长任务成功率

### 3. OpenAI 把 Codex 推到 "(almost) everything"
- **来源**: [OpenAI Blog](https://openai.com/index/codex-for-almost-everything/)
- **发生了什么**: 4 月 16 日，OpenAI 给 Codex 加了后台计算机操作（自带光标）、应用内浏览器、图像生成（gpt-image-1.5）、记忆、定时唤醒（automations）、90+ 插件（含 JIRA、GitLab、CircleCI、Microsoft Suite 等），并支持远程 devbox SSH。覆盖 300 万周活开发者。
- **背景**: 与 Anthropic 的 Claude Code、Google 的 Gemini Code Assist 三足鼎立，竞争焦点从「写代码」转向「跨工具、跨时间的工作代理」。
- **分析**: 看点不是单功能，而是 Codex 第一次把"持续性任务（cross-day automations + memory）"做成产品默认形态——这是 agent 从"会话式"走向"驻留式"的关键拐点。对小团队来说，这意味着大量原本在 Zapier/n8n 上的轻量自动化会被 LLM agent 重写；对产品策略来说，"个人 AI 工位"会成为下一个客单形态。同时也要注意：背景 computer use 当前仅 macOS、EU/UK 推迟，企业部署要规划合规窗口。
- **影响与关注点**:
  1) 体验 Codex 的 background computer use，对比我们 Hermes agent 的 cron + skill 机制
  2) 关注 90+ 插件中与我们工作流重合的（GitLab、Notion、Render）
  3) 评估「driven-by-memory 的主动建议」对 UX 的启发

### 4. Google Gemma 4 开源：26B-MoE/31B 单 H100 跑，逼近闭源体验
- **来源**: [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/)
- **发生了什么**: 4 月 2 日发布的 Gemma 4 在本周持续发酵：四档（E2B/E4B/26B-A4B MoE/31B dense），Apache 2.0，原生多模态（文/图/视频，E 系列加音频），128K~256K 上下文，140+ 语言。31B 在 LMArena 开源榜第三、26B 第六。bfloat16 权重单卡 H100 80G 可载，量化版可下放消费级 GPU；E2B/E4B 可跑 Pixel/Jetson/树莓派。
- **背景**: 接续 4 亿次 Gemma 下载与"Gemmaverse"生态，Google 押注开源作为对 Llama 的反击和对 OpenAI 的差异化。
- **分析**: Gemma 4 把"单卡可部署的高质量推理 + agentic 工具调用"门槛拉到一个新平面，对国内自部署、私有化场景非常友好。对比 Anthropic/OpenAI 的封闭 agent 栈，Gemma + 自建 tool runtime 的组合现在足以撑起一条独立技术路线，尤其适合边缘/嵌入式 + 数据敏感场景。
- **影响与关注点**:
  1) 在我们的本地推理栈上跑 26B-A4B MoE，量一下 tok/s 与显存占用
  2) E4B 的端侧 agent 可行性（手机/边缘盒子）
  3) 评估用 Gemma 4 替代部分 GPT-4o-mini 调用以降本

### 5. RAM 短缺将持续数年，AI 硬件链条承压（276 分）
- **来源**: [The Verge](https://www.theverge.com/ai-artificial-intelligence/914672/the-ram-shortage-could-last-years) | 配套 [Bromine Chokepoint, War on the Rocks](https://warontherocks.com/cogs-of-war/the-bromine-chokepoint-how-strife-in-the-middle-east-could-halt-production-of-the-worlds-memory-chips/)
- **发生了什么**: HBM/DRAM 因 AI 数据中心吞噬产能而结构性短缺，预计延续数年；同时中东局势波及溴供应——溴是存储芯片关键原料，叠加产能风险。
- **背景**: HBM3e/HBM4 主要由 SK 海力士/三星/美光供给 NVIDIA、AMD AI 加速卡，已被预订到 2026 年底。
- **分析**: 这从供给侧给所有大模型扩张计划压一道天花板：训练侧推迟、推理侧云价格难降。中长期看，量化、MoE、稀疏激活、端侧推理（如 Gemma 4 E 系列）将不只是"性价比选项"，而是"被迫的工程默认"。
- **影响与关注点**:
  1) 锁定明年 GPU/服务器采购窗口，避免被动加价
  2) 提前做小模型/量化路线储备
  3) 关注 HBM4 量产时间点（影响 2027 年模型规模）
