# 企业级 AI 架构六层蓝图

## 总览图（文字版）

```
┌─────────────────────────────────────────────────────────────────────┐
│ L6 入口层    桌面 IM / 手机 App / Web 工作台 / CLI / 邮件 / 语音       │
├─────────────────────────────────────────────────────────────────────┤
│ L5 Agent 编排  RM 副驾驶 · 审贷助手 · 问数助手 · 合规助手 · 数字员工    │
├─────────────────────────────────────────────────────────────────────┤
│ L4 工具层     MCP/OpenAPI 网关 ← 包壳老系统：客户/授信/支付/审批/数仓   │
├─────────────────────────────────────────────────────────────────────┤
│ L3 知识层     企业知识库（制度/产品/案例）+ 行业知识 + 向量检索 + 图谱   │
├─────────────────────────────────────────────────────────────────────┤
│ L2 模型层     基础大模型（DeepSeek/Qwen/自研）+ 领域小模型 + Embedding   │
├─────────────────────────────────────────────────────────────────────┤
│ L1 基座层     国产算力（昇腾/海光/英伟达）+ K8s + 模型服务 + 训练框架     │
└─────────────────────────────────────────────────────────────────────┘
   贯穿三横：① 数据治理   ② 安全合规   ③ 可观测/审计/评估
```

## L1 基座层

- **算力**：国产化优先（昇腾 910B / 海光 / 寒武纪），英伟达留给训练；中小行起步 8-16 卡足够推理
- **调度**：K8s + KServe / vLLM / TGI；平安经验：统一算力平台后 GPU 利用率 +16pp
- **存储**：对象存储分租户、向量库（Milvus / Weaviate / 国产）、KV 缓存
- **MLOps**：训练/微调/评测一体化平台（参考浦发"四位一体"）

## L2 模型层

- **基础大模型**：DeepSeek-V3/R1 + Qwen2.5/3 主力，**中小行直接用，别自研**
- **领域小模型**：审单/票据/影像/反欺诈这类高频任务，小模型成本/精度更优
- **Embedding**：bge-large / nomic-embed-text；金融领域微调一份
- **混合使用原则**：复杂语义→大模型，规则/分类→小模型，**省钱 + 可解释**

## L3 知识层

- **企业知识库**：制度文档 / 产品说明书 / 风控案例 / 历史批复 / 同业研报
- **结构化数据**：客户主数据 / 授信批复 / 财报 / 行业图谱
- **检索**：BM25 + Dense Vector + Rerank 三段式
- **关键工程点**：
  - **租户隔离**：按机构/部门拆 collection，不能"全行一个库"
  - **更新机制**：制度发布走流程，自动入库 + 版本化
  - **可追溯**：每个答案必须能引用到原文档+段落

## L4 工具层（这一层是老系统改造的核心）

- **MCP Server / OpenAPI 网关**包壳现有系统：
  - 客户管理：`get_customer`, `search_customer`, `list_my_customers`
  - 授信：`get_credit_line`, `list_pending_approvals`
  - 支付/账户：`query_balance`, `list_transactions`
  - 数仓：`run_sql`, `query_metric`, `gen_chart`
  - 审批：`submit_approval`, `query_approval_status`, `approve`, `reject`
- **每个工具必须**：
  1. 标注**权限要求**（哪个角色能调）
  2. 标注**副作用等级**（读 / 写 / 不可逆）
  3. 透传**调用者身份**（不能 service 账号兜底）
  4. 返回**结构化结果 + 引用**

## L5 Agent 编排层

- **编排框架**：LangGraph / AutoGen / 自研都行，**关键是有 HITL（人在环上）切面**
- **典型 Agent**：
  - **RM 副驾驶**（对公）— 客户洞察 / 拜访准备 / 方案生成 / 工单提交
  - **审贷助手** — 资料解析 / 风险提示 / 意见初稿（必须人审）
  - **问数助手** — NL→SQL→图表（数仓权限严控）
  - **合规助手** — 制度查询 / 文本审查 / 风险点标注
  - **数字员工** — 后台自动化（票据、对账、报表）
- **决策树**：场景按风险等级分 3 档——只读/可改/不可逆——决定 HITL 强度

## L6 入口层

- **桌面 IM 集成**（飞书/企微/钉钉）— 最高频
- **手机银行 App**（招行已落地 14.0）
- **Web 工作台**（数字驾驶舱）
- **CLI / IDE 插件**（给 IT、研发）
- **语音/外呼**（智能客服、外呼）
- **邮件机器人**（@ Agent 触发）

## 三条横向能力

### ① 数据治理
- 数据分级（L1 公开 / L2 内部 / L3 敏感 / L4 核心）
- 训练语料**必须脱敏审核**
- 知识库分租户、向量库带 metadata 过滤

### ② 安全合规
- **五条防线**：身份透传 / 库隔离 / 语料脱敏 / Prompt 注入检测 / 结果二审
- 详见 [[03-数据授权与权限控制四维矩阵]]

### ③ 可观测 / 审计 / 评估
- 全链路 trace（用户→Agent→工具→DB）
- 每次生成留存 prompt + 检索证据 + 结果 + 调用者
- 自动化 evals（参考招行/科大讯飞金融大模型评测集）
- 关键指标看板：采纳率 / 工时节省 / 错误率 / 投诉率

## 建设次序（强建议）

1. L1 基座 + L2 选型（4-6 周）
2. L3 知识库 MVP（2-3 个高频领域）+ L4 工具网关（10-20 个工具）（6-8 周）
3. L5 1 个 POC Agent（推荐 RM 副驾驶）+ L6 IM 入口（6-8 周）
4. 三横（治理/安全/审计）**同步起步**，不能事后补
