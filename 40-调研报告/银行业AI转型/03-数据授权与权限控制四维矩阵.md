# 数据授权与权限控制四维矩阵

> 银行场景的权限远比"RBAC 角色组"复杂。**RM 只看自己客户、审查官看全行、风控按风险标签看、行领导按机构看**——单一模型扛不住。

## 四维矩阵

| 维度 | 控制内容 | 实现技术 | 例子 |
|---|---|---|---|
| **WHO** 身份 | 用户/角色/岗位 | OIDC + RBAC | 张三 / 客户经理 / 总行对公部 |
| **WHAT** 数据 | 行 / 列 / 字段 | RLS + 列级权限 + 脱敏 | 只看自己名下客户、身份证号脱敏 |
| **WHERE** 域 | 机构 / 部门 / 产品线 | ABAC 属性策略 | 北京分行 / 信贷部 / 对公业务 |
| **WHEN** 场景 | 调用上下文 / 工具 | 工具级策略 | 拜访前可看 KYC，授信审批可看财报 |

**五件套技术栈**：RBAC + ABAC + RLS（行级安全）+ 动态脱敏 + 全链路审计

## 角色矩阵示例（对公场景）

| 角色 | 客户范围 | 数据深度 | 写操作 | 典型工具集 |
|---|---|---|---|---|
| 客户经理 | 自己名下 | 标准（脱敏身份证/手机） | 可发起申请，不可批 | 客户洞察、拜访准备、申请草稿 |
| 团队长 | 团队全部 | 标准 | 可初审 | + 团队看板、业绩分析 |
| 支行长 | 支行全部 | 标准 | 可终审（限额内） | + 支行驾驶舱、合规预警 |
| 风险审查官 | 全行（按授信流转） | 完整（含财报/征信） | 不可发起，可批 | 审贷助手、历史案例库 |
| 部门总（总行对公部） | 全行对公客户 | 聚合 / 抽样 | 政策决策 | 业务驾驶舱、客群分析 |
| 分行领导 | 本分行 | 聚合 + 异常下钻 | 重大决策 | 分行驾驶舱、风险预警 |
| 行领导 | 全行 | 聚合 + 跨条线 | 战略决策 | 行长驾驶舱、行业对标 |
| 审计 | 全行 | 完整 + 不可改 | 只读 | 审计追溯、合规检查 |

## 行级安全（RLS）SQL 示例

PostgreSQL（Hive / Greenplum 同理）：

```sql
-- 1. 客户经理只能看到自己名下的对公客户
ALTER TABLE corp_customer ENABLE ROW LEVEL SECURITY;

CREATE POLICY rm_self_only ON corp_customer
  FOR SELECT TO role_rm
  USING (rm_user_id = current_setting('app.current_user_id')::int);

-- 2. 支行长看全支行
CREATE POLICY rm_branch ON corp_customer
  FOR SELECT TO role_branch_head
  USING (branch_id = current_setting('app.current_branch_id')::int);

-- 3. 风险审查官看全行（按授信状态）
CREATE POLICY risk_review_all ON corp_customer
  FOR SELECT TO role_risk_reviewer
  USING (credit_status IN ('reviewing','approved'));

-- 4. 行领导只能看聚合，不能 select *（视图层控制）
CREATE VIEW v_corp_customer_agg AS
  SELECT branch_id, industry, COUNT(*) AS n,
         SUM(credit_amount) AS total_credit
  FROM corp_customer GROUP BY branch_id, industry;
GRANT SELECT ON v_corp_customer_agg TO role_executive;
```

**关键**：`current_setting('app.current_user_id')` 由**会话级注入**，Agent 调用时透传——不是 Agent 自己声明的。

## Agent 身份透传（伪代码）

```python
# 1. 用户登录 → 拿到 OIDC token
user_token = oidc.login(username, password)

# 2. Agent 接收用户请求，token 跟着走
async def agent_handle(user_token, user_msg):
    # 3. 调工具时透传
    result = await mcp_client.call_tool(
        tool="list_my_customers",
        params={"limit": 50},
        # ⚠️ 关键:不是 service token,是用户 token
        auth_headers={"Authorization": f"Bearer {user_token}"},
    )
    return llm.chat(messages=[..., result])

# 4. MCP Server 端
async def list_my_customers(params, ctx):
    # 解析 token,拿到用户 ID
    user = oidc.verify(ctx.auth_headers["Authorization"])
    # 注入会话变量给 DB
    await db.execute(f"SET app.current_user_id = {user.id}")
    # RLS 自动生效
    return await db.query("SELECT * FROM corp_customer LIMIT %s", [params.limit])
```

## 列级权限与动态脱敏

```sql
-- 列级
REVOKE SELECT (id_card, mobile, salary) ON corp_customer FROM role_rm;
GRANT  SELECT (id_card, mobile, salary) ON corp_customer TO role_risk_reviewer;

-- 动态脱敏（PG 16+ / 商用 DB 都支持）
CREATE FUNCTION mask_id_card(s text) RETURNS text AS $$
  SELECT CASE
    WHEN current_user_has_role('role_risk_reviewer') THEN s
    ELSE substr(s,1,6) || '********' || substr(s,15,4)
  END
$$ LANGUAGE sql STABLE;
```

## 五条 Agent 安全防线

1. **身份透传** — service token 绝对禁用，全链路用用户 token
2. **库/索引隔离** — 知识库按机构/部门拆 collection，向量检索带 metadata filter
3. **训练语料脱敏** — 微调/RAG 入库前必经脱敏 + 审核流程
4. **Prompt 注入检测** — 工具返回的文本视为不可信，过 guardrail
5. **写操作二审** — Agent 提交的任何写操作（审批/转账/外发）必须人按按钮

## 审计落地清单

每次 Agent 交互留存：
- `trace_id` + 用户 ID + 时间戳
- 完整 prompt + RAG 检索的文档列表
- 所有工具调用（参数 + 返回的 hash）
- 模型输出 + 用户是否采纳
- 最终业务动作（提交/取消/修改）

**保留期**：参考业务系统，最少 5 年；信贷/反洗钱相关 10 年起。
