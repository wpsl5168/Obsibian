# 老系统改造路径 — CLI 化与 MCP 包壳

> **核心原则**：包壳 > 重写。20+ 年的对公系统、流程审批、SSIS 包，重写风险/合规成本远大于收益。让 Agent 学着用老系统，而不是把老系统拆了。

## 6 类资产的 AI 化策略

### ① 前端（旧 Web / 桌面客户端）
- **不改前端**，加一个"AI 副驾驶面板"（侧边栏 / 浮窗）
- 副驾驶通过 MCP 调后端，不走老前端的 UI 链路
- 老前端继续在，**用户既能传统点点点，也能跟 AI 说话**
- 适用：3-5 年内一定会重构的前端，先共存

### ② 网关服务
- 老网关原样保留
- **新增 AI 网关**：处理 Agent 调用、限流、审计、身份透传
- 两层网关并行，AI 网关→老网关→后端

### ③ 后端接口（SOAP / REST / 内部 RPC）
- **每个核心接口包一个 MCP Tool**：
  - 工具名 = 业务动词（`list_pending_credit_approvals`）
  - 参数 schema 严格定义
  - 权限校验前置（OIDC/JWT 透传调用者）
  - 副作用等级标注（read / write / irreversible）
- 接口太多？**先包 20-30 个最高频的**，覆盖 80% 场景

### ④ 数据库
- **绝对不允许 Agent 直连业务库写数据**
- 读：通过受控视图 + 行级安全（RLS），详见 [[03-数据授权与权限控制四维矩阵]]
- 写：必须走 API 工具层，**不能裸 SQL**
- 数仓查询：限定到只读副本 + 查询超时 + 结果行数封顶

### ⑤ BI 数仓 + SSIS
- **SSIS 包不动**——它们是数据管道，AI 不需要替代
- **AI 在 BI 层加值**：
  - "问数 Agent"：自然语言 → SQL → 图表（参考招行管理驾驶舱数据 Agent）
  - 自动报表叙述（数据 + 解读，不只是数字）
  - 异常预警自动归因
- **关键**：数仓的元数据（表 / 字段 / 指标 / 业务含义）必须先治理好，否则 NL→SQL 全是幻觉

### ⑥ 流程审批
- **审批引擎不动**（不是核心 AI 化对象）
- AI 在 3 个位置切入：
  1. **发起前**：草拟申请材料（如客户经理发起授信申请，AI 帮写理由）
  2. **审批中**：辅助审批人——风险点提示、历史相似案例、合规检查（招行/建行已落地）
  3. **审批后**：自动生成意见单、归档、同步下游
- **HITL 红线**：审批结论**必须人按按钮**，AI 只出初稿/建议

## CLI 化的真实含义

老王问"如何 CLI 化"——这里要厘清两层意思：

### 第一层：让人/Agent 都能用 CLI
- 给业务系统建一套 `bank-cli`（或 `corp-rm`）命令
  - `bank-cli customer list --my`
  - `bank-cli credit pending --branch=X`
  - `bank-cli approval submit --type=授信 --customer=X --file=...`
- 受益对象：IT 运维 / 高级 RM / Agent
- **真正的价值**：Agent 现在可以"shell 进系统"，而不只是调单个 API

### 第二层：MCP 化（AI 友好的"CLI"）
- CLI 给人用，MCP 给 Agent 用
- **两者底层共享同一套工具实现**——双通道复用
- 工具描述（description / examples）面向 LLM 写清楚

## 包壳的工程顺序

```
Week 1-2  盘点：列出 100+ 现有接口，按频次/价值排序
Week 3-4  治理：定义 20-30 个核心工具的 schema + 权限矩阵
Week 5-8  实现：MCP Server + 身份透传 + 审计日志
Week 9-10 联调：接 1 个 Agent（RM 副驾驶）做端到端
Week 11-12 灰度：选 1-2 个支行试点
```

## 常见反模式（避坑）

1. ❌ **service 账号兜底**——Agent 用一个超管账号查所有数据，等于权限失控
2. ❌ **裸 SQL 工具**——给 Agent 一个 `run_sql`，立刻数据全裸
3. ❌ **写操作不审核**——AI 直接提交审批/发起转账
4. ❌ **一次性把所有接口都 MCP 化**——做不完且没必要，20% 接口承担 80% 场景
5. ❌ **重写老系统配合 AI**——上线日期会被无限推
6. ❌ **元数据/字段含义不治理就上问数**——SQL 全错，业务侧立刻不信任 AI
