# 银行业 AI 转型调研 · 对公客户管理系统视角

> 客户场景：传统银行对公客户管理系统（前端 + 网关 + 后端接口 + 数据库 + BI 数仓 + SSIS + 流程审批），如何在**不重写**的前提下，CLI 化 + Agent 化，赋能客户经理 / 各级管理者 / 行领导。

---

## 📌 核心结论速查

1. **不要重写，要"包壳"** — 老系统暴露 MCP/OpenAPI 工具层，AI 在上层调用；20+ 年历史数据迁移风险 > 收益
2. **POC 首选 RM 副驾驶** — 高频日活、易量化（工时/出单率）、不碰审批红线、3 个月见效（民生 RM 助手覆盖 2 万人参考）
3. **模型策略：国产开源为主** — DeepSeek/Qwen 本地部署，中小行 500-800w 起步；自建大模型留给头部行（工建农中年投 250+ 亿）
4. **数据授权必须五件套** — RBAC + ABAC + RLS + 动态脱敏 + 全链路审计；service 账号兜底是高危反模式
5. **人在环上是合规红线** — 央行 2026"积极稳妥、安全有序"+ 招行已落实"审贷人员对 AI 方案复核责任制"
6. **量化效果对标**（行业头部 2025）：审贷意见生成 90%、单份耗时 5 分钟、RM 触客 +14%、token 日均 260 亿、数字员工 = 5.5 万人年
7. **架构六层**：算力基座 → 模型层 → 知识库 → 工具层（MCP）→ Agent 编排 → 入口（IM/App/CLI），数据治理/安全/可观测**贯穿**
