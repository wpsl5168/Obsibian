项目开发过程

从写代码，转向运营一条交付闭环

每个阶段产出下一阶段可直接读取的 Artifact。AI 负责生成、转换和验证，人守住意图、风险与生产权限。

核心：它不是让一个 Agent 从需求一路跑到上线，而是把 SDLC 变成有证据、有边界、有人工 Gate 的事件驱动系统。

Plan：先固定问题，不急着谈实现

想法、Ticket、反馈或事故都进入同一个入口。

intent.md

AI 做什么

  • 追问用户、范围、约束、期望结果和开放问题
  • 把发起人的自然语言整理成统一模板
  • 保留原始意图，不经多轮角色转述

怎样触发下一阶段

Product Owner 接受并提交 intent.md，触发 Design。

人工 Gate：这个问题是否真实、值得做、边界是否正确。

Design：需求与设计在同一上下文完成

AI 将意图与组织规范一起读入，形成工程可执行规格。

spec.md

AI 做什么

  • 应用 Security、Compliance、Brand、UX Skills
  • 生成需求、接口、数据、用户流程和验收标准
  • 明确标出冲突规则、风险与未决问题

怎样触发下一阶段

Product Owner 审核规格；高风险项交给 Architect 或 Policy Owner。批准后触发 Plan Mode。

人工 Gate：方案是否忠于意图，约束是否完整，风险由谁承担。

Build：任何代码之前，先批准实施计划

Agent 在只读模式理解代码库，工程师先改计划，再让它改代码。

plan.md + diff

计划必须回答

  • 改哪些文件、按什么顺序
  • 最可能破坏什么、最大风险在哪里
  • 选择了什么方案、放弃了哪些替代方案
  • 用哪些测试证明完成

执行方式

计划获批后进入 Auto Mode。独立任务放入不同 Git Worktree，多个 Session 并行。偏离计划时，必须同步更新 plan.md。

人工 Gate：实现路径和 Blast Radius 是否可接受。

Test：Agent 交付的是证据，不是“我写完了”

验证发生在整个执行过程中，不等到最后才交给 QA。

tests + logs + screenshots

反馈回路

  • 运行 Build、Unit Test、Integration Test 和 Lint
  • UI 任务启动浏览器，截图并与批准稿比较
  • Bug Fix 先提交失败测试，再禁止 Agent 修改测试
  • 由独立 Verifier 使用新上下文做最终检查

Agent 也要被测试

历史真实任务组成 Eval Suite。Model、Prompt、Skill、Hook 或 CLAUDE.md 变化时，CI 重跑 Evals。

通过条件：工具输出证明行为正确，失败就修代码而不是弱化检查。

Deploy：AI 全面初审，人判断意图与风险

Agent 可以把发布准备做到最后一步，但不能自行跨过生产 Gate。

PR + review findings

Review Loop

  • 按 REVIEW.md 固定检查 Bug、Security、Compliance
  • 对照 spec.md 与 plan.md 检查实现偏差
  • Agent 自动处理评论、修复、重跑验证
  • Branch Protection 保证写代码的 Agent 不能批准自己

发布边界

Development 可自动部署；Staging 增加强制检查；Production 需要 Release Manager 授权和 Hook 放行。

人工 Gate：变更是否符合原始意图，剩余风险是否可以接受。

Maintain：生产系统自动生成下一轮工作

确定性监控负责发现异常，AI 只在越界后介入诊断。

incident record → intent.md

分级响应

  • 轻微异常只记录
  • 中度异常允许 AI 只读诊断
  • 严重异常允许提 PR 或调用预批准 Rollback Runbook
  • 诊断结果写成新 intent.md，重新进入 Plan

为什么不用 AI 判断告警

Control Band、阈值和权限等级必须由版本化的确定性配置决定，避免模型临场扩大权限。

人工 Gate：Service Owner 决定立即修复、排期或驳回，并调优监控阈值。

控制不是一层 Prompt

越接近生产，控制越确定。软规则负责提高正确概率，硬边界负责阻止不可接受动作。

CLAUDE.md：Repo 工作手册

命令、架构、约定和高频错误。Agent 同一个错误犯两次，就把纠正规则写回文件。

Skills：组织知识

安全、API、品牌和合规政策。它们是可版本化的建议性控制。

Hooks + Sandbox：硬边界

阻止访问秘密、修改受保护路径或绕过生产审批。关键规则不能只靠模型自觉。

Tests + Evals：回归证据

既测试产品，也测试驱动 Agent 的配置是否退化。

人的注意力上移

发起人表达真实问题
Product批准 Intent 与 Spec
Engineer审查计划、风险和证据
Architect处理高风险决策
Code Owner批准 PR
Release授权生产发布
Service Owner裁决异常回流

自治程度按环境分级

安全不是“自动或不自动”二选一，而是让权限随环境、风险和证据变化。

Development

Agent 可自主修改、测试和部署，快速闭环。

Staging

自动部署，但必须通过集成测试、安全检查与回滚演练。

Production

Agent 完成准备，人类授权；仅可执行预批准操作。

闭环终点也是起点

生产异常 → 确定性检测 → AI 诊断 → PR、Runbook 或新 intent.md → 再次进入完整交付链。

真正的新角色

工程师不再主要等待 Build、Test 和 Review，而是同时驾驶多个隔离 Session，维护控制系统并审查关键 Artifact。

AI 承担生成、转换、检查和跟进；人负责价值判断、风险承担与最终授权。
