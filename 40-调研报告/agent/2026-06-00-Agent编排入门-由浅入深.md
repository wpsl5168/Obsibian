# Agent 编排入门 — 由浅入深

> 给初学者的概念地图。不堆术语，每一步都回答"为什么需要下一个东西"。读完这页再去看 [[40-调研报告/agent/2026-06-Agent编排框架横评-SK-MAF-LangChain|框架横评]] 和 [[40-调研报告/agent/2026-06-01-LangGraph实操入门|LangGraph 实操]]。

## 第 0 层：为什么需要"编排框架"

最原始的用法：你给大模型发一句话，它回一句话——**一次 LLM 调用**，直接调 API 就行，不需要任何框架。

但很快不够用：
- 模型不知道今天天气 → 得让它**调工具**（查天气 API）
- 一个问题要分几步 → 先查资料、再总结、再翻译
- 一步错了要重试、要分支判断、中途要人确认

这时你在写一堆"什么时候调哪个、结果怎么传下去、出错怎么办"的胶水代码。**编排框架就是来管这摊事的**——管理 agent 之间、步骤之间的控制流和数据流。

> **核心定义**
> - **Agent** = LLM + 工具 + 记忆 + 能自己决定下一步做什么
> - **编排（Orchestration）** = 管多个 agent / 多个步骤怎么协作

---

## 第 1 层：从"一个 agent"到"多个 agent"

单个 agent 能力有限。复杂任务要拆给多个专职 agent，像组团队：一个搜资料、一个写代码、一个审查。

**问题来了：这个团队怎么协作？** 谁先干、谁后干、谁说了算、信息怎么传——这就是编排的核心。历史上出现了**四种协作思路（范式）**，这是理解整个赛道的总钥匙。

---

## 第 2 层：四种编排范式（用团队比喻记）

**① 对话式（Conversation）— 像开会**
几个 agent 围一桌用"说话"协商，A 说完 B 接话，一个主持人决定谁发言。灵活，但像真实会议——可能跑偏，不太可控。
→ 代表：**AutoGen、OpenAI Agents SDK**

**② 图 / 状态机（Graph）— 像流程图**
画一张明确的流程图：这个框做完→根据结果走左还是走右→可以绕回去重做。每一步、每个分支都你定死，**可控、可复现、能断点续跑**。
→ 代表：**LangGraph、微软 MAF Workflows**

**③ 角色扮演（Role）— 像公司分工**
给每个 agent 发"工牌"：你是研究员、你是文案、你是审核。按角色自然分工，上手最直观。
→ 代表：**CrewAI**

**④ 事件驱动（Event）— 像流水线传送带**
每步处理完"扔出"一个事件，下一步"接住"继续干。天然适合数据加工流水线（尤其 RAG）。
→ 代表：**LlamaIndex Workflows**

> 记住这四个范式，后面所有框架都能往里对号入座。

## 第 3 层：主流框架认识（先知道各自解决什么）

### 微软系（三代演进，有历史包袱）
- **Semantic Kernel (SK)** — 微软最早的企业级框架（2023），适合 .NET/Java 老系统集成。现转**维护模式**（不主推）。唯一支持 Java。
- **AutoGen** — 微软研究院的多 agent 框架，对话式，学术圈火。也转维护模式。
- **Microsoft Agent Framework (MAF)** — 2025 新发，**把 SK + AutoGen 合并**，是微软未来方向。但还在 Preview（未 GA），压生产要谨慎。

### LangChain 系（生态最完整，新手最常遇到）
- **LangChain** — 做"积木"：把模型、工具、检索打包成标准组件。入门最常见。
- **LangGraph** — 做"流程图"：用图编排 agent，复杂任务的事实标准。
- **LangSmith** — 做"运维"：看 agent 怎么思考、调试、监控。
- 三者配合：**组件（LangChain）+ 编排（LangGraph）+ 运维（LangSmith）**，原型到上线一条龙。

### 其他主流
- **CrewAI** — 角色扮演范式，**上手最快**，适合多角色业务流程。不依赖 LangChain。
- **OpenAI Agents SDK** — OpenAI 官方，**最轻量、学习曲线最低**，但绑 OpenAI 生态。
- **LlamaIndex Workflows** — 事件驱动，**RAG / 文档密集型**首选。

## 第 4 层：初学者怎么动手

### 学习路径（由浅入深）
1. **先理解概念**，别急着上框架。搞懂三个词：
   - **tool calling**（模型调工具）
   - **agent loop**（think→act→observe 循环）
   - **state**（贯穿全流程的共享状态）
2. **第一个框架二选一**：
   - 想要生态全、资料多、长期主力 → **LangGraph**（图心智模型稍难，但受益最大）
   - 想最快跑通 demo、用 OpenAI → **OpenAI Agents SDK**（最简单）
3. **从单 agent 做起**：先让一个 agent 会调一个工具（如查天气），跑通。
4. **再加第二个 agent**：体会"协作"和"信息传递"。
5. **再学持久化 + 人工介入（HITL）**：让流程能暂停、等确认、再继续——这是生产级 agent 的门槛。

### 避坑提醒
- 别一上来学 LangChain 一堆 Chain 抽象，容易被"过度封装"绕晕。直接从 LangGraph 的 node/edge 入手更清晰。
- 框架会变（微软还在合并、LangChain 刚出 1.x），但**四范式 + agent loop 的底层逻辑不变**，先吃透概念。
- **MCP**（Model Context Protocol）这个词会反复遇到——它是给 agent 统一"接工具"的标准协议，值得早点了解。

---

## 关键概念速查

- **Agent**：能自主决定下一步的 LLM + 工具 + 记忆
- **Tool / Tool calling**：模型调用外部能力（API、检索、计算）
- **Agent loop**：think（想）→ act（调工具）→ observe（看结果）→ 循环
- **State（状态）**：贯穿整个流程、各步骤共享读写的数据
- **Orchestration（编排）**：管多 agent / 多步骤的协作顺序与数据流
- **Supervisor / Handoff / Swarm**：多 agent 的三种组织方式（中心调度 / 互相转交 / 无中心蜂群）
- **HITL（Human-in-the-loop）**：流程中途暂停等人工确认再继续
- **Checkpointing**：把每步状态存下来，支持暂停-恢复、故障重跑
- **MCP**：给 agent 统一接工具/上下文的标准协议
