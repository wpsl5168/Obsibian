# 盈利线索 · 可验证 RL 环境 wedge

> 来源：[[2026-04-Karpathy-Sequoia-Ascent-Software3.0]] 第 ⑥ 节
> 性质：盈利探索线索（draft），待老王决策是否深挖

## 核心命题

Karpathy 给创业者的最聚焦建议：找一个 **高价值 + 可验证 + 前沿 labs 还没重点训练** 的领域，自建领域专属 RL 环境 / eval / 数据集，用 fine-tune 把模型在这块拉到 SOTA 之上。

**为什么成立**：
- 可验证 = 有自动 reward 信号 → fine-tune / RL "技术上确定能 work"（Karpathy 原话：拉杆就有效）。
- labs 未覆盖 = 不被巨头碾压。数学/代码已是红海（labs escape velocity），但很多经济重要领域有"潜在可验证结构"未被开发。
- 护城河 = 领域专属的 RL 环境 + eval 数据本身就是壁垒，不是靠基座模型领先。

## 三条筛选标准（wedge 判据）

| 维度 | 问题 | 淘汰信号 |
|---|---|---|
| 高价值 | 这领域有人愿意为"对一次"付钱吗？ | 单次价值低、量小 |
| 可验证 | 输出能被自动判对错/打分吗？ | 只能靠人主观评、无 ground truth |
| labs 未训 | 巨头基座开箱就强吗？ | GPT/Claude 开箱即 SOTA → 没你的位置 |

> 注：Karpathy 说"几乎一切最终都能某种程度上变可验证"（连写作都能用 LLM 评审团打分），所以真正的门槛是**容易 vs 难**，不是能否。越是"需要领域知识才能构造验证器"的，护城河越深。

## 候选领域脑暴（待验证，非结论）

- 结合老王已有资产，优先扫这几类"有验证闭环但 labs 没重训"的方向：
  - **企业 IT 迁移校验**（老王主业）：M365/SharePoint/Azure 迁移后的配置正确性、权限合规、数据完整性——天然有"迁移前后 diff 可验证"的结构，且高价值、labs 绝不会专训这种企业私域任务。
  - **工程安全检查**（对接 safety-demo 项目）：合规项是否齐全 = 可枚举可验证。
  - **国内政策/资格类**（学区/车牌/幼升小，已有 skill）：规则明确→答案可验证，但单次价值偏低，更适合做 to-C 工具不是 RL wedge。
- 反例（不要碰）：纯 to-C 信任型（法律/财税助手躺赚）——零可验证闭环，已被张雪峰视角调研否掉（见 [[../../20-项目/AI风口调研/2026-AI风口-张雪峰视角]]）。
