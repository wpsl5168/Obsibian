## 4. 待老王拍板（P0/P1）

### 🔴 LLM-P1-1 · 四 provider 全无 HTTP timeout / 无 AbortController

**位置**：`lib/pipeline/llm.js:3-19` `httpsPost` + `callGitHubModels/callOpenAI/callZhipu/callAnthropic` (21-97)
**现象**：`https.request` 未传 `timeout`；`upstream` 无 AbortSignal。若上游 TCP 不 RST 只 hang（GitHub Models 高峰 / Anthropic overload / 智谱高延迟），API route 会挂到 Vercel/serverless 平台 timeout（Vercel Hobby 10s / Pro 60s）才被强杀 → **用户 60s 无反馈无法主动取消**。fallback 链更糟：第 1 家 hang 60s → 第 2 家再 60s → 前端 90s+ 无任何 SSE 事件。
**AI 生成场景高概率触发**——大模型上游偶发慢，正是这个 pipeline 的 hot path。
**修法**（需老王拍策略）：
- (a) `httpsPost` 加 `req.setTimeout(20000, () => req.destroy(new Error('upstream timeout')))` + 每 provider 独立超时 20~30s
- (b) `httpsPost` 接受可选 `signal: AbortSignal`，`callProviderWithFallback` 起 `AbortController`，每家超时或整链超时 `.abort()`；`pages/api/generate.js` 传 `req.signal` 关联客户端断连
- (c) 二选一或叠加；(b) 更彻底

### 🔴 LLM-P1-2 · streamToText 无中断信号

**位置**：`lib/pipeline/llm.js:124-182`
**现象**：Node `on('data')` 路径 + WebStream `reader.read()` 路径均无 AbortSignal 检查。客户端关闭 SSE 后，服务端继续读上游到 END → **浪费 provider quota + 拖长下一次 fallback 排队时间**。
**修法**：同上 (b)，`streamToText` 增加 `signal` 参数，在两条 read 循环里 `if (signal?.aborted) throw new AbortError`；同时 `upstreamRes.destroy()` 主动关闭上游 socket。

### 🟡 LLM-P1-3 · Model 硬编码，无 env 覆盖

**位置**：`lib/pipeline/llm.js:27/46/65/86`
**现象**：`gpt-4o` × 3、`glm-4-plus`、`claude-3-5-sonnet-20241022` 全部字面量。切模型（如把 GitHub Models 换 `gpt-4o-mini` 省 token，或 Anthropic 升 `claude-3-5-sonnet-20250514`）要动代码 → 与 Phase 3+ "AI 生成质量迭代" 严重耦合。
**修法**：抽 `MODEL_MAP = { github: process.env.LLM_MODEL_GITHUB || 'gpt-4o', ... }`；`callXxx` 从 `MODEL_MAP` 取。**改动小但需老王决定是否引入 env**（brickhub 目前没有明显的 env 依赖，加 env 是新维度）。

### 🟡 LLM-P1-4 · 5 export 对外零使用，API 面收敛决策

**位置**：`lib/pipeline/llm.js` 全部 7 export
**事实**：跨文件被真实用的只有 `callProviderWithFallback` + `streamToText`（`index.js:4`）。另外 5 个 (`httpsPost` + 4 个 `callXxx`) 对外零 grep 命中。
**为何是 P1 不是 P2 死代码**：这 5 个 export 在 llm.js 内部**互相调用**（`callProviderWithFallback` dispatch 4 provider，4 provider 用 `httpsPost`），非死代码；只是 API 面**过宽**。降级 `export` 为模块内私有能收敛入口但**可能挡住未来某个 API route 直调某一家 provider 的扩展点**。
**修法**（老王拍）：
- (a) 收敛：删掉 5 处 `export`，只留 2 个真外部 API
- (b) 保持现状（若 Phase 4 有 provider-specific route 计划）
- **推荐 (a)**：Phase 3 目标是"AI 创意工坊"，provider 抽象应该只对 pipeline 暴露；将来要 provider-specific 再解除

### 🟡 TEST-P1 · llm.js 零真实测试覆盖

**位置**：无对应测试文件；`__tests__/generateIntegration.test.js:14`
**现象**：唯一间接可达的集成测试用 `jest.mock('../lib/pipeline/index.js', () => ({ ... }))` 把整个 pipeline stub 成假函数 → llm.js 里 SSE 解析（`streamToText` 里 `provider === 'github'|'openai'|'zhipu'` vs Anthropic `content_block_delta` 分支）、fallback 链错误累积（`failures.push(...).join(' | ')` 顺序、错误信息截断 `.slice(0, 200)`）**全部零跑过**。
