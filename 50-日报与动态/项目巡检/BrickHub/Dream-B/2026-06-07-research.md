## 待老王确认 (P1 / P0) — 仅报告, 不动手

### P0 — 数据丢失风险

**P0-1. L364 清空按钮无确认弹窗** — 一键 50 块积木全没且**不可逆**(虽然 Undo 能恢复, 但页面刷新或 useReducer 重置后丢失)。儿童误触是必然事件, 应至少弹一次确认。修法: `window.confirm` 或自绘 Dialog。**红线: 数据丢失 + 儿童产品 = P0**。

### P1 — 功能缺陷 / 体验严重受损

**P1-1. L394 OrbitControls touches.ONE = THREE.TOUCH.NONE — 单指触屏完全无法旋转视角** (Pitfall #39):
```js
touches={{ ONE: THREE.TOUCH.NONE, TWO: THREE.TOUCH.DOLLY_ROTATE }}
```
设计意图大概是"单指留给点击放置积木", 但**结果是 iPad 用户只能两指缩放, 无法单指轻量调整视角**。儿童 iPad 用户基本一只手玩, 双指操作门槛高。建议:
- 方案 A: 长按 (long-press) 单指切换到 PAN/ROTATE 模式
- 方案 B: 加一个浮动按钮"视角模式 / 放置模式"显式切换
- 方案 C: 单指 PAN, 双指 DOLLY+ROTATE (但会和 onPointerDown 放置积木冲突)
涉及交互范式选择, **绝不自动改**。

**P1-2. L246 HTML5 drag/drop API 触屏完全不可用** (Pitfall #39):
```js
onDragOver={handleDragOver}
onDrop={handleDrop}
```
+ FreeBuildTray 里的 `draggable` button 同样问题。**iOS/Android 长按 button 触发系统选择菜单, 不发 dragstart 事件**。沙盒页"从托盘拖零件到画布"这条主路径在移动端完全失效。修法选项:
- (a) react-dnd + react-dnd-touch-backend
- (b) @use-gesture/react / @dnd-kit (kid-friendly)
- (c) 改"点选托盘 → 点画布定位"无拖拽流(最简单, 推荐 BrickHub 儿童场景)
涉及交互范式重构, **绝不自动改**。

**P1-3. L342 视角重置按钮完全无 handler** (Pitfall #31):
```jsx
<button title="重置视角" className="...">  {/* 无 onClick */}
```
图标是 home 屋顶, 视觉上是核心入口("玩崩了重置"), 但**点击零反应**。修法需产品确认: 重置到 `position=[12,10,12], fov=48` 初始值? 还是重置 `OrbitControls.reset()`? 涉及目标决策, **绝不自动改**。

**P1-4. L119-135 BrickContextMenu 缺 a11y 三件套** (Pitfall #28):
- ❌ Escape 键关闭(右键菜单已选中, 但只能再次点击零件外关闭, 键盘用户被困)
- ❌ Backdrop 点击关闭(目前是 `onClick={() => setSelectedId(null)}` 在 L376 的 Canvas div 上, 算半实现, 但 stopPropagation 在菜单上, 点菜单外 + 点积木内 时机不一致)
- ❌ 焦点管理(打开时焦点未迁入旋转按钮, 关闭后未复位到积木)
修法建议: 加 `useEffect` 监听 `keydown` Escape + ref 管焦点。

**P1-5. L19-21 loadFromLS 无 schema 校验**:
```js
function loadFromLS() {
  try { const raw = localStorage.getItem(LS_KEY); return raw ? JSON.parse(raw) : []; } catch { return []; }
}
```
返回的数组没校验 part shape (defKey/color/gridX/gridY/gridZ), 任何外部脚本或上一版本 schema 不兼容的内容会让 `buildOccupancy` (L66 `PART_DEFS[p.defKey]` 找不到) 或 `Brick` 渲染崩。修法:
- Zod / runtime schema 校验
- 或至少 `Array.isArray(parsed) && parsed.every(p => p?.defKey && typeof p.gridX === 'number')`
不通过则 `localStorage.removeItem` + return []。涉及 schema 设计, **绝不自动改**。

**P1-6. L77 HISTORY_LIMIT=50 + 大模型场景内存放大**:
50 步 × 假设单步 100 块积木 × 每块 7 字段 = 35000 个 part 对象常驻内存。在 Free Build 模式下儿童容易快速堆出几百块, undo 栈会膨胀到 100+ MB JSON。建议:
- 改为差量 diff 记录(每步只存"+/-"变化)
- 或保留 50 但每 10 步合并(snapshot+diff 链)
低概率撞顶, 但移动端 iOS Safari 内存上限低易 OOM 杀页面。

## 依赖动态 — 🔥 紧急: Next.js 安全升级

### 🔥 Next.js May 2026 security release (优先级最高)

本地: `^14.2.0` → **5 个 advisory 影响 14.x, 无补丁路径**:
- **High**: DoS via connection exhaustion (Cache Components) — GHSA-mg66-mrh9-m8jx
- **High**: SSRF via WebSocket upgrades — GHSA-c4j6-fc7j-m34r
- **Moderate**: Cache poisoning in RSC responses — GHSA-wfc6-r584-vfw7
- **Moderate**: XSS in App Router w/ CSP nonces — GHSA-ffhc-5mcf-pf4q
- **Low**: Middleware redirects can be cache-poisoned — GHSA-3g8h-86w9-wvmq

**官方说**: "Patches are not planned for [14.x]. Consider upgrading to Next.js 15.x or 16.x"
+ CVE-2026-23864 DoS (CVSS 7.5) 也明确 13.x/14.x 不补

**保守升级路径 A**: 14.2 → 15.5.x LTS
- App Router 已经在用, 升级表面接近无破坏
- React 18 仍支持 (但 15.5 起官方推荐 React 19)
- 评估: 1-2 天工作量, 跑一遍全部 jest + 手动 sandbox/model 页验证

**激进升级路径 B**: 14.2 → 16.2.x
- 同时拉起 React 19 + R3F v9
- @react-three/fiber: v8.18 → v9.x (重写 ThreeElements types, peer 升 R3F v9 配 three r170+)
- @react-three/drei: v9.122 → v10.x (peer 锁定 R3F v9)
- 工作量 5-8 天, 但一次性把 three.js 从 r158 升到 r180 拿到 WebGPU 能力
- 风险: 整套全栈升, breaking changes 累加, 需要 visual check 全部 BrickRenderer 输出

**强烈建议**: 这周内先走路径 A 把安全 advisory 关掉, 路径 B 排到 BrickHub v2 节奏。
