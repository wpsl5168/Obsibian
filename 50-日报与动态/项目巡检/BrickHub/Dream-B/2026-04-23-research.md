# BrickHub 每日报告 — 2026-04-23

## 今日质检（审查文件：components/BrickRenderer.js, 981 LOC + npm test 全量）

### Bug隐患
| # | 问题 | 位置 | 根因 | 建议方案 | 优先级 |
|---|------|------|------|---------|--------|
| 1 | LDrawLoader 缓存模型(`loaderGroup`)被淘汰时未 dispose() 几何体/材质/纹理 | `BrickRenderer.js:138-143` `writeCachedModel`+`MODEL_CACHE_LIMIT=24` | Map.delete 只解引用 JS 对象，但 Three.js 的 GPU 资源(BufferGeometry/Material/Texture)需要显式 `.dispose()` 才会释放 VRAM | 在 `writeCachedModel` 淘汰旧 group 时，对 oldest 执行 `oldest.traverse(c=>{ c.geometry?.dispose(); ...})`，注意只在缓存中、非当前 setLoaderGroup 引用的对象上做 | **P1** |
| 2 | `window._brickhubDebugGroup = groupResult.result` 调试全局泄露到生产 | `BrickRenderer.js:733` | 全局变量永久持有最近一次模型的全部 mesh 引用，浏览数十个模型后累计 VRAM 增长，且生产环境暴露内部对象 | 用 `if (process.env.NODE_ENV !== 'production')` 包裹；或彻底删除 | **P1** |
| 3 | 全局 monkey-patch `THREE.FileLoader.prototype.load` 影响所有 loader | `BrickRenderer.js:213-282` | 目前所有 .dat/.ldr/.mpd/.png 全部走自定义路径，但任何其他 Three.js 加载（GLTF/纹理/HDR）也会进入这条路径，未来引入新 loader 会被 cache-bust + missingPartUrlCache 误伤 | 改为只 patch `sharedLoader.fileLoader`（LDrawLoader 内部 FileLoader 实例），不要 patch 原型 | **P1** |
| 4 | 每次 fetch 强制 cache-bust `?cb=${Date.now()}` | `BrickRenderer.js:238` | 完全绕过浏览器 HTTP 缓存与 CDN 边缘缓存，单次首屏可触发数百次 .dat 拉取，IDB 缓存命中前每个都重新走网络 | 移除 cache-buster；如果是为了规避 401/HTML 错误页，应在响应层面处理（404→记录 missing），而不是禁用缓存 | **P0**（流量/性能） |
| 5 | `partsIndexDict` 拉取无 race 防护 | `BrickRenderer.js:164-175` | 多个并发的 `getSharedLDrawLoader()` 调用都会重复 fetch `parts-index.json`，竞争写入同一全局变量 | 用 `partsIndexPromise` 缓存 in-flight Promise，所有调用 `await` 同一 Promise | **P2** |
| 6 | `useEffect([step, loaderGroup, sandboxMode, placedIds, hintId])` 中 placedIds 是父组件每次 render 新建的数组 | `BrickRenderer.js:845` | 每次父级 setState（即便 placedIds 内容相同）都会触发整棵场景图 traverse + 包围盒重算 | 父组件用 `useMemo`/稳定引用 placedIds，或在本 effect 用 `useRef` 比较内容 | **P2** |
| 7 | 沙盒可见性 effect 内 `placedIds.includes(c.uuid)` 在 traverse 内对每个节点 O(n*m) | `BrickRenderer.js:766-779` | 大模型(>500 mesh) × 许多已放置零件 → 卡顿 | effect 内将 placedIds 转 `Set` 一次，然后 `.has()` O(1) 查询 | **P2** |
| 8 | `applyMaterialsToMesh(group, '16', ...)` 硬编码颜色码 16 | `BrickRenderer.js:643` | 16 = LDraw "current color" 标记，作为顶层默认色对部分模型可能产生灰色兜底；若模型期望特定主色会丢失 | 文档化为何选 16；或从模型首条 `1 <color> ...` 指令推断主色 | **P3** |
| 9 | `DEFAULT_LDRAW` 测试常量混用 `3001.dat`(loader识别) 与 `p2x2`/`r2x2`(procedural专属命名) | `BrickRenderer.js:474-480` | `canUseLDrawLoader` 因开头是 `0` 返回 true，但 `p2x2`/`r2x2` 在 LDraw 库中不存在 → 触发 missingPartUrlCache 报错路径，UI 出现"缺失零件"提示 | 默认模型应纯标准 LDraw，或纯 procedural 形式，不要混用 | **P3** |

### 测试覆盖检查（npm test 结果）
- **总计**：13 suites / 118 tests → **2 suites failed / 12 tests failed**，其余通过
- **失败 1：`__tests__/freeBuildTray.test.js`（10 tests fail）** — 测试用 `getByText('🧱 砖块')` 等带 emoji 的纯文本匹配，但 `FreeBuildTray.js` 的 CATEGORIES 实际渲染结构是 `<svg/> + <span>{label}</span>`，label 仅为 `'砖块'`（无 emoji 前缀），导致全部 text query 失败。**Root cause**：组件实现与测试期望不一致（疑似最近移除 emoji 前缀但忘改测试），需对齐二者。**建议**：保留 SVG 图标 + 纯文本 label（更易于可达性 + 国际化），改测试用 `getByText('砖块')`；或在 label 后追加 emoji 装饰。**优先级 P1**（CI 红，阻塞回归门禁）
- **失败 2：`__tests__/officialLdrawRender.test.js`（2 tests fail）** — `manifest.json` 中 `localPath` 使用 Windows 反斜杠 `__tests__\fixtures\official-ldraw\ldraw\parts\xxx.dat`，在 Linux 上 `fs.existsSync` 解析失败（实际文件存在）。**建议**：`scripts/validate-official-ldraw.ps1` 生成 manifest 时统一用正斜杠 `/`；或测试用 `samplePath.replace(/\\/g, path.sep)` 兼容。**优先级 P1**
- **缺测试关键路径**：BrickRenderer 的双路径切换、materialPatched、IDB cache 命中/失效逻辑、cache 淘汰时的资源释放，目前没有单元覆盖
