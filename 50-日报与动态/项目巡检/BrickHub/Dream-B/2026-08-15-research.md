## 结论

今日审查 `lib/knowledgeBase.js`。发现 2 个新增功能缺陷，均涉及检索语义/API 契约，按 P1 仅报告、不自动修改；无 P2/P3，不创建分支或 PR。

- **BUG-P1**：英文查询分类器会把单字母 token 当成关键词子串。`design a race car`、`build a carpet store` 均被实测误判为 `ship`，直接污染检索类别与生成上下文。
- **API-P1**：`topK=abc` 经 `Number()` 变为 `NaN`，随后 `slice(0, NaN)` 静默返回 0 个示例；API 仍返回 200。需拍板非法值采用 400，还是回退默认 4。
- 既有 **TEST-P1** 延续：唯一测试通过 `jest.mock('../lib/knowledgeBase')` 整体替身，7 个 export 与内部排序/缓存/文本归一化逻辑零真实覆盖。

## Bug 复现链路

```text
输入: "design a race car"
tokenize → [design, a, race, car]
CATEGORY_KEYWORDS 遍历时 keyword.includes("a") 大量命中
最终 detectQueryCategory → ship(score=3)
预期 → f1 或 vehicle
```

```text
输入: topK="abc"
Number("abc") → NaN
Math.min(NaN, 8) → NaN
Array.slice(0, NaN) → []
HTTP 层仍 200
```

实际验证命令：

```bash
node -r @babel/register - <<'NODE'
const kb = require('./lib/knowledgeBase.js')
console.log(kb.detectQueryCategory('design a race car'))
console.log(kb.detectQueryCategory('build a carpet store'))
console.log(kb.searchKnowledge('汽车', { topK: 'abc' }).examples.length)
NODE
```
