## 待老王确认 (P1 — 4 项)

### P1-1: `useEffect` deps `[onError, onResult]` callback ref drift (Pitfall #38 第一项)
- **代码位置**: `components/VoiceInput.js:16-51`
- **问题**: `useEffect(() => { ... new SR() ... }, [onError, onResult])`。父组件每次 render 传 inline arrow → useEffect 重跑 → 新 `SpeechRecognition` 实例创建,旧实例 `r.abort()` 但事件可能丢、内存泄漏
- **修法**: (a) `useRef` 镜像 callback 模式(参考 BrickRenderer.js 已有的 `onRenderedRef.current = onRendered`); (b) 强制父组件 `useCallback` 包裹 onError/onResult
- **风险**: 当前因死链未触发,但接线后高频 re-render 场景必崩

### P1-2: SR 配置 hardcoded (lang/continuous/interimResults)
- **代码位置**: `components/VoiceInput.js:22-24`
- **问题**: `r.lang = 'zh-CN'` 写死,无 props 暴露。未来海外用户/英文用户无法切换
- **修法**: 加 `lang` / `continuous` props,默认 `'zh-CN'` / `false`
- **优先级**: 中,产品决策(目前 BrickHub 仅中文市场即可)

### P1-3: `recogRef.current?.start()` 抛错不被捕获
- **代码位置**: `components/VoiceInput.js:55-64`
- **问题**: `start()` 同步可能抛(如已在 listening 状态、权限未授予即调用),代码先 `start()` 后 `setListening(true)`,若抛则 listening 状态未更新但 UI 也未提示
- **修法**: `try { recogRef.current.start(); setListening(true); } catch (e) { onError?.(e.message); }`
- **风险**: 用户多次快速点击会触发,体验断

### P1-4: `e.error === 'not-allowed'` 等权限错误无友好提示
- **代码位置**: `components/VoiceInput.js:39-43`
- **问题**: `onError?.(e.error)` 仅传字符串给父组件。但父组件(PromptDock,死链中)是否做了用户提示未知,且 `'not-allowed'` / `'no-speech'` / `'audio-capture'` 等几类错误需要差异化提示
- **修法**: 组件内自带最小 fallback Toast(如 `setError({ kind: 'permission', msg: '麦克风权限被拒绝,请在浏览器设置中允许' })`),或文档明确父组件处理契约
- **优先级**: 低-中,产品决策
