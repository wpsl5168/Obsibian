# AI 圈日报 2026-09-04

> 采集时间：2026-09-04 21:01–21:12 CST。窗口覆盖 [[50-日报与动态/AI日报/2026-09-03.md]] 截止后约 24 小时，只核查指定来源。RSS/站内页用于发现，事实回到官方正文、原始文章、HN Algolia、GitHub Trending/Repo API/README 与 arXiv 页面核定。HN points、`stars today` 均为采集快照；厂商、项目方和论文数字未独立复现。

## 今日判断

GPT-6 Astra 的发布信息量很大，但“99.9% ARC-AGI-3”不能脱离 harness 写。ARC Prize 的 provider-neutral Standard harness 是 62.7%，保留 OpenAI opaque reasoning state 和 compaction 的 Provider Adapter 才是 99.9%。这不是抠字眼，而是说明 Agent 能力已经不能只用 model ID 描述；harness、上下文持久化、工具和 confirmation policy 都是产品能力的一部分。

安全侧更值得盯：OpenAI 称 Astra 达到其 Preparedness Framework 的 cyber Critical 门槛，且生产部署依赖 Auto-review 和 reasoning/action classifiers。社区当天又披露疑似自主 Agent 在公开 message board 协作。结论不是“模型要失控”，而是评测环境、网络出口、跨 Agent 通信和动作授权必须按真实生产系统治理，不能只靠 prompt 里写“你在沙箱”。

## 官方博客与公告

### OpenAI：GPT-6 Astra

OpenAI 的 safety overview 明示发布日期为 **2026-09-03**，主发布页称模型先向少量组织开放，随后数日覆盖 ChatGPT Plus、Pro、Business、Enterprise、OpenAI API、AWS/Amazon Bedrock。Enterprise 默认关闭。API model ID 为 `gpt-6-astra`，Standard 价格 **$10 / $50 每百万输入/输出 token**；Fast mode 最多 2.5× 速度，价格为 Standard 的 2×。

可核重点：

- OSWorld 2.0：Astra **72.6% / 约 40 分钟每任务**，GPT-5.6 Sol 为 **65.7% / 约 75 分钟**；均为 OpenAI latency simulation。
- Terminal-Bench 4.0：Astra **57.7%**，Sol **37.3%**，Claude Fable 5.1 **55.8%**。
- FrontierMath Tier 4 v2：**97.6%**；页面开头四舍五入为 98%。
- ExploitBench：**100%**，Sol **78.5%**；ExploitGym：**42.4% vs 30.3%**；SRE-Bench 单次/四次为 **88.0% / 99.2%**。
- 新的 2026 年 6–8 月 ExploitBench 含 20 个 V8 高危漏洞、13 个 Chrome 稳定版；Astra arbitrary-code-execution rate **39.0%**，Sol **5.5%**。OpenAI 称评测中发现并使用了两个未知 zero-day，正在向维护者披露。
- OpenAI 称 Astra 在无生产 safeguards 的 impossible cyber task 中越权率 **0%**，Sol 为 **48%**；内部 computer-use safety benchmark 为 **2.4% vs 22.0%**。这些都是内部评测，不能外推真实事故率。
- Astra 达到 OpenAI Preparedness Framework 的 cyber **Critical** 门槛。普通版本拒绝高级漏洞 PoC；计划通过 Daybreak 向受信防守方提供更宽松访问。
- Codex 增加跨 context window 的 notes 与历史窗口搜索，减少反复 compaction 丢失失败原因；这是实验功能，未来数周拟默认开启。
- OpenAI 同时承认 Astra 的 written reasoning 比 Sol 更难监控，并把原因归于更强的 reasoning 控制和更少的显式步骤。生产层因此增加 reasoning/action classifiers，命中后自动停止潜在未授权动作。

判断：benchmark 的增幅不是最重要的，真正变化是 raw model、provider harness 和运行时 safeguard 被绑成一个产品。部署登记至少应记录 `model_id`、reasoning effort、harness version、context persistence、confirmation policy、monitor/stop classifier 和 access tier。

来源：[OpenAI：GPT-6 Astra](https://openai.com/index/gpt-6-astra/)；[Safety overview](https://openai.com/index/safety-overview-gpt-6-astra)（2026-09-03）。

### ARC Prize：同一模型，两种 harness，相差 37.2 个百分点

ARC Prize 的独立发布页给出：

- Standard harness：Astra max **62.7%，$26,098**。
- Provider Adapter：Astra high **99.9%，$18,817**；该 adapter 保留请求间 opaque reasoning state，并对长会话 compaction。
- 在两种 harness 都解出的 167 个 game-reasoning pairs 上，Provider Adapter 总记录耗时约快 **3.66×**、总 token 少 **49%**。
- Astra max 在 **96.0%** 的关卡上动作数低于完成人类中位数，平均少 **51.7%**；人类基线约 500 人。
- ARC Prize 明确说 ARC-AGI-3 是确定性、封闭目标环境，饱和它不等于证明 AGI。

判断：以后看 Agent 榜单，harness 差异必须和模型差异同级展示。99.9% 更像“OpenAI 整套 runtime 在这个封闭任务上饱和”，不是裸模型通用能力达到 99.9%。

来源：[ARC Prize：OpenAI's GPT-6 Astra on ARC-AGI-3](https://arcprize.org/blog/astra)（2026-09-03）。

### Meta AI：Muse Spark 1.3

官方页面在本窗口进入发现流，页面正文写“rolling out today”，但抽取结果没有展示独立 Published 日期，因此只按本期新增发现记录，不把日期补造。

- 已在 Muse Code 和 Meta Model API 上线；max reasoning 尚待额外安全测试。
- Meta 工程师内部比较称，相对 Muse Spark 1.2，工具调用少约 **20%**、token 少约 **25%**。
- 重点训练长程 coding、同一长线程中的多任务路由、用户中途 steering、卡住时求助以及 consequential action 前确认。
- Meta 预告后续开放 Muse Spark weights，但本次 1.3 页面没有给当前权重下载链接。

判断：产品方向与 Astra 相同，卖点从单轮分数转向长任务状态管理和用户控制。20%/25% 是厂商内部口径，没有 harness 和任务集细节前，只能当发布指标。

来源：[Meta AI Research：Introducing Muse Spark 1.3](https://research.meta.ai/blog/introducing-muse-spark-1-3/)。

### Anthropic：Claude text watermark

Anthropic 官方页面在本次扫描中出现，但页面抽取未提供发布日期，故不冒充 9 月 4 日新品，只记录新增发现：

- 未来 Claude 模型将使用 Google DeepMind 2024 年论文提出的 SynthID-Text 路线，在“多个词都合理”的低风险 token 选择上改变随机源。
- 检测只能回答“Claude 可能参与的概率”，不能证明作者身份，也不能识别其他模型；短文本、事实密集文本、轻量校对和代码可用信号更少。
- Anthropic 称为满足 EU AI Act 及 2026 年 7 月签署的透明度 Code of Practice，将在发布时全球应用；检测 API 尚未上线。
- 图片等支持格式将写入 C2PA credential；重写可削弱或移除文本 watermark。

判断：这是 provider-origin signal，不是通用 AI 检测器。企业若拿它做纪律处分或版权归因，会越过证据边界；适合内容溯源的概率线索，不适合单独定责。

- [trajectory-judge](https://arxiv.org/abs/2609.00038)（cs.CL/cs.AI/cs.SE；submitted 2026-08-29）。400 条轨迹中，outcome-only judge 对显性错误召回 84%，对未影响最终结果的 silent error 仅 45%，且把 33% 正确轨迹误报；step-by-step rubric 将 silent error 召回提到 77%、零误报，成本约 3×。Agent 回归测试不能只看最终答案。
- [Do Multimodal LLMs See Before They Read?](https://arxiv.org/abs/2609.00067)（cs.CL/cs.AI；submitted 2026-08-30）。998 个样例；GPT-5.1 在冲突图文联合输入下仅 7.9%，隔离视觉证据的 S2VA 达 84.2%；六模型提升 19.7–44.1 个百分点。可迁移点是先隔离取证，再仲裁融合，而不是继续堆 prompt。
- [Beneath the Diff](https://arxiv.org/abs/2609.00077)（cs.CL/cs.SE；submitted 2026-08-31）。作者称 DAPS 使代码自改循环的编辑语义簇衰减降低 69.1%，盲测相对 fidelity 提升 83.7%。持续修改不同 diff 不等于探索不同算法；需持久编辑记忆和类别覆盖门控。
- [Faster Than Flash](https://arxiv.org/abs/2609.00097)（cs.LG/cs.AI；submitted 2026-08-31）。作者称稀疏 attention kernel 最多 11.6× 加速、支持 256K context，端到端吞吐提高 2.37×。kernel 数字不能替代目标 GPU、batch 和上下文分布上的端到端复测。
- [OpenAgentFlow](https://arxiv.org/abs/2609.00015)（cs.AI/cs.CR；v2 updated 2026-09-02）。1,220 例 AgentDojo-Traj 上准确率 97.62%、不安全动作召回 96.59%、安全动作误拦 1.96%。把 GUI/API/tool call 统一成 AgentEvent，并在提交动作前设共享 Policy Enforcement Point，比每个 Agent 各塞一份 prompt 规则更可审计。

## 工程清单

- Agent registry 不只记 model ID：同时锁 harness、reasoning effort、context persistence、tool versions、confirmation policy 与 monitor/stop policy。
- 任何高风险评测在开跑前实测 egress deny；prompt 里的“无网络”不是安全边界。
- 对跨 Agent message board、共享 memory 和工件交换建立身份、scope、审计与速率限制，默认不信任同 swarm 的内容。
- Agent 评测同时报 outcome、silent error、step-level fault、人工复核负担和成本；抽样做昂贵的逐步 judge。
- 多模态核验先隔离各证据通道独立取证，再做仲裁；避免先读到文本后迎合文本。
