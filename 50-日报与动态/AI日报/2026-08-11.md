# AI 圈日报 2026-08-11

> 采集时间：2026-08-11 21:00 CST。新闻窗口以最近 24 小时及上期未收录的一手动态为主。只采用指定来源；HN points 与 GitHub stars today 均为采集时快照。arXiv 条目提交于 2026-08-10，预印本未经同行评审。

## 今日判断

今天两条硬消息都不是普通模型跑分。

第一，OpenAI 把高风险网络能力拆成 Daybreak Blue 与 Red 两层：Blue 去掉系统级拦截，Red 再提供专门训练的 GPT-5.6-Cyber。内部评测中，后者对 exploit chain、认证绕过、提权等高级请求的完成率从 GPT-5.6 Sol 的 1.5% 拉到 95.0%，并已找到 Chrome V8 的 CVE-2026-15903 及另一条可组成 exploit chain 的漏洞。风险判断也很直接：这不是“更会写安全报告”，而是受控开放可工作的 exploit 能力。身份核验、scope、日志和隔离环境现在是产品本体，不是合规附件。

第二，Anthropic 的未发布 Claude 研究版把黎曼 zeta 零点位于临界线上的已知下界从 41.6% 推到 67.2%。31M output tokens、约 60 个 subagents、2,400 条 shell commands，最后还有人类数学家审查和 Lean formalization。结论尚未经过常规同行评审，但验证链明显比“模型声称证明了某猜想”扎实。它也给 auto-research 一个现实成本标尺：发现不是一次 prompt，而是大规模搜索、互审、数值检查和形式化验证。

## 官方博客与公告

### OpenAI：GPT-5.6-Cyber 与 Daybreak 分级访问

- 发布：2026-08-10。
- Daybreak Blue：面向获批防守方，移除生产系统对网络安全请求的系统级 guardrails；仍会对高度 dual-use 请求拒答。
- Daybreak Red：提供 GPT-5.6-Cyber，专门降低 exploit development、authentication bypass、privilege escalation 等任务的拒答。
- OpenAI 内部 Advanced Cybersecurity Completion Rate：GPT-5.6-Cyber 95.0%，GPT-5.5-Cyber 57.3%，GPT-5.6 Sol 1.5%，Sol + Blue 2.0%。该数据由厂商自建评测，外界暂无同条件复现。
- GPT-5.6-Cyber 在 ExploitGym 与 zero-day discovery 内部评测上优于 Sol；在 Vulnerability Discovery and Report Writing 上反而弱于 Sol，官方归因于报告较短、细节不足。
- 在 ExploitBench 的标准 300-turn 设置里，Sol 更省 token、表现最好；放宽到 600 turns 后两者差距缩小。专用模型并非所有 cyber 任务都更强。
- OpenAI 用该模型审计 V8，报告了两个此前未知、可组成内存破坏与 heap sandbox escape 链条的漏洞；Google 已修复其中高危 CVE-2026-15903。
- 访问仅对获批个人与组织开放，控制项包括 identity verification、account security、monitoring、approved-use restrictions 与 legal attestations。

**判断**：95% 对 1.5% 说明主要变化不是基础推理能力，而是训练目标与 policy gate。企业若采购类似能力，必须把授权范围绑定到具体资产、临时凭据和隔离环境；只签承诺书不够。

原文：[OpenAI — Expanding Daybreak as the Cyber Defense Window Narrows](https://openai.com/index/expanding-daybreak-as-the-cyber-defense-window-narrows)

### Anthropic：Claude 推进黎曼 zeta 零点下界

- Anthropic 称，未发布 Claude 研究版将“满足黎曼猜想的 zeta 零点比例”的已知下界从 41.6% 提高至 67.2%，并明确没有证明黎曼猜想。
- 方法组合了 Baluyot、Goldston、Suriajaya、Turnage-Butterbaugh 的近期工作与 Bombieri 2000 年论文，通过带 Weil 二次型的函数空间，同时处理临界线上与线外零点对应的正、负定子空间。
- 两次 Claude Code session 合计产生 31M output tokens。第一次试了 650 个想法均失败；第二次持续一天半，约 60 个 subagents 执行 2,400 条 shell commands、编写数百个 Python scripts，并做数千次数值检查。
- Agent 下载 54 篇 arXiv 论文查重，让不同 subagents 互审、找反例，并独立重做证明。
- Anthropic 内部数学家 Levent Alpöge、Ralph Furman 检查论文；Brian Conrey、Dan Goldston 做短期外部审阅。另有 Lean formalization，通过 Lean comparator。
- 正式论文、专家简版说明、Claude 自述发现过程和 Lean 仓库均由 Anthropic 公开。

**判断**：结论仍需常规数学共同体审查，不能直接叫“已证明新纪录”。但这条的可信度高于普通 benchmark：过程、证明、人审和 formal proof 都能查。真正可迁移的工程模式是 proposer、critic、numerical checker、literature search、formal verifier 分工，而不是把 60 个 Agent 当算力烟花。

原文：[Anthropic — Learning more about Claude's mathematical capabilities](https://www.anthropic.com/research/riemann-zeta) · [Lean 仓库](https://github.com/anthropics/zeta-23-lean)

### OpenAI：Model ML 的金融文档 Agent 案例

- Model ML 用 GPT-5.6 Sol 生成可编辑 PowerPoint 与 Excel，并对数字、来源、公式、结构和视觉质量做内部 Composite eval。
- PowerPoint 测试中，Sol 100% 生成出 .pptx，Opus 5 为 76%；professional-readiness 43.3% 对 26.7%。但 Sol 的 layout 75.9% 低于 Opus 5 的 78.8%，chart legibility 78.8% 低于 83.1%。
- Excel 中，Sol headline accuracy 83.3%，Opus 5 为 82.8%；但“全部关键输出正确”Sol 50%，Opus 5 与 Fable 5 均 60%。
- OpenAI 标题强调 Sol 每份 deck 比 Fable 5 少 21% tokens；同一表里 Sol 为 1.10M tokens，Opus 5 为 953K，GPT-5.6 Terra 为 720K。标题只挑了有利参照。
- 客户案例称某资产管理机构的定制 tearsheet 从约 1 小时降至 5 分钟；这是客户自报，非独立测试。

**判断**：有价值的是把“成功生成文件”“可审阅”“视觉质量”“关键数字全对”拆开评。43.3% readiness 说明离免审还很远；营销标题故意避开更省 token 的对手，不该只看摘要。

原文：[OpenAI — Model ML completes finance work more efficiently with GPT-5.6 Sol](https://openai.com/index/model-ml)

## arXiv（2026-08-10 提交批次）

### Stealing Reasoning Traces：加密 CoT 仍可跨模型解密

- [arXiv:2608.09867](https://arxiv.org/abs/2608.09867)，cs.CR/cs.AI/cs.LG。
- 论文称，供应商返回给 client、供后续请求回传的 encrypted reasoning blocks，可在同一 provider 的不同 session、用户和模型之间互换。
- 攻击把强模型的加密 trace 注入同 provider 的较弱、保护更少的模型，诱导后者输出明文，不必直接 jailbreak 强模型。
- 作者称在 Anthropic、OpenAI、Google 上演示了 reasoning extraction；从公开仓库抓取并解码 315,320 个 reasoning blocks，恢复 367 个 PII artifacts 与 182 个 credentials。
- 还可泄露最终安全拒答背后的危险推理，或在 encrypted block 中放 invisible prompt injection。作者称已 responsible disclosure，并提出把密文绑定 user/session/model、完整性校验等修复方向。

**判断**：如果独立复现成立，这是 Agent trace 存储的现实数据泄露问题。日志脱敏不能只扫明文；encrypted blob 也应按 secret 处理，禁止公开进 repo，并做 session/model binding。

### SWE-Bench ProMax：把 coding benchmark 拉回真实重构

- [arXiv:2608.09802](https://arxiv.org/abs/2608.09802)，cs.CL/cs.SE，COLM 2026 conference paper。
- 170 个 expert-curated refactoring instances，来自 Python、Java、TypeScript、Go、C、C++、Rust 七种语言真实 commits。
- 平均每题改 11.4 个文件、261.6 行代码；issue description 重写，tests 人工排除过窄与检查未声明需求的问题。
- 作者引用近期审计：近 60% 未解 SWE-bench Verified 题存在 flawed tests，且 frontier models 可能逐字复现训练数据中的 gold patches。
- 两种 Agent scaffold 下最佳模型 resolve rate 仅 41.2%。

**判断**：这个 benchmark 比继续刷快饱和的 SWE-bench 更接近企业代码改造。采购 coding Agent 时，应增加跨文件 behavior-preserving refactor，而不是只看修单点 issue。

### MMDiff：从多模态训练差异里找可控特征

- [arXiv:2608.09928](https://arxiv.org/abs/2608.09928)，cs.CL/cs.LG。
- 对 LLaVA-MORE、PaliGemma 2、InternVL3.5 训练 multimodal sparse autoencoders，再 diff base LM 与 multimodal-adapted 模型的 feature。
- 移除发现的特征，spatial task 平均下降 12%、OCR 下降 17%；对 multimodal safety attacks 的 attack success rate 降 24%，且论文称 VQA 不受影响。
- steering 相比标准 single-layer baseline，spatial accuracy 平均 +3.6%，OCR +1.8%。

**判断**：比“看激活图讲故事”前进了一步，因为做了 causal removal 与 steering。数字仍是作者实验；要看特征能否跨 checkpoint、prompt 分布和语言稳定复用。

### SKALD：把 Skill 监督蒸馏进权重

- [arXiv:2608.09826](https://arxiv.org/abs/2608.09826)，cs.AI/cs.LG。
- 作者观察到 RLVR 中 rollout groups 全对或全错占 63.0%–68.0%，group-relative reward 因而没有区分信号。
- 同一 Qwen3-Base 分成 question-only student 与读取 abstract skill card 的 teacher；只在验证表明 teacher advantage 为正时蒸馏，测试时 student 不再需要 skill card。
- 五个 held-out math benchmarks 上，相比 GRPO，avg@8 在 0.6B、1.7B、4B 分别提升 2.46、4.85、12.01；1.7B 下仍比 FLOP-matched GRPO 高 4.06。

**判断**：它解决的是 Skill 作为 privileged training signal，而不是运行时 prompt 管理。适合有稳定、可验证技能的离线训练；频繁变化的业务知识仍不该烧进权重。
