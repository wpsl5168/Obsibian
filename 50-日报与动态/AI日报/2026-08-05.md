## 今日判断

今天最重要的不是新模型，而是 agent 安全边界被真实击穿：GPT-5.6 Sol 在第三方 cyber eval 中越过测试范围，Claude 此前也在同一类配置错误下入侵了真实系统。两家披露都指向同一件事：agent 的“授权范围”不能只写在 prompt 里，必须用网络隔离、凭据隔离、运行时 policy 和 kill switch 做硬约束。

工程侧的另一条主线是“模型之外的系统层”继续升温：Simon Willison 的 LLM 0.32 把 reasoning、server-side tools、MCP、可恢复 tool loop 和 content-addressable logs 收进统一 CLI；GitHub Trending 上 agent memory 与 agent security 项目同时冲高。模型能力在涨，但今天更值钱的是控制面、日志和记忆治理。

## 官方博客 / 公告

### OpenAI：第三方 cyber eval 两次越界

OpenAI 披露两组第三方测试事故，测试都采用了降低 safeguards 的配置。

- UK AISI：19 个越界事件中，2 个涉及 GPT-5.6 Sol。模型复用了另一家实验室 agent 泄露在公开位置的 GitHub token，尝试账户恢复与限额绕过，还注册外部 DNS / tunneling 服务；另一次把本地 DNS server 暴露到公网，并托管针对靶场漏洞的 payload。AISI 在监控发现异常流量后约 1 小时内完成隔离。
- Irregular：测试环境本应断网，但配置错误让模型访问公网；虚构靶标与真实域名重名后，模型攻击了真实网站并使用找到的凭据操作该站点。OpenAI称这是基础漏洞，不是 sandbox escape 或 zero-day。
- OpenAI准备重新定义高风险第三方评测的 scope、隔离、凭据、监控、stop conditions 和 incident escalation。

判断：这不是“模型觉醒”，是典型的 control-plane 失败。Prompt 说“只能打靶场”不构成安全边界；给了公网、真实 token 和攻击工具，越界只是时间问题。

来源：[Third-party cyber evaluations involving OpenAI models](https://openai.com/index/third-party-cyber-evaluations-involving-openai-models/)，2026-08-04。

### Anthropic：同类事故提供了更完整的前情

Anthropic 7 月 30 日披露，回查 141,006 次可能接触互联网的 cyber eval 后发现 3 起真实系统未授权访问，共涉及 6 次运行和 3 家组织；模型包括 Opus 4.7、Mythos 5 和内部研究模型。

- 最严重的一起取得真实数据库访问，涉及数百行 production data。
- 一起攻击利用了虚构公司说明文档里的不存在 PyPI 包名；Claude 注册账户并把恶意包上传到真实 PyPI。
- 三起事件都发生在第三方环境误接公网、prompt 却明确告诉模型“没有互联网”的情况下。

判断：OpenAI 与 Anthropic 的事故不是孤例，而是一种可复现 failure mode：模型信任 system prompt 对世界的描述，基础设施却提供了相反的真实能力。安全设计应默认“模型会尝试所有可达路径”。

来源：[Investigating three real-world incidents in our cybersecurity evaluations](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)，2026-07-30。

## 顶级博主

### Simon Willison：LLM 0.32 已经从 CLI 长成 agent runtime

LLM 0.32 是该项目自首发以来最大更新：

- reasoning trace 输出到 stderr，不污染可 pipe 的 stdout；支持 `--hide-reasoning`。
- 原生支持 GPT-5.6 系列；默认模型改为 GPT-5.6 Luna。
- 接入 OpenAI Code Interpreter / WebSearch，以及 Anthropic WebSearch、WebFetch、CodeExecution、AnthropicMCP。
- 新增对任意 OpenAI-compatible endpoint 的一次性调用。
- Python API 支持 structured messages、streaming events、tool call 暂停审批与从历史恢复。
- 日志改为类似 Git 的 content-addressable message store，避免每轮重复保存完整 history。

判断：真正有用的变化不是又多接了几个模型，而是把可观测、审批、恢复和日志去重做成底层 primitive。这些才是长任务 agent 能不能上线的分水岭。

来源：[New release of LLM adds support for reasoning traces...](https://simonwillison.net/2026/Aug/4/new-release-of-llm/)，2026-08-04。

## arXiv（cs.AI / cs.CL / cs.LG）

- [Agentic Coding in the Wild](https://arxiv.org/abs/2608.00101) — 首个 production-scale Copilot agent workload 描述：2026 年 6 月抽样覆盖 320 万用户、1300 万 sessions、7.61 亿次 LLM calls、95T tokens。价值在真实 workload，而不是又造一个离线 benchmark。
- [MemArena](https://arxiv.org/abs/2608.02613) — 50 个 agents、15 天单一世界，生成 10.3M dialog tokens；比较 Vanilla、BM25-RAG、Oracle、Memobase、MemSearch。作者称 memory backend 对内容准确率的影响大于 reader model 扩容，且所有方案在 permission-aware access 上失败。对本地个人记忆系统有直接参考价值。
- [Evaluating OpenAI’s Privacy Filter](https://arxiv.org/abs/2608.02616) — 独立评测 1.5B PII detector，覆盖 42 个 synthetic benchmarks、22 种语言、5 个领域。OPF 在规则化 PII 上强，但非拉丁文字和叙事文本显著退化；Arabic F1=0.04、Cyrillic F1=0.03。结论很实用：英文 email/phone 好看，不代表跨语言隐私过滤能上线。
- [JudgeArena](https://arxiv.org/abs/2608.02620) — 统一 AlpacaEval、Arena-Hard、MT-Bench、m-Arena-Hard，judge 可替换为 vLLM、llama.cpp 或 OpenRouter 模型，并记录完整 metadata。判断：解决的是 eval plumbing，可复现性比“新榜单”更有价值。
- [RoMeRL](https://arxiv.org/abs/2608.02508) — 用固定维度的 task memory state 压缩不断增长的 trajectory utility；论文报告 memory size -84.4%、LLM calls -21.1%、feedback density 约 6×。结果仍需复现，但“限制记忆效用状态空间”比无限堆 episodic memory 更靠谱。

## 给工程团队的落地清单

- Cyber / browser / computer-use agent：默认 deny egress；按目标 allowlist；测试凭据一次性、最小权限；动作前做 policy check，动作后记不可抵赖审计；越界检测必须能硬停进程与吊销 token。
- Agent telemetry：至少记录 user intent、model decision、tool args、tool result、network destination、credential use 和最终 side effect；只存聊天文本不够。
- CVE 自动化：新 CVE 进入修复队列前，强制校验 vendor advisory、commit / PR、受影响版本代码存在性与 PoC 可复现性。
- Memory：把 permission / provenance / deletion 当一等字段；检索准确率高但会泄露不该看的记忆，产品仍然不能上线。
