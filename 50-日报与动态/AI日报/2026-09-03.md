## 今日判断

今天真正的主线不是 Gemini 又涨了几分，而是前沿厂商开始把网络安全能力拆成公开版和受信版。Google 的 Gemini 3.8 Flash Cyber 与昨天 Anthropic 的 Mythos 5.1、OpenAI Astra 方向一致：同底座或同代能力，按访问者身份、用途和审计条件开闸。企业接入模型以后不能只记 model ID，还要记 access tier、safeguard profile 和能力有效期。

Agent 工程则有三个能直接落地的信号：长链可靠性应按每步误差预算，而不是只报总 pass rate；评测失败可以用轻量分类器提前止损；仓库知识先编译成带来源和约束的 skill/spec，再交给 coding agent，比塞 README 或自由文本计划靠谱。

## 官方博客与公告

### Google：Gemini 3.8 Flash 与受限开放的 Flash Cyber

正文日期为 2026-09-02；这是六周内第三次 Flash 更新。

- Gemini 3.8 Flash 的 HLE-Verified 为 **54.9%**。Google 明说复杂任务会执行更多 reasoning step 和 tool call、可能消耗更多 token；算力优先场景可降低 effort 或继续使用 3.7 Flash。
- Flash Cyber 在覆盖 **20 种编程语言**的内部漏洞发现评测中成功率超过 **70%**；CWE-Bench pass@1 为 **47.2%**，对比文中领先模型的 47.8%。数字均为 Google 口径。
- 普通 3.8 Flash 带 CBRN 与 cyber offense safeguards；Flash Cyber 使用更宽松的网络安全限制，只通过 Fairwind Program 向受信防守方开放。
- 正文脚注写明 introductory price 在 2026-12-31 到期；2027-01-01 起输入/输出价格为 **$1.50 / $7.50 每百万 token**。页面抽取未完整显示当前 introductory price，因此不补造。

判断：Cyber benchmark 差距不大，真正变化是能力闸门。模型注册表应把 access tier 和 safeguard profile 当一等字段，否则同一个名称在不同账户下不是同一种产品。

来源：[Google：Introducing Gemini 3.8 Flash and 3.8 Flash Cyber](https://deepmind.google/blog/introducing-gemini-3-8-flash-and-38-flash-cyber)（2026-09-02）。

### Google：Fairwind 网络安全计划

- Fairwind 首批面向政府、Google Cloud 客户和网络安全伙伴，提供 Gemini 3.8 Flash Cyber 与 CodeMender。参与组织须把访问限制在内部安全、事件响应或渗透测试人员，并部署 MFA 等控制。
- Google 称已有全球 **650 多家**参与伙伴。
- 官方称 CodeMender 可把人工数周的漏洞修补压到数分钟，并生成经过验证、可部署的补丁；这是厂商声明，正文没有独立生产统计。

判断：这不是普通模型发布，而是“更强能力换更重身份与运行控制”的分发模式。650 家伙伴说明 restricted access 已经能规模化，不再只是少量红队试用。

### Simon Willison：Claude 的公开 system prompt 不是完整运行上下文

- Fable 5.1 新规则禁止复现歌词、诗歌、书籍和文章段落；歌词与诗歌仅明确放行 **1929 年前**首次发表的作品。规则也覆盖用 SVG、Canvas、CSS、HTML 和 ASCII art 重画版权角色、logo 与产品设计。
- 提示词新增简短回答要求，并要求避免 `genuinely`、`honestly`、`straightforward` 等修饰语。
- 公布的核心 prompt 删除了 `end_conversation` 规则，但 Simon 从实际会话确认，工具、memory、past chats、web search、artifact 等还有按功能注入的额外 prompt blocks，Anthropic 没有公开这些层。
- Fable 5.1 的 reliable knowledge cutoff 与 training data cutoff 均为 **2026 年 6 月**。

判断：厂商“公开 system prompt”只能证明核心层，不能证明最终执行策略。做安全审计或行为复现时，必须记录功能开关、工具层提示和动态注入内容，不能拿一份公开 Markdown 当全量证据。

来源：[Simon Willison：Claude’s new system prompt really doesn’t want to reproduce song lyrics](https://simonwillison.net/2026/Sep/2/claudes-new-system-prompt/)（2026-09-02）。

## arXiv

9 月 3 日分类页显示 cs.AI / cs.CL / cs.LG 分别有 **58 / 61 / 83** 篇 new submissions，另有 104 / 40 / 76 篇 cross-list。下列 `submitted` 来自 Atom API，不把分类页日期冒充提交日期。均为预印本，数字是作者自报。

- [READY or Not](https://arxiv.org/abs/2609.02095v1)（cs.AI；submitted 2026-09-02）。16 个 agent 系统、750 个临床审计案例中，两个 autonomous accuracy 只差 0.3 点的系统，要达到同一 **76% reliability**，分别需 **39.2% / 29.6%** 人工复核。Agent 上线验收必须同时报可靠性目标、监督负担和成本。
- [Repo-To-Skill](https://arxiv.org/abs/2609.02749v1)（cs.AI/cs.CL；submitted 2026-09-02）。从 1,000 个 ML 仓库蒸馏出 5,000+ verified skills，覆盖 20 个领域、178 个能力族；固定 GPT-5.5、harness 和执行预算后，MLE-bench +134.3%、PaperBench +34.4%。结论和 Hermes 路线高度相关，但涨幅过强，需复核 skill 验证标准与 baseline 公平性。
- [PaperCompiler](https://arxiv.org/abs/2609.02272v1)（cs.CL/cs.AI/cs.SE；submitted 2026-09-02）。先把论文证据编译成仓库级规格，区分来源、推断、外部委派和未决项，并写入跨文件依赖与不可退化约束；Paper2CodeBench fidelity **3.64→4.15**，高严重度批评 **13.2%→6.1%**。比自由文本 plan 更适合多 Agent 编程。
- [EarlyEval](https://arxiv.org/abs/2609.02783v1)（cs.CL；submitted 2026-09-02）。用一对 LightGBM 成功/失败分类器提前停止 agent run；在 SWE-bench Verified、TerminalBench、Toolathlon 上减少 **13%–26% steps**、最多 **44.1% input token / 29.4% output token**，预测准确率 89%–97%，resolve rate 平均只波动 1–2 点。适合压回归测试成本，但必须保留随机全跑样本防误杀。
- [How Fast Do Agents Rot?](https://arxiv.org/abs/2609.01660v1)（cs.AI cross-list；submitted 2026-08-31）。9 个模型、10,664 条轨迹；工具型任务中所有模型在 16 步内从接近满分跌至接近零。限制上下文衰减反而更快，说明主变量是 dependent steps，不只是 lost-in-the-middle。生产链路应拆阶段、设检查点和每步可靠性预算。
- [Harness Engineering / HEART](https://arxiv.org/abs/2609.01736v1)（cs.AI/cs.CL/cs.LG cross-list；submitted 2026-09-01）。从 25,519 个函数动态检索 tool primitive；五个 benchmark 平均高于 SFT 模型 10%、高于三款商业模型 6%，API 成本最多降 85%；50 个真实任务完成率 84%。自然语言 wrapper 会隐藏 schema 错误，仍需类型验证和执行审计。
- [ExecRetrieval](https://arxiv.org/abs/2609.01865v1)（cs.CL cross-list；submitted 2026-09-01）。939 个 Python 任务、23 种向量配置；最佳系统 exec@10=1.00，但 exec@1 仅 0.331，领先系统 91.5%–99.4% 的 rank-1 错误是近似但有 bug 的代码。代码 RAG 的 embedding 相似度不能替代执行验证。
- [NeoMME](https://arxiv.org/abs/2609.01657v1)（cs.AI cross-list；submitted 2026-08-31）。260M/800M 单塔多模态编码器，支持 16,384 token、最多两张 4K 图；260M 在 L40S 页面编码吞吐约为对照 2×，文档向量压缩 255× 后保留超过 95% nDCG。模型与 checkpoint 以 Apache-2.0 发布。
- [Leech Lattice 2-bit serving](https://arxiv.org/abs/2609.02652v1)（cs.LG；submitted 2026-09-02）。4B/8B/14B 端到端分别加速 1.11×/1.29×/1.41×；4B 配 int8 输出头达 87 tok/s、2.60GB，但困惑度变为 1.38×、MMLU 下降 14.7 分。它把极低比特的质量税写清了，比只报压缩率有用。

## 工程清单

- 模型 registry 增加 `access_tier`、`safeguard_profile`、能力到期时间和审计要求；同名模型不能默认等价。
- Agent 任务按 dependent steps 建可靠性预算，长链拆阶段并做 checkpoint；扩大 context 不是通用解法。
- 回归评测可加 EarlyEval 式 early stop，但保留随机全跑与误杀监控。
- 把仓库/论文知识先编译成带 provenance、unresolved items、cross-file constraints 的 skill/spec，再交给执行 Agent。
- 代码 RAG 的最终候选必须过编译、单测或 sandbox execution；embedding rank 只能负责召回。
