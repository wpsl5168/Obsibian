## 今日判断

今天没大厂模型发布，真正有用的是三条工程信号。

第一，MCP 的重点已经不是再加一种 tool call，而是补长任务、异步事件、机器身份和大工具目录。7 月规范已移除协议级 session 与初始化握手；新路线图继续推进 server events、DPoP、Workload Identity、委托授权和渐进式工具发现。方向对，但目前多数仍是 roadmap，不应把计划当成已交付能力。

第二，本地模型“变笨”不能先甩锅给量化模型。Qwen3.6-27B 的单机实验表明，仅切换 vLLM attention backend，约 100k token 的真实 Agent 上下文后段就出现 top-1 分歧；只量化 KV cache 后，INT4 还会破坏工具调用。验收必须覆盖目标 chat template、采样参数、长上下文和真实 tool call，短问答加吞吐压测不够。

第三，Simon Willison 的 `llm 0.33` 补完昨日依赖事故：升级 OpenAI Python SDK 3.x，并从 `httpx` 切到 `httpx2`。这次修复速度快，但也再次说明 provider SDK 升级必须经过干净安装和 smoke test，不能直接穿透生产。

### Simon Willison：llm 0.33 完整修复依赖事故

正文日期 **2026-08-22**，发布时间 17:01 UTC，即 8 月 23 日 01:01 CST。

- 升级到 OpenAI Python SDK 3.x，并将 HTTP client 从 `httpx` 切换到 `httpx2`；作者明确称这是 0.32.1 临时修复后的完整方案。
- `llm embed`、`embed-multi` 与 Python embedding API 新增 per-call `--key` / `key=`，不修改共享模型状态；旧插件可走兼容 fallback。
- `--template` 可重复传入并按顺序组合。
- Responses API 模型新增 `reasoning_summary=auto|concise|detailed`。

判断：最重要的不只是恢复安装，而是 per-call key 避免共享模型状态被并发请求污染。0.33 仍应补 clean-venv 安装与 provider plugin 回归，防止昨天同类事故重演。

原文：[Release: llm 0.33](https://simonwillison.net/2026/Aug/22/llm/)

### Simon Willison：代码审查不是 Agent 验收的唯一方式

Simon 认为，编码 Agent 的关键能力是能明确要求修改，并可靠验证结果；逐行阅读所有代码通常不是最有效的验证方式。

判断：观点对，但不是“以后不用 review”。验收可以从逐行阅读转向行为测试、diff 风险扫描、权限边界和可复现检查；高风险路径仍要人工看代码。

原文：[More than just code review](https://simonwillison.net/2026/Aug/22/more-than-just-code-review/)

### MCP 新路线图 — 226 points

7 月 28 日规范已经移除协议级 session 与初始化握手，服务端可无状态横向扩容；客户端可先用 `server/discover` 获取版本和能力。下一阶段聚焦：

- server-initiated events，减少长任务轮询；
- HTTP transport 统一，包括本地 server over stdio；
- DPoP、Workload Identity Federation、ID-JAG、token exchange，用于 Agent 自身身份与委托授权；
- 渐进式工具发现，避免连接百工具 server 时一次性把整个目录塞进上下文；
- 统一工具结果契约。

判断：这是今天最重要的协议动态。MCP 正从“工具调用格式”补成长任务和企业身份协议。渐进发现很实用，直接处理 token 成本与 tool selection 退化；但路线图内容尚未交付，落地时还要盯 SEP 与 SDK conformance。

### 本地 LLM 变笨，可能是推理栈而非模型 — 393 points

作者用 Qwen3.6-27B BF16、RTX PRO 6000、固定 nightly vLLM，在约 100k token 的真实 Agent 上下文上测试。只切换 FlashAttention 2、Flash Inference 与 Triton Attention，前几千 token 一致，后段开始出现 top-1 token 分歧；同 backend 重跑的 hidden-state logits 则逐位一致。只量化 KV cache 时，BF16 工具调用正常，INT8 最终恢复，INT4 未恢复。权重量化对照中，NVFP4 与 AWQ W4A16 均未正确闭合 tool call，并执行了错误 Cisco 命令。

判断：这是单模型、单 GPU、单工作负载实验，不能外推所有模型；但足够推翻“相同权重就必然相同行为”的偷懒假设。本地推理验收要固定完整 runtime 指纹，并用真实长上下文工具链做 canary。

[HN：393 points](https://news.ycombinator.com/item?id=49402232)｜[原文](https://forum.level1techs.com/t/why-your-local-llm-feels-dumber-than-it-is/253917)

## arXiv

2026-08-23 为周日，cs.AI、cs.CL、cs.LG 的 `new` 页面仍对应 **Friday, 21 August 2026**，没有周末新列表。以下是与昨日去重后的延迟发现，提交日期来自 arXiv Export API；均为预印本，未同行评审。

- [Outcome Monitors: Recovery Affordances for Silent Tool Failures](https://arxiv.org/abs/2608.19303) — cs.AI/cs.CL/cs.SE，提交于 8 月 19 日 UTC。ToolMaze 完成率 **10.9%→28.1%**；tau-bench 两档提升 **14、12 个百分点**。移除 receipt 中的 recovery-tool list 后收益消失；恢复列表后收益回来。判断：关键不是多写错误解释，而是明确告诉 Agent 可用的恢复动作；但合同词表外检测率只有 **46%**，泛化仍弱。
- [DeltaMomentum](https://arxiv.org/abs/2608.19491) — cs.LG/cs.CL，提交于 8 月 19 日 UTC。达到 AdamW 同等验证损失所需步骤，67M 模型最多减少 **46.39±4.32%**，370M 减少 **22.12±0.80%**；额外计算为 gated-MLP 线性层成本的 **22.2–25.0%**，无持久额外内存。判断：可替换 momentum buffer 的明确方案；训练步数下降不等于墙钟时间同比下降，需实测 kernel 与分布式通信。
- [When to Retrain](https://arxiv.org/abs/2608.19488) — cs.LG，提交于 8 月 19 日 UTC。覆盖 **3,933** 次实验、54 组配对；无增量更新时，不同策略使漂移后准确率相差 **15–55 个百分点**。判断：对即时标签的线性在线模型，是否增量学习比选哪种漂移触发器更重要；不可直接外推深度模型和延迟标签场景。
- [Hear2Act](https://arxiv.org/abs/2608.19515) — cs.CL，提交于 8 月 20 日 UTC。含 **480** 个场景；直接增加音频时最优决策率仅 **14.6%→15.3%**，先把语音关切显式转成中间状态后升至 **39.6%**，接近真实状态输入的 **40.7%**。判断：语音 Agent 可能听出了语气，却没把它带进决策；显式抽取 concern/state 比把音频直接塞进端到端模型更靠谱。
- [CacheRoute](https://arxiv.org/abs/2608.19677) — cs.DC/cs.LG，提交于 8 月 20 日 UTC。Llama-3.3-70B FP8、**60 张 H100** 下，在 3.5 秒 p99 SLO 时达到 **176±11 QPS**，为五个基线中最强者的 **2.3×**；KV cache 命中率 **64.1±1.3%→93.2±0.5%**。判断：前缀亲和路由收益具体，但论文也给了两个 32B 反例；应先 shadow replay，不能看热 key 统计就上线。

分类入口：[cs.AI](https://arxiv.org/list/cs.AI/new)｜[cs.CL](https://arxiv.org/list/cs.CL/new)｜[cs.LG](https://arxiv.org/list/cs.LG/new)
