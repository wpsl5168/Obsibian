## 今日判断

今天最该看的不是新模型，而是 Agent 的“配置债”。一篇对 1,867 个仓库的研究称，CLAUDE.md 一类指令文件在生命周期内平均增长 226%；追加规则很便宜，等规则失去来由后，安全删除却越来越难。作者把问题叫作 catastrophic remembering，并给出很朴素的修法：给规则保留 rationale/comment。其受控实验中，注释将冗余增长从 211.3% 压到 1.4%。这比再做一个 prompt compressor 更接近工程根因。

另一篇 TideRL 说明 Agentic RL 的瓶颈也变了：多轮 rollout 会等待外部环境、上下文持续增长，GPU occupancy 高不等于训练有效。按 task readiness 做 continuous batching、actor pipeline 与弹性资源调度，作者报告相对同步基线最高 5.6 倍 goodput、等待时间最高下降 77.6%。如果数字能复现，Agent RL 集群首先该优化等待和重复 prefill，不是盲加卡。

## arXiv（2026-08-11 提交批次）

### Catastrophic Remembering：Agent 指令文件为何只增不减

- [arXiv:2608.11095](https://arxiv.org/abs/2608.11095)，cs.AI/cs.LG/cs.SE。
- 数据覆盖 1,867 个仓库、247,694 条 instruction lifetimes。
- 作者称 agentic prompts 生命周期内平均增长 226%，每次 commit 净增 4.9 条 instructions；规则越老越不易删除，log-hazard 为 -0.032/commit。
- 理论直觉：追加一条规则成本低；当规则 rationale 丢失后，要在不引入 regression 的前提下判定删除，最坏成本随规则集合呈指数增长。
- 在反转 IFEval 构造的可验证环境中，记录 latent reasoning 的 prompt comments 将 excess instructions 从 +211.3% 压到 +1.4%，减少 99.3%；在 WildIFEval 上 instruction-following 最高提升 23.1%。

**判断**：这与真实 skill/memory 维护高度相关。规则必须同时保存触发条件、原因、失效条件和验证方式；只保存“以后永远这样做”，迟早变成没人敢删的配置债。统计来自论文作者，尚待独立复现。

### SkillZip：不跑 eval 的结构化 Skill 压缩

- [arXiv:2608.11079](https://arxiv.org/abs/2608.11079)，cs.AI。
- 将 skill 看作 typed contract，而非平面文本；重复规则上移到共同 scope，重复动作提取为共享 procedure，只保留差异化 exception。
- 用 minimum description length 目标压缩，同时对 trigger、workflow edge、tool requirement、obligation、output field 设置 hard coverage。
- 支持一次 structured extraction + deterministic optimization，也支持 Zip-on-Write 增量合并，不要求 replay tasks 或重解析全部历史。

**判断**：结构思路对，但“evaluation-free”不能等于“behavior-free verification”。它能证明字段没丢，不能证明压缩后模型执行语义不漂；生产合并仍应跑最小 regression set。摘要没有给具体压缩率，不能替作者补数字。

### TideRL：Agentic RL 应按 readiness 调度

- [arXiv:2608.10402](https://arxiv.org/abs/2608.10402)，cs.LG/cs.DC。
- Continuous Task Batching 保留 rollout state，避免反复 prefill；Resource-Aware Ref-Actor Pipelining 在 decoupled streaming 与 colocated aggregation 间动态选择；Elastic Resource Scaling 按 readiness 在 rollout 与 training 间移动 ranks。
- 作者报告：相对同步基线最高 5.6× goodput，相对异步基线高 33% 以上；KV cache hit rate 1.58×，per-step training time 最多下降 44.3%，总等待最多下降 77.6%，任务效果相近。

**判断**：这是系统论文，关键指标应是 useful training throughput 和 wait breakdown，不是 GPU utilization。数据仅为作者实验，需看 workload、集群规模和重分配开销后再判断可迁移性。

### Recovering Wasted Compute in Autoresearch Agents

- [arXiv:2608.10424](https://arxiv.org/abs/2608.10424)，cs.AI/cs.LG。
- 作者在表格数据 autoresearch 中归纳四类浪费：不同 search branch 重复修同一 bug；剩余预算充足却不调超参；tree search 实际不探索；做了数据分析却不把结论用于后续决策。
- 干预包括全局 debug consultant，把 runtime constraints 跨 branch 共享；再配合 prompt/control 改造与新的 tree-search 规则。在基础模型不变时，作者称可获得显著提升，但摘要未给统一数字。

**判断**：这比“多开 subagent”更实在。并行分支必须共享已证伪方案、环境约束和失败签名，否则只是在并行烧同一种错。
