## 今天的判断

**别用 Skills 的数量和星数代替质量验收。** Dan Luu 在 Rust/Zstd 任务上测试不同提示和 Skills：给 Agent 一个 TDD 或形式化工具的名字，常常只是换了测试外壳，并没有测到更容易出错的地方。他用隐藏测试验收，正好避开“实现和测试复制同一个错误”的自证循环。单项实验不能证明 TDD 没用，但足以提醒我们：看 Agent 实际执行了什么，别只看提示写得多专业。

ECC 今天合入的补丁把这件事落到了代码：删掉虚构的 MCP 包和 dispatch 接口，给可执行示例补回归检查，还收紧路径豁免与配置更新边界。**高星合集也可能教你调用不存在的东西。** 这些是 main 上的待发布补丁，不是2.2.1已经可安装。

Mistral的30亿欧元融资可以看，但钱不是模型能力证明。公告没有带来一套新权重和许可证；企业选型仍要核部署、数据边界与实际可替换性，而不是照单全收“主权AI”的宣传。

## Hacker News：给 Agent 指定 TDD/形式化工具，不等于它真的会测

- 原文：[Dan Luu — How well do agents use test/verification techniques?](https://danluu.com/agentic-testing/)
- 讨论：[HN 49605246](https://news.ycombinator.com/item?id=49605246)，**120 points / 45 comments**。
- HN 提交时间：2026-09-08 02:58:16 UTC（10:58:16 CST），属于近 24 小时。正文谈的是 September 2026 实验；页面未提供可核的精确发布日期，因此采用“本期 HN 新发现”，不擅称作者 9/8 才做实验或发文。

**实测范围：**

Dan Luu 让 Codex / GPT-5.6 Sol 用 Rust 实现 Zstd，比较 **26 种提示条件，另加 4 个 Skills 条件**；展示 medium 与 xhigh 两档，各条件各档 **80 次运行**。评价轴是成本和“隐藏测试全部通过的运行占比”，不是 Agent 自己写的测试通过率。另做 IMAP RFC 等补充任务，不能把单项实验当覆盖所有软件开发。

“Use TDD”“Use Lean 4”“Use QuickCheck”这类短指令经常只改变表面形式：把普通单元测试塞进新框架、证明与高风险实现无关的性质，或者用完全随机输入反复覆盖同一拒绝路径。原文举例，四条 Huffman 流的测试把输入做成完全相同，遗漏流顺序颠倒；差分测试又把同一错误写进两份实现。

Hegel 官方 Skill 的这次实验中，作者报告 **medium 成本高 26%、xhigh 高 41%**，正确性没有改善；这是此任务/模型/配置下的作者测量，未独立复现。不要改写成“所有 Skills 让成本高 41%”。ECC Rust 测试 Skill 的总体分数接近 Default，但作者检查实际使用情况后认为总体数值受未读/晚读 Skill 的高分运行影响；不把其事后观察写成已经建立因果关系。

作者自己写的短 Skill 提醒：先找可能犯错的区域，列出不同解释，用非对称/边界样例区分，结构化随机输入避免只测崩溃。它在此实验得分最高，但作者明确说 **还没准备好作为通用 Skill 使用**，其中“新上下文独立推导”的要求几乎没被执行。他也提示实验设置曾有错误，修正后结果更平淡，部分细节未完整展开。因此不引用图中细小排名作为普适结论。

**判断：**昨天只有“怎么管理 Skills”的经验讨论；今天补上了“要测具体行为，而非收藏名词”的实验材料。可执行建议是先建立不会由被测实现自证的验收标准，再检查测试是否真的覆盖高风险状态。它不是“别用 TDD/形式化方法”，而是“不能用提示里出现了 TDD/Lean 代替验证是否正确使用”。

可核原句：
- `the fraction of runs that passed 100% of the (hidden) tests ... average of 80 runs from each condition and effort`
- `agents tend to either just write the tests they would normally write, but inside a framework for a different type of test technique`
- `cost was much higher (26% higher on medium and 41% on xhigh)`
- `I don't think it's really ready to use either`（作者自制 Skill）
