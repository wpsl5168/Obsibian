## 今日判断

今天最重要的两条都不是模型发布。OpenAI 预告 Private Safety Processing，试图在 Zero Data Retention 下跨多轮识别风险：客户内容留在客户基础设施，或由客户持钥加密存放在 OpenAI；OpenAI 只收风险类别和严重度，不看原始 prompt/response。方向是对的，但关联标识、误报、申诉和客户侧审计仍要等 9 月白皮书。

OpenRouter 将被 Stripe 收购。官方自报每天处理 10T+ tokens、覆盖 400+ 模型、服务 1000 万+ 用户。Stripe 买的不是一个支付客户，而是跨模型推理入口。短期 API 不会立刻变，长期要盯模型排序是否继续中立、支付与推理数据边界、费率和路由政策。

工程侧最有用的提醒来自 Simon Willison：Agent 能把一天 50–200 行生产代码推到约 1,000 行，但人的认知审查能力没跟着涨。瓶颈已从敲代码移到评审和 conceptual integrity；拿 LOC、PR 数或 token 数奖励团队，只会更快造出难维护的软件。

### OpenAI：Zero Data Retention 下做跨交互安全检测

正文日期为 8 月 19 日；上一期采集截止时未收录，本期作为新增发现。

- 现有 ZDR 安全系统逐次检查请求；Private Safety Processing 计划关联多次相关交互，识别跨账号探测、长期有害意图，以及 Agent 在被要求停止后继续行动等模式。
- ZDR 部署中，客户内容留在客户控制的基础设施。另一方案是内容存于 OpenAI，但由客户持有加密密钥；OpenAI 人员没有密钥。
- 自动系统可以处理内容，但 OpenAI 只收到活动类别、严重程度等窄信号，不收到原始提示词和响应。客户可用自己系统中的信息调查告警，并自主决定是否向 OpenAI 分享内容。
- 当前处于早期客户测试，计划 9 月开始推出并发布技术白皮书。
- 法定例外：疑似 CSAM 图片仍会被保留、人工检查和报告。

判断：这是企业 AI 隐私控制面的实质更新，不是普通 ZDR 营销。真正决定能否用于金融、医疗和内部知识库的，是白皮书是否讲清跨会话关联键、密钥吊销、告警证据、误报申诉和可审计性。

原文：[Offering Zero Data Retention for frontier models](https://openai.com/index/offering-zero-data-retention-for-frontier-models)

### OpenAI：Replit 用 Luna 常驻、Sol 按需升级

Replit 推出由 GPT-5.6 Luna 驱动的 Free Mode，不消耗用户 usage；Agent 保留完整项目上下文，需要更强推理时路由到 GPT-5.6 Sol，再返回 Luna。正文只说面向数百万用户，没有给限额、延迟、成本或任务成功率。

## 顶级博主

### Simon Willison：代码生成变快，认知审查没变快

Simon 估计传统工程师普通一天交付约 50–60 行生产代码，极好的一天约 200 行；熟练使用 Agent 后可到约 1,000 行已调试代码。他称自己的生成速度可能提高 100 倍，但没有能力持续理解 100 倍的代码。

功能从“一周”降到“一小时”后，原本由时间成本强制执行的克制消失。系统会像不断加房间的 Winchester Mystery House：每个局部功能都能跑，整体 conceptual integrity 逐渐崩掉。

判断：这些数字是个人经验，不是 benchmark；结论却很实用。团队应给变更预算、架构一致性检查和删除代码留位置，指标看已审查变更、缺陷、返工和维护成本，不能奖励 LOC。

原文：[Conceptual integrity and counting lines of code](https://simonwillison.net/2026/Aug/19/conceptual-integrity-and-counting-lines-of-code/)

### Simon Willison：Agent 自动换到有 KVM 的 CI 验证 sandbox

Simon 让 Claude Fable 5 测试 smolvm 是否能安全执行不可信 Python/JavaScript，包括 CPU/RAM 限制、禁网、文件白名单和无限循环防护。Claude Code Web 环境没有 `/dev/kvm`，Agent 随后创建 GitHub Actions workflow，在暴露 KVM 的 runner 上继续测试。

判断：亮点是 Agent 能识别验证环境不满足前提并自动换路，不是 smolvm 已获安全背书。GitHub Actions 能跑测试，不代表逃逸、侧信道和资源耗尽已被证明安全。

原文：[smolmachines / smolvm as a sandbox](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/)

### Unsloth Dynamic 3.0 GGUF — 296 points

首发 Qwen3.8-27B 后训练量化，兼容 llama.cpp。项目方称 9.83GB 的 `UD-Q2_K_XL` 相比下一名 top-1% accuracy 高约 8%；6.2GB 的 `UD-IQ1_S` 保留约 72% top-1% accuracy，体积缩小 89%。方法用新 imatrix 校准集和逐层量化选择，并用额外 300 个任务比较 32-token greedy 轨迹。

判断：10GB 档本地模型很实用，但 top-1% accuracy、KL 和短轨迹不等于长程 Agent 成功率。上线前必须测目标硬件吞吐、峰值内存、长上下文、tool-call schema 和自有任务回归；数字均为厂商自测。

[HN](https://news.ycombinator.com/item?id=49365443)｜[原文](https://unsloth.ai/docs/basics/dynamic-3.0-ggufs)

### Ornith-1.5：自动造题、造 harness、做 rollout — 200 points

发布 397B MoE、35B MoE（每 token 激活 3B）和 9B dense。RL 闭环共同生成任务、scaffold/harness 与 rollout，再以 validity × frontier difficulty × novelty 奖励及 GRPO 优化；目标成功率 `p*=0.2`。发布方称五次运行均值中，397B 在 Terminal-Bench 2.1/DeepSWE 得 86.1/56.0，9B 在 SWE-bench Verified 得 70.6。

判断：“自我改进”发生在受控训练流程，不是线上模型自主持续学习。可迁移价值是 curriculum 工程；风险仍是生成 harness 的奖励保真和 reward hacking，跨模型分数不能脱离模板、裁判和防作弊条件比较。

[HN](https://news.ycombinator.com/item?id=49362401)｜[原文](https://ornith.ai/ornith_1_5.html)

### AI 数学开始补 provenance 供应链

Terence Tao 的 12 页文章主张，AI 数学不能只数解题成功，还要验证、清晰表达、来源归因、社区接受和进入规范理论。文中引用 First Proof 第二批：10 个未公开研究题中，4 套系统至少一套在 7/10 题通过，单题计算成本数十至数百美元。

Palomar 则登记固定 Git commit 的 Lean 形式化，用 Lean kernel 与独立 NanoDa kernel 重放，隔离 statement/solution、限制额外公理。它明确没有人工同行评审，也不保证创新性、重要性或形式陈述符合自然语言原意。

判断：双 kernel、固定 commit 和版本元数据是靠谱的证明供应链；自然语言到形式陈述的语义对齐仍是薄弱点，不能把 kernel 通过写成“数学结论已全面认证”。

## arXiv

cs.AI、cs.CL、cs.LG `new` 页列表日期均为 8 月 20 日；分别有 67、72、91 篇 new submissions。以下提交时间来自 arXiv API，均为预印本，不等于同行评审。

- [Cacheable by Design?](https://arxiv.org/abs/2608.18261) — 235B Qwen3 Q4_K_M 134GB 在单张 8GB GPU 上暖态仅 0.44 tok/s；locality 训练最多把 cache miss 降 60%，但所有配置都未过“perplexity 恶化≤1%”预注册门槛。训练加 cache-aware rerouting 可降 miss 约 80%，代价≤3.4% perplexity。硬结论：边缘 MoE 先撞 SSD/RAM 带宽，cacheability 不是免费的。
- [FM-Bench](https://arxiv.org/abs/2608.18423) — Agent 管理足球俱乐部 20 个游戏年、26 个工具、约 340–400 个决策点；15 个前沿模型、3 seeds 均跑完，模型规模、价格、厂商和 token 花费都不能预测排名。长期 Agent 评测终于把累积后果和失败记忆放进确定性环境，不再依赖 LLM judge。
- [Efficient INT8 Inference of Small NLP Models](https://arxiv.org/abs/2608.18182) — SmoothQuant 接入 TorchAO，TorchInductor 做图融合并按 oneDNN/AVX512_VNNI/AMX 选 INT8 GEMM；BERT、DistilBERT、XLM-R 端到端吞吐最高 5.8×，实现已 upstream 到 PyTorch/TorchAO。比单独 kernel benchmark 更接近可采用成果。
- [Compress and Forget](https://arxiv.org/abs/2608.18578) — 高干扰下 Qwen INT4 准确率由 81.0% 降到 68.3%；INT8 在 3 个模型中的 2 个也有较小真实损失。量化验收必须加入覆盖/改写式记忆干扰测试，综合榜不掉分不代表长上下文安全。
- [Institutional Newspapers Pipeline](https://arxiv.org/abs/2608.18972) — 工作站级流水线处理 1,473,635 张 1795–1930 年公版报纸扫描，得到 83.1M crops、16.3B o200k_base tokens，并开放 pipeline、模型和数据。工程价值在分阶段可解释与可复用，仍需按年代和版式抽样核 OCR 误差。
- [FlashAttention for Scalable Vector Architectures](https://arxiv.org/abs/2608.18656) — 已集成 ggml/llama.cpp；gem5 模拟中 512-bit VL prefill 相对 scalar 快 22×–42×，decode 快 8×–11×。论文同时指出 Q8_0 linear layer 会接管瓶颈；模拟数字与真实硬件结果必须分开看。
- [GEAR](https://arxiv.org/abs/2608.18849) — 先用 synthetic covariates 扩 teacher query 覆盖，再用真实标签和 out-of-fold 预测重锚定；二分类 AUC 增 1.81–2.00 points，中位 CPU 推理时间降 57×–2866×。可迁移点是“扩覆盖”和“回真实分布”分阶段，不是简单堆 synthetic data。
- [Learned, Then Lost](https://arxiv.org/abs/2608.19168) — 训练 32 个 GPT-2 124M，仅替换一行 batch 注入 194-token 段落。50 步后 8/8 seeds 显示短期学会，训练结束行为差异不可检测，但权重位移仍达 seed-to-seed 欧氏距离的 44.1%。对数据归因和遗忘讨论是少见的真实双训练 counterfactual。
