## 今日判断

今天最该看的不是模型榜单，而是 Agent 的控制面。Simon 对 ChatGPT Work 的实测把能力和风险放在了一张图上：无头浏览器、联网代码执行、持久文件、子代理和定时任务集中到一个产品后，它就同时满足“私有数据、不可信输入、对外通信”三项提示注入条件。功能越完整，越不能把审批分类器当安全边界。

Claude Code Opus 5 Auto Mode 的攻击复现给出了同一结论：恶意网页经 ZIP 和 Python 模块遮蔽诱导 Agent 执行 decoder，小样本成功率 60–80%。数字不能外推，但攻击链够具体。抓网页的 coding agent 应无凭据、隔离运行、限制出网和 import path；审批弹窗只是辅助。

论文里真正可迁移的两条也都在控制面：CURA 用只读 harness 遥测做在线失败预警；OBPE 把 Agent 权限从 prompt 搬到可信工具边界。前者解决“它失败了却说成功”，后者解决“模型是否愿意守规矩”。这比继续堆一层 system prompt 靠谱。

### Simon Willison：Understanding ChatGPT Work

Simon 实测的是 ChatGPT Work 云端版。该功能只向 20 美元/月及以上订阅者开放，Free 和 8 美元/月 Go 不可用；相比普通 Chat，它增加联网代码执行、完整无头 Chrome、跨会话持久文件系统、网站部署、子代理和定时任务。Simon 从环境中枚举出 223 个工具，其中 6 个来自个人 MCP，另发现 44 个 Skills。

判断：这不是 OpenAI 的稳定接口承诺，而是一次有数字、有边界的黑盒工程拆解。Work 同时持有私有数据、读取不可信内容并可对外通信，正好构成 Simon 所说的提示注入“致命三要素”。生产使用要按高权限执行环境治理，不是按聊天窗口治理。

### CURA：Computer-Use Agent 运行时告警

[CURA: Certified Runtime Alarms for Computer-Use Agents](https://arxiv.org/abs/2608.27808)（cs.AI）。361 个 OSWorld 任务中，71 次失败有 64 次（90%）仍声称成功。CURA 在 α=0.10 时检测 42.3% 失败，中位提前 31 步，误报率 0.066；告警触发监督后完整完成率为 84.5%（305/361）。

判断：只读 harness 遥测、无额外 LLM 调用，容易迁移到浏览器代理、RPA 和桌面自动化。离线 AUROC 相比 token 基线优势不显著（Δ=+0.026，p=0.101），真正价值是在线预警和明确的误报预算。

### OBPE：在可信工具边界执行权限政策

[If Agents Were Angels...: Out-of-Band Policy Enforcement at a Trusted Tool Boundary](https://arxiv.org/abs/2608.27646)（cs.AI）。在 Jira、ServiceNow mock、4 个模型和 20 个自适应红队任务上共 3,621 次试验，trace failure 从 57.6% 降至 0.2%；safe-useful completion 提升 21.8 个百分点，但任务 fulfillment 从 79.1% 降到 60.9%。

判断：typed operation/resource 授权、查询收窄和字段过滤把治理从 prompt 搬到可信工具边界，方向对。代价是完成率下降，写操作、持久审批和时序政策仍未覆盖。

### DAMP：混合精度 recurrent-state 量化

[DAMP: Decay-Aware Mixed-Precision Recurrent-State Quantization](https://arxiv.org/abs/2608.27513)（cs.LG）。在 Qwen3.6-35B、Kimi-Linear-48B 和 6 个基准上，以平均 9.9 bit/state value 接近 FP32 准确率；recurrent-state 存储减少 69.1%，更新 kernel 最快 2.01×，整模 TPOT 最多下降 10.9%。

判断：按误差能量与衰减持久性保留少数高风险通道，比全层统一量化更合理；目前只验证 GDN/KDA recurrent state，不能外推到普通 Transformer KV cache。

### 扩散 LM 的轨迹级投机解码

[Trajectory-Level Speculative Decoding for Diffusion Language Models](https://arxiv.org/abs/2608.27514)（cs.CL）。去噪迭代减少 30–40%，tokens/step 从 2.6 升到 4.3；相对 vanilla dLLM 加速 7–14×，相对 Fast-dLLM 1.3×，准确率变化小于 1%。

判断：方法具体，但只在 dLLM 路线成立时有系统价值；对现有自回归 serving 栈帮助有限。

### FinExam-10K：RAG 应按需调用

[FinExam-10K: When Retrieval Helps Financial Reasoning?](https://arxiv.org/abs/2608.28155)（cs.CL）。数据集含 10,198 道 CFA/FRM 题；门控器只对 7.9% 的 held-out 问题调用 FunctionGraph-RAG，把准确率从 70.83% 提到 71.23%（p=.0446）。

判断：真正有用的是“检索条件触发”，不是把 RAG 默认常开。净增益只有 0.40 个百分点，别拿显著性包装成大提升。

## 工程清单

- 抓取网页或处理附件的 coding agent：容器/VM 隔离、无凭据、默认限制出网、固定 import path；审批分类器不能替代这些边界。
- Agent 失败检测放到 harness 遥测层；权限策略放到 typed tool boundary。不要继续靠更长的 system prompt 堆治理。
- RAG 增加调用成本且可能推翻正确答案，应先做 gate 和 no-RAG 基线，再决定是否检索。
