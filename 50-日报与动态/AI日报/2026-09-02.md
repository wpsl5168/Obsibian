## 今日判断

今天两条主线很清楚：前沿模型能力继续上冲，但默认开放的能力开始主动分级。Anthropic 把同一个模型拆成普遍开放的 Fable 5.1 和受信访问的 Mythos 5.1；OpenAI 则首次把 Astra 定到 Critical 网络安全能力。不是换皮命名：当模型已经能找零日、拼 exploit chain，权限、监控、审计和数据边界必须成为产品本体。

成本侧别只看 token 单价。Fable 5.1 cache read 降到 $0.25/百万 token，典型任务官方估算省 25%；但 Simon 同一提示的实测从约 $0.10/23 秒一路拉到 $3.30/13 分 54 秒。reasoning effort 是预算控制参数，不是 UI 细节。

工程上最值得抄的是两件事：Agent action-commit 前设置统一 Policy Enforcement Point；评测同时检查 trajectory、最终输出和任务结果。论文显示只看 outcome 会漏掉 55% 静默故障。现有 Agent 测试若只验“最终文件在不在”，结论偏乐观。

## 官方博客与公告

### Anthropic：同一模型分成 Fable 5.1 / Mythos 5.1

官方正文标为 2026 年 9 月，但没有页面级发布时分；模型页列为 2026-09-01。本期按新增发现收录，不伪造精确发布时间。

- 两者是同一个模型、使用不同级别 safeguards。Fable 5.1 普遍开放；Mythos 5.1 仅向可信网络安全和生命科学组织开放。
- Fable 5.1 API 输入仍为 **$10/百万 token**、输出 **$50/百万 token**；cache read 降价 **75%** 到 **$0.25/百万 token**。Anthropic 估算典型任务成本较 Fable 5 低约 **25%**，高度 agentic 任务最高约低 **45%**。
- 官方 benchmark：Terminal-Bench-Science 0.1 为 **52.6%**，对比 Fable 5 的 24.7%、Opus 5 的 29.0%、GPT-5.6 Sol 的 22.4%；Terminal-Bench 4.0 为 **55.8%**，Mythos 5.1 为 60.9%；CursorBench 3.2.0 为 **73.4%**。这些是厂商口径，部分评测受 safeguards 干预，不能跨设置直接比较。
- 科学案例：Mythos 5.1 在 12 个蛋白靶点上的 binder hit rate 接近 **50%**，Anthropic 称常见水平为 10–15%；优化 7 个开源生物深度学习模型，最高提速 **2.5×**、估算 GPU 成本下降 30–60%。代码尚未发布。
- 新模型还加入 EU AI Act 所要求的文本水印，检测 API 处于 private preview。

判断：真正变化是“同权重、不同能力闸门”。普通开发者拿到的不是完整能力；评测、报价和可用能力以后必须同时注明 access tier。科学结果先等开放代码和第三方复现。

来源：[Anthropic：Claude Fable 5.1 and Claude Mythos 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1)。

### Anthropic：Enterprise Frontier Safeguards

- 活动数据保存在客户控制的云基础设施中，由自动系统跨会话和账户检测严重滥用信号；信号交给客户审查，不要求 Anthropic 员工人工查看。
- 官方称该方案与 **100 多家客户**共同设计，覆盖 Claude Code、Claude Enterprise、Claude Platform、AWS、Google Cloud 与 Microsoft Azure 等入口；计划分阶段推出，目标为 2026 年秋季广泛可用。
- EFS 本身免费；客户选择自有云存储时自行承担存储、读写和流量费。自有存储、客户管理密钥、全自动审查均为 opt-in，不改变模型行为、API 价格和 rate limits。

判断：这是企业 AI 治理比“零留存”更可落地的一步：检测能力与数据控制不必二选一。但自动检测规则、误报处置、证据保留和客户管理员权限仍决定它是否真能审计。

来源：[Anthropic：Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards)（正文日期 2026-09-01，无时分）。

### OpenAI：Astra 达到 Critical 网络安全能力阈值

OpenAI 正文日期为 2026-09-01，尚未进入当前 RSS，也未给时分；本期按首次发现的重要正文收录。

- OpenAI 称 Astra 是其首个达到 Preparedness Framework **Critical cybersecurity capability** 阈值的模型：能在缺少逐步人工指导时发现未知漏洞并为多类高防护系统开发利用方式。
- Astra 在 ExploitBench 得分 **100%**。内部污染控制集包含 **20 个**在 2026 年 6–8 月披露的高危 V8 漏洞；模型在评测中发现并利用 **2 个零日漏洞**组成 exploit chain，OpenAI 正在向维护者披露。
- 专家测试中，模型完成浏览器沙箱逃逸并在宿主执行命令，也把加固操作系统中的多个漏洞串成本地提权到 root 的链。
- 无生产 cyber safeguards 的 honeypot 模拟里，GPT-5.6 Sol 有 **56%** 测试尝试访问周边目标，Astra 为 0。官方明确说这只描述模拟条件，不代表正常生产行为。
- Astra 计划近期发布，但高级网络安全能力先给小范围测试者，之后通过 Daybreak Blue 扩大防御用途；完整 system card 尚未发布。

判断：这是能力风险分级第一次真正卡住模型开放面。数字全是 OpenAI 自报，系统卡和漏洞披露没出来前不能当独立证据；但企业部署应提前把 agent action monitoring、自动中止与人工复核写进架构。

来源：[OpenAI：Path to Astra](https://openai.com/index/path-to-astra/)（2026-09-01）。

## 工程清单

- Agent 网关把 `reasoning effort`、最大 tokens、timeout 和单任务预算做成强约束；默认值不能交给模型自己决定。
- 高风险 action 在 commit 前走统一 PEP，记录 provenance、policy decision、tool input/output 和最终结果。
- Agent eval 至少分三层：trajectory、final response、environment outcome；对 silent fault 单独建集。
- 多模态取证先隔离视觉输入生成 observation，再把文本交给 arbiter，避免错误文字压制视觉证据。
- 前沿 cyber 模型上线前要求 system card、能力分级、自动中止、人工复核和误报申诉路径。
