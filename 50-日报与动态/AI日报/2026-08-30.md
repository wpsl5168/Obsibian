## 今日判断

今天最有价值的不是新模型跑分，而是 Debian 给 AI 代码划了条清楚的责任线：生成式 AI 输出不能直接作为 Debian 贡献，但允许用于探索、研究、分析和批评。这个边界比“全面拥抱”或“全面禁用”都实用——工具能用，作者责任不能外包。

Hy4 Preview 的 770B/49B MoE、1M 上下文和 1.56TB 权重说明大模型的开放权重继续向超大规模走，但这类模型对绝大多数团队只是 API 商品，不是可部署资产。腾讯自报工程盲测和吞吐提升可作为候选信号，不能当独立结论。

vLLM 0.28.0 才是今天更直接的工程更新：分层 KV cache 磁盘 offload、Rust frontend/gRPC、Kimi-K3 内核与显存优化一起进来，但依赖升级和插件拆分也带来破坏性变更。生产环境先做固定模型、固定硬件的回归，别看版本号就滚动升级。

## 顶级博主

### Simon Willison：Hy4 Preview 的规模比“开放”更值得警惕

Simon 记录腾讯 Hy4 Preview：纯文本 MoE，770B 总参数、49B 激活参数、1M token 上下文，Hugging Face 权重约 1.56TB；前代 Hy3 为 295B/21B、256K 上下文、约 598GB。模型模板显示两档推理强度：默认 `high` 与 `no_think`。

判断：权重可下载不等于普通团队能运营。1.56TB 只是权重体积，实际推理还要算 KV cache、并行通信、量化损失和 serving 软件适配。工程评估应先按 API 模型看待，除非已有对应集群和长期利用率。

来源：[Simon Willison](https://simonwillison.net/2026/Aug/29/hy4/)；[腾讯发布页](https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/)；[Hugging Face](https://huggingface.co/tencent/Hy4-preview)。Simon 发布于 2026-08-29 23:53 UTC，即 2026-08-30 07:53 CST。

## 工程清单

- AI 辅助贡献的落地规则可直接借 Debian 的边界：允许研究分析，禁止未审查生成物直接进入交付；提交者对版权、测试和正确性全责。
- vLLM 0.28.0 升级先锁一组真实模型做 TTFT、TPOT、吞吐、显存、KV offload、量化和 tool-call 回归，特别检查 Transformers 5.15.0 与 bitsandbytes 插件迁移。
- 超大开放权重模型先算完整 TCO：权重、KV cache、互联、冗余、利用率和运维人力；别拿“可下载”替代“可部署”。
