## 今日判断

今天最硬的东西不是新模型，而是 Anthropic 把 Fermat's Last Theorem 的 Lean 形式化产物公开了：最终证明使用 29,500 余个中间定理，可由 Lean kernel、comparator 和独立 Rust kernel nanoda 三路检查。这不是 Claude 发明了新的数学证明；它把既有数学论证和人类开源 Lean 工作扩成一份端到端、机器可检查的工程制品。真正变化是验证成本结构：生成仍然昂贵，但正确性不再只能靠读自然语言和信厂商截图。

第二条工程线更朴素：Spotify 用 hook 强制把大文件读取和样板生成转给便宜模型，在一个 Java monorepo 的四类任务里，把 Claude 消耗的 bulk-read token 平均压低约 90%。这不是总成本下降 90%，更不能把 debugging 和编辑一起外包；但“路由规则必须由 hook 执行，不能只写进 CLAUDE.md”是可直接抄的做法。

## 官方博客与公告

### Anthropic：Claude 完成 Fermat's Last Theorem 的 Lean 形式化

Anthropic 官方正文称，Claude 在约 11 天内、主要自主运行，生成约 1,300 万行 Lean，过程中证明 30,300 个定理，最终证明使用其中 29,500 个；多 Agent harness 消耗约 60 亿 output tokens，内部研究模型能力约等于 Claude Fable 5.1。工作通过 Prove2Me 协作平台组织，早期失败尝试约占最终非样板代码的 7%。人类输入主要是少量高层数学方向。

边界必须写清：

- 这项工作形式化的是 Wiles/Taylor-Wiles 路线的简化版本，不是发现一份新的 FLT 数学证明。
- 产物复用了 Imperial College London FLT、`flt-regular` 和 Mathlib 等人类开源成果；仓库用 `ATTRIBUTION.md` 标注来源。
- Anthropic 的正文页面在本次抽取中没有展示 Published 日期，本期因 HN 新增高热讨论和公开仓库上线而收录，不补造发布日期。

公开仓库提供的可核信息：

- 默认构建目标 `FinalCheck.lean` 限定只依赖 Lean 的三个标准公理：`propext`、`Classical.choice`、`Quot.sound`，并禁止 `sorry`、新增 `axiom`、`native_decide` 等逃逸手段。
- 从头构建共检查 60,475 个模块。官方复现记录为 96 jobs 下约 5 小时 32 分钟、峰值 153 GB 内存；单个并行 job 约需 5 GB，个别模块最高约 36 GB。
- `leanprover/comparator` 重放约 14 小时 46 分钟，峰值 230 GB；独立 Rust kernel `nanoda` 检查 1,052,234 个 declarations，无错误。
- HTML 离线浏览产物约 390 MB，覆盖 29,511 个 theorem 页面和 1,450 个 definition module。
- 仓库明确标注为 research artifact，不维护、不接受贡献，Apache-2.0。

判断：这事的价值不是“AI 解决了 FLT”，而是证明生成和证明核验第一次被拆得足够干净。可信边界仍包括 Lean/nanoda kernel、依赖和定理陈述是否对应人类想表达的数学；但这比让专家逐页审 AI 长文可靠得多。代价也不小，当前完整复现需要数百 GB 级内存与磁盘，不是个人电脑点一下就能验。

来源：[Anthropic：Formalizing Fermat's Last Theorem](https://www.anthropic.com/research/formalizing-fermats-last-theorem)；[公开 Lean 仓库](https://github.com/anthropics/fermats-last-theorem)。

OpenAI、Google DeepMind、Meta AI、Microsoft Research 在本窗口未发现相对上一期可核的新正文。Meta 的 Muse Voice Transcribe 页面提供 80 ms 音频块、训练覆盖 70+ 语言等信息，但页面未显示可核发布日期，暂不冒充今日新品。Andrej Karpathy、Lilian Weng、Chip Huyen 无新增正文。

### Spotify：把低推理任务从 Claude Code 分流

[Portal by Spotify cut my Claude Code token usage by 90%](https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90) — **168 points**。

作者用 Portal AiKA Modes 把大文件读取和样板代码交给 Gemini 2.5 Flash。关键不在“多模型”本身，而在三层约束：PreToolUse hook 在文件超过默认 350 行时阻断整文件读取；脚本封装一次性调用；skill 告诉 Agent 何时使用。Java monorepo 四类场景中，bulk-read 让 Claude 消耗的 token 平均减少约 90%。

限制同样明确：不能可靠委派编辑；便宜模型漏掉过一个 thread-safety bug；每次转发增加约 10–30 秒，Portal 单次调用上限 30 秒。判断：标题说的是 Claude 侧读取 token，不是端到端成本或所有任务 token。适合大文件粗读和模板生成，debugging、架构、安全代码仍应留给主模型。

### EEBench：用可执行约束测 AI 电路设计

[Can AI design circuit boards yet?](https://eebench.org/blog/can-ai-design-circuit-boards-yet/) — **283 points**。

EEBench V1 有 13 个任务，用确定性构建、BOM、SPICE 仿真和容差角检查电路，不靠看图打分。9 月 1 日榜单中 Claude Opus 5 为 61.6%，Grok 4.6 为 57.1%，Claude Fable 5.1 为 56.4%；尚无 GPT-6 Astra 结果。一个保持供电任务里，模型选的 22 µF 电容在 4.7 V 偏压下实际只剩 11.4 µF，远低于 545 µF 要求，供电 0.85 ms 后跌破 3 V——源码能构建，但电路没完成任务。

判断：这类 benchmark 比“在 KiCad 里点得像不像人”靠谱，因为 reward 来自电气行为。局限是目前只到模拟、器件选择和成本约束，还没覆盖 PCB layout、制造和实物 bring-up；榜单由 atopile 团队建设和出资。

## arXiv

9 月 5 日是周六，cs.AI / cs.CL / cs.LG 当前 `new` 页面均显示 **Friday, 4 September 2026**。以下“submitted”是论文首投日期，不是列表日期；修订稿单独标注。均为预印本，数字来自作者摘要，未独立复现。

- [Speculative Macro Commit for Faster Tool-Using Agents](https://arxiv.org/abs/2609.03236)（cs.AI；submitted 2026-09-03）。作者称相对顺序执行，τ²-Bench Telecom 延迟降低 18.59%，AppWorld 墙钟时间降低 44.9%；相对已有 Speculative Actions 再降 10.23% / 7.7%。把推测执行从单动作扩到动作宏，适合工具 Agent；AppWorld 任务完成率有轻微下降，不能只报速度。
- [Jina-OCR-v1](https://arxiv.org/abs/2609.03181)（cs.CL/cs.CV；submitted 2026-09-02）。3B MoE、每 token 激活约 570M 参数；OmniDocBench v1.6 为 91.14，olmOCR-Bench 为 83.4，吞吐 2.57 页/秒；NVIDIA L4 上推测解码约 2×。共享递归 draft block、无损验证和针对公式/表格/结构的可验证奖励值得复现。
- [MemoryLACE](https://arxiv.org/abs/2609.03201)（cs.CL/cs.LG；submitted 2026-09-02）。在 BEAM 上相对 Hindsight 端到端时间降低 66.6%。用稀疏的合并、取代、矛盾关系代替全局知识图谱，适合长期 Agent memory；生产持续写入成本和关系误判仍未知。
- [Activation-Keyed Momentum](https://arxiv.org/abs/2608.19491)（cs.LG/cs.CL；v2 updated 2026-09-03）。额外计算约为 gated-MLP 线性层的 22.2%–25.0%，无持久额外内存；达到 AdamW 同等验证损失所需步数，67M 模型最多减少 46.39±4.32%，370M 减少 22.12±0.80%，实验延伸到 1B。迁移门槛不高，但额外算力不能忽略。
- [Puro-2B](https://arxiv.org/abs/2608.27370)（cs.CL/cs.LG；v2 updated 2026-09-03）。作者在 RTX 5090 上以 FP8 训练最多 1.4T tokens，最佳模型训练计算成本低于 $6.9K；拟合成本律估算约 $4.4K 可达到其评测口径下的 Qwen2-1.5B 水平。数据、代码、权重和配方公开，适合小团队复现；成本和“接近 Qwen”都依赖作者计价与评测口径。

分类页：[cs.AI](https://arxiv.org/list/cs.AI/new)；[cs.CL](https://arxiv.org/list/cs.CL/new)；[cs.LG](https://arxiv.org/list/cs.LG/new)。

## 工程清单

- 把 Agent model routing 做成 hook/policy 层的强制规则；只写进提示词属于建议，不是控制。
- 形式化证明和安全关键代码都要拆开“生成器”和“验证器”，验证器尽量使用不同实现、固定版本和可重放输入。
- 硬件 Agent 评测优先用仿真、容差角、BOM 和成本约束，不用 GUI 操作完成度代替工程正确性。
- 长期 memory 优化先测持续写入、矛盾关系误判和端到端延迟；同一 backbone 的离线 benchmark 第一名不等于生产稳定。
