## 头条: OpenAI GPT-5.6 正式 GA

**官方发布:**
- 时间: 2026-07-09 北京时间
- 博文: https://openai.com/index/gpt-5-6
- System Card: https://deploymentsafety.openai.com/gpt-5-6/gpt-5-6.pdf
- API 文档: https://developers.openai.com/api/docs/guides/latest-model

**三个型号:**
1. **GPT-5.6 Sol** (最强旗舰): $5/M input, $30/M output
2. **GPT-5.6 Terra** (日常均衡): $2.5/M input, $15/M output
3. **GPT-5.6 Luna** (经济型): $1/M input, $6/M output

**定价对比:**
- Claude Opus 4.8: $5/$25
- Claude Fable 5: $10/$50
- GPT-5.6 Sol: $5/$30

**核心 benchmark 声明:**

### Agents' Last Exam (长期专业工作流, 55 领域)
- GPT-5.6 Sol: **53.6** (新高)
- Claude Fable 5 (adaptive reasoning): 40.5
- 领先 13.1 分,且成本约 1/4

### SWE-Bench Pro (代码补丁质量)
- Claude Fable 5: **80%**
- GPT-5.6 Sol: 64.6%
- OpenAI 前一天(7月8日)专门发文质疑该 benchmark 约 30% 的任务是 broken,暗示成绩不可信 (https://openai.com/index/separating-signal-from-noise-coding-evaluations/)

### Artificial Analysis Intelligence Index
- GPT-5.6 Sol (max reasoning): 与 Fable 5 只差 1 分
- 完成时间少 39% (耗时 61% 的时间)
- 成本约一半

**新 API 特性:**
1. **Programmatic Tool Calling** — 模型在一轮内用 JS 编排多个 tool call (类似 Anthropic 的 dynamic filtering)
2. **Multi-agent** — 原生子 agent 并行
3. **Prompt cache breakpoints** — 手动指定缓存切分点(类似 Claude,但 OpenAI 仍支持自动检测)
4. **detail: original** — 图片不再自动缩放

**社区反应 (Hacker News #48849066, 1380 分, 953 评论):**
- 共识: Fable 在复杂 coding 任务上代码质量更好,但 GPT-5.6 Sol 在多步 workflow 性能强,价格实惠
- 分歧: SWE-Bench Pro 争议大,OpenAI 称其 30% broken,Anthropic 未回应
- 工程师选型趋势:
  - Opus 4.8 日常主力
  - Codex (GPT-5.2 Codex) 代码 review (pedantic)
  - Fable 5 难题+高层设计
  - GPT-5.6 Terra/Luna 性价比高,适合批量任务

**Simon Willison 一手体验 (https://simonwillison.net/2026/Jul/9/gpt-5-6):**
> "提前试用了 Sol,确实能干,但在我测的复杂 coding 场景里,没觉得比 Fable 强。"
> "最有趣的是 Programmatic Tool Calling,有可能弥补 MCP 和完整 terminal session 之间的鸿沟。"
> "18 张 pelican 骑车图:无推理最便宜 0.71 美分(Luna),max 推理最贵 48.55 美分(Sol)。"

**我的判断:**
- OpenAI 在 long-running agentic workflow 上确实有进步,Agents' Last Exam 领先幅度大
- SWE-Bench Pro 数字战是 PR 战,OpenAI 发文质疑 benchmark 的时机(Fable 碾压的前一天)太巧合,工程可信度存疑
- 真正值得关注的是 **Programmatic Tool Calling** — 如果模型能在一轮内编排多 tool,减少往返,这对 MCP 生态是补强
- **定价**: Luna/Terra 性价比高,适合跑批量任务;Sol 不如直接用 Fable,除非你真的在跑 55 领域的 multi-hour workflow
- **选型建议不变**: Fable 适合写代码 + 复杂推理,GPT-5.6 适合批量 + 中等复杂度 workflow,成本敏感场景用 Terra/Luna

## 总结与判断

### 本日核心事件
OpenAI GPT-5.6 正式 GA,三型号覆盖高/中/低成本场景,主打 long-running agentic workflow,在 Agents' Last Exam 上大幅领先 Fable,但在 SWE-Bench Pro 上落后,且 OpenAI 提前一天质疑该 benchmark 的可信度,存在 PR 战嫌疑。

### 工程选型建议
- **复杂代码 / 高质量输出**: Claude Fable 5 / Opus 4.8 仍是首选
- **批量任务 / 中等复杂度 workflow**: GPT-5.6 Terra/Luna 性价比高
- **多步 agent 编排**: GPT-5.6 Sol 的 Programmatic Tool Calling 值得试
- **成本敏感**: Grok 4.5 ($2/$6) 可关注,但需验证实际质量

### 技术趋势
1. **Benchmark 可信度危机**: OpenAI 质疑 SWE-Bench Pro,Anthropic 未回应,社区开始怀疑厂商自报成绩
2. **Agent 编排能力内卷**: 从多轮对话 → 单轮内 JS 编排 tool (OpenAI) / dynamic filtering (Anthropic),减少往返开销
3. **本地大模型可行性**: MoE + int4 量化在 32GB 消费级硬件上跑 744B 模型,虽然慢但能用

### 值得深挖的方向
- Programmatic Tool Calling API 实际效果,能否替代部分 shell script 编排
- arXiv:2607.08028 企业 Agent 合约工程,适合生产化 Agent 系统
- sqlite-utils 4.0 by Fable 的成本实例($149),可作为"AI 写库"成本基准
