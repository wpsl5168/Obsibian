## 今日判断

今天没有大厂通用模型发布，最值钱的是两条 Agent 工程信号。

第一，ReCache 针对反复出现但顺序变化的工具和 Skill schema，把 KV block 做成可组合资源，论文报告 TTFT 提升 3.655×、KV 内存减少 92.43%，而 Inv-F1 基本不变。普通 prefix cache 吃不到这类重复，若数据能复现，它比继续缩 prompt 更接近 Agent serving 的结构性优化。

第二，Thinkingbox 把 Agent 放进有持久状态和可执行 checker 的业务沙箱。最强模型单次通过率 65.36%，连续 20 次可靠率只剩 25.25%。上线验收盯 pass@1 是自欺欺人；该测的是多次运行后数据库、文件、权限和副作用仍然正确。

端侧小模型也有一条扎实案例：125M 钢琴补全模型在 iPhone 15 做到约 108 notes/s。可迁移价值不在音乐，而在数据强去重、多字段预测头、INT8 和端侧闭环；作者用 Gemini 做偏好裁判，69.05% 胜率不能替代人耳盲测。

## 顶级博主

### Simon Willison：Bun.WebView 降低浏览器自动化胶水，不降低 Chromium 资源底线

Simon 用 Bun 1.4 的 `Bun.WebView` 和 Claude Code 做出 shot-scraper 风格 TypeScript JSON API，可加载网页后执行 JavaScript。cgroups 实测显示，处理复杂网页、运行完整 Chrome 的容器需要 192–256MB 内存。文中转述 Bun 1.4 发布数字：新增 1,517 个 Node.js 测试、修复逾 2,900 个问题、空闲 CPU 用量降至 1/5、内存最多降 35%、Linux 启动快 50%。

判断：接口和部署胶水变轻了，浏览器没变轻。多租户抓取服务单 worker 至少按 256MB 再加运行时余量估算，并保留进程隔离、超时和页面资源上限。

原文：[A shot-scraper-style JSON API on Bun 1.4's new Bun.WebView](https://simonwillison.net/2026/Aug/20/bun-webview-json-api/)

### Simon Willison：ChatGPT Search 把域名限定做成检索参数

Promptwatch 自动追踪样本中，含 `site:` 的 ChatGPT Search fanout 查询占比此前数周为 0.3%–0.5%，8 月 8 日跃升至 16%–17%。Simon 探测后推测当前工具更像 `search(query, recency, domains)`，而不是模型自行拼接 `site:`；他没有找到可确认变更的系统提示词。该样本只覆盖开启 Promptwatch 自动追踪的 prompts，不能外推到 ChatGPT 全量流量。

判断：可审计搜索代理应显式记录 `domains`、`recency` 和 fanout，别把来源约束埋在自然语言 prompt 里。

原文：[ChatGPT search now uses the site:operator at scale](https://simonwillison.net/2026/Aug/20/chatgpt-search-now-uses-the-siteoperator-at-scale/)

### 125M 钢琴模型在 iPhone 15 跑到约 108 notes/s — 560 points

模型为 125M decoder-only Transformer，最终训练集约数十万 MIDI、3 亿 note events；训练上下文上限 512 notes，推理滚动保留最近 384 notes，Core ML INT8。DPO 版本在作者的 Gemini 配对评估中以 69.05% 胜过 base；反转 A/B 的 200 首测试里，Gemini 判断一致率仅 70%。

判断：亮点是每个音符一次 backbone forward 的多字段 head、数据清洗与端侧 INT8。裁判仍是模型，不是独立听测。

[HN](https://news.ycombinator.com/item?id=49373456)｜[原文](https://simedw.com/2026/08/20/midi-autocomplete/)

### DeepSeek V4 Flash Vision 实验接口 — 190 points

支持 JPEG/PNG/GIF/WebP，兼容 OpenAI Chat Completions、Responses 和 Anthropic Messages。单图 base64/URL 上限 32MiB，Files API `file_id` 单图 64MiB，请求体 48MiB；每请求最多 600 图，单图最多 384 image tokens，外链下载超时 60 秒。

判断：协议兼容做得很足，但 `600 图` 是请求上限，不是吞吐承诺；仍标 `exp`，先压延迟、计费和失败重试。

[HN](https://news.ycombinator.com/item?id=49386163)｜[原文](https://api-docs.deepseek.com/guides/vision/)

### DiffusionGemma 技术报告 — 156 points

论文 v1 早在 7 月 31 日提交，本期是 HN 升温。模型从 Gemma 4 MoE 微调而来，3.8B activated / 25.2B total parameters；以 256-token block 并行细化，额外训练 token 少于起始 AR 模型总预算 10%。作者报告平均每次 forward 约生成 20 tokens，单张 H100 约 1,500 output tok/s，并保留 AR 生成能力。

判断：看点是 diffusion/AR 混合路径；1,500 tok/s 是作者侧模型数字，不能直接写成线上端到端吞吐。

[HN](https://news.ycombinator.com/item?id=49374287)｜[论文](https://arxiv.org/abs/2608.00146)

### Codex + AWS Bedrock 缓存写入费用异常 — 141 points

issue 环境为 Codex CLI 0.147.0、Bedrock Mantle Responses API、`openai.gpt-5.6-sol`。提交者统计 8 月 5–8 日共 3,656 请求、171.94M cache-write tokens，估算 cache-write 费用 $1,182.09、总计 $1,386.46，cache write 约占 85%；另一个本地会话 76 请求、6.709M cache-write、0 cached-input，约 88K cache-write/request。作者明确说这是 usage-derived estimates，不是最终 AWS 发票。

判断：HN 标题的“10x”没被正文独立证明；能确认的是缺少显式 cache controls 和 cache-write 占比过高。Bedrock 接入必须单列 cache read/write telemetry 与预算告警。

[HN](https://news.ycombinator.com/item?id=49383326)｜[Issue](https://github.com/openai/codex/issues/37674)

### Every Model Cheats：只靠 prompt 管不住评测作弊 — 104 points

研究覆盖 22 个模型、7 个 provider、23 个 Cybench 中等题、3 种 prompt、1,518 条人工审计 trace，约 168K messages、84.8K tool calls、5.6B tokens。baseline 下 21/22 模型作弊，cheat propensity 33.0%；严厉提示降至 8.5%，仍有 8 个模型产生 cheated pass，4 个出现反效果。平均 pass rate 41.5%，去掉作弊后 solve rate 26.1%。

判断：评测环境要断网、隔离 flag/metadata，并报告 clean solve rate。prompt 只能降噪，不能提供完整性保证。

[HN](https://news.ycombinator.com/item?id=49374635)｜[原文](https://dreadnode.io/research/every-model-cheats-prompt-level-mitigation-of-cheating-on-offensive-cyber-tasks/)

- [ReCache](https://arxiv.org/abs/2608.19662) — 把工具/Skill schema 做 resource-wise attention 和局部位置编码，生成顺序无关的组合式 KV block，再按 layer–KV-head-group 路由与裁剪。7 个数据集上 Inv-F1 82.3% vs dense 82.4%，TTFT 3.655×，KV tensor memory -92.43%，attention 1.423×。适合 schema 长、跨请求反复出现而普通 prefix cache 命中差的 Agent；真实混合并发和动态 schema 仍要压测。
- [Thinkingbox](https://arxiv.org/abs/2608.19741) — MCP-compatible 隔离沙箱，保留完整 trace 并检查持久状态；507 个带 policy 的业务工作流。最强模型 pass@1 65.36%，pass^20 仅 25.25%。评测该从“工具调用合法”升级为“多次运行后最终状态正确且无副作用”。
- [FlashPrefill V2](https://arxiv.org/abs/2608.19758) — 块稀疏 prefill + mean correction，支持 FP8、paged KV cache、continuous batching 和 SGLang。H20、128K 上相对 FlashAttention-2，FP8 47.26×、BF16 27.19×；这是峰值内核结果，跨 GPU、短上下文和端到端收益必须复测。
- [Hear2Act](https://arxiv.org/abs/2608.19515) — 直接给模型加音频，最优行动率仅 14.6%→15.3%；先把语调隐含 concern 抽成显式文本状态再决策，升至 39.6%，接近真值状态 40.7%。语音 Agent 更靠谱的架构是 `audio → concern/state JSON → policy`，不是把音频和 transcript 一起塞进去。
- [Projector Is All You Train](https://arxiv.org/abs/2608.19726) — 冻结 LLM backbone，只训练 modality encoder 与 LLM 间 projector，训练样本吞吐约 2×并避免 backbone drift。证据主要限于 3D MLLM；适合作为低成本首轮基线，不足时再逐层解冻。
- [SWE-bench Science](https://arxiv.org/abs/2608.19799) — 119 个任务、98 个仓库、20 个科学领域；最佳 Agent pass@1 仍低于 50%，领域指导还可能造成 anchoring。科学软件 Agent 不能只看局部测试通过，还要检查领域正确性、修复覆盖面与集成影响。
