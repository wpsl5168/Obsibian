# AI Daily — 2026-04-21

## 一句话总览
本周「编码 Agent + 模型迭代」双线推进：Anthropic 发布 Claude Opus 4.7（更换 tokenizer，新增 xhigh effort 档），OpenAI 把 Codex 升级为「能用电脑、记忆、跨日续命」的全栈工程师助理，阿里 Qwen3.6-Max-Preview 在 6 项编码 Benchmark 登顶，Moonshot 同步开源 Kimi Vendor Verifier 用以治理第三方推理服务的精度漂移问题。

## 重点事件

### 1. Anthropic Claude Opus 4.7 GA + 首次更换 Tokenizer
- **来源**: [anthropic.com/news/claude-opus-4-7](https://www.anthropic.com/news/claude-opus-4-7) ｜ [Simon Willison 实测](https://simonwillison.net/)
- **发生了什么**: 4/16 Opus 4.7 正式 GA，价格不变（$5/$25），但 tokenizer 升级，相同输入会产生 1.0–1.35× 的 token 数；图像支持长边 2576px（上一代 3 倍），并新增 `xhigh` effort 档（介于 high 与 max 之间），Claude Code 默认值上调到 xhigh。
- **背景**: Opus 4.7 主打长链路工程任务、自我校验、视觉与"品味"输出，逊于内部更强的 Mythos Preview，但显著超过 4.6。Simon Willison 实测系统提示 token 用量为 4.6 的 1.46×，相当于实际涨价 ~40%。
- **分析**: 这是 Anthropic 首次切换 tokenizer，调用方需重做 token 预算与成本回归测试；指令跟随更"字面"，老 prompt 必须复盘；xhigh 档 + Task Budget（公测）显示 Anthropic 在把"算力调度"作为产品旋钮交给开发者，编码场景的真实成本和延迟会比纸面价格更难估算。
- **影响与关注点**:
  1) 凡是接 Anthropic API 的服务，立即新跑一次 token×价格回归，留意月度成本上涨；
  2) Claude Code 默认 xhigh 后端到端时延变长，CI/IDE 集成需要重新测；
  3) 高分辨率视觉对 OCR/UI 截图类任务可能直接替换现有 GPT-4o/Gemini 工作流。

### 2. OpenAI Codex「for (almost) everything」：电脑使用 + 记忆 + 90+ 插件
- **来源**: [openai.com/index/codex-for-almost-everything](https://openai.com/index/codex-for-almost-everything/)
- **发生了什么**: 4/16 Codex 大版本升级——后台 Computer Use（自带光标，多 Agent 在 Mac 上并行不打扰用户），原生浏览器/应用内评论、用 gpt-image-1.5 出设计稿、90+ 插件（Atlassian Rovo、CircleCI、CodeRabbit、GitLab、MS Suite、Render…），跨日 Automations、Memory（preview）、按上下文给出"今日待办"。
- **背景**: Codex 周活已达 3M 开发者；OpenAI 同期发布的 GPT-5.3-Codex 是底层模型；Agents SDK 也在 4/15 出了"下一代"。
- **分析**: 这是 IDE 助理向"工程师同事"的形态跨越——异步、能跨日、能挂插件、能直接操作未上 API 的应用。它压制 Cursor/Windsurf 的方式不是更快补全，而是"我替你跑测试、提 PR、回评论、起草下一周计划"。Memory 进入 Codex 意味着 OpenAI 准备把开发者上下文沉淀在自己侧（迁移成本陡增）。
- **影响与关注点**:
  1) 对照评估自家 Hermes Agent / Claude Code，关注「跨会话续接 + 插件市场」是否需要补；
  2) 警惕长上下文/记忆带来的隐私与代码外泄风险，企业版要等 EU/UK 区可用再大规模铺；
  3) 关注 90+ 插件中是否有可对接 Linear/JIRA/Render 的官方 MCP 路径，省自研。

### 3. 阿里 Qwen3.6-Max-Preview：六项编码 Benchmark 登顶（HN 615）
- **来源**: [qwen.ai/blog](https://qwen.ai/blog?id=qwen3.6-max-preview) ｜ [HN 讨论](https://news.ycombinator.com/)
- **发生了什么**: 4/18 阿里发布 Qwen3.6-Max-Preview，相对 3.6-Plus 在 SkillsBench +9.9、SciCode +6.3、NL2Repo +5.0、Terminal-Bench 2.0 +3.8，宣称在 SWE-bench Pro、Terminal-Bench 2.0、SkillsBench、QwenClawBench、QwenWebBench、SciCode 六项夺冠；提供 OpenAI/Anthropic 兼容 API。
- **背景**: 闭源旗舰路线，承接此前 3.6-Plus；上 HN front page 615 分说明海外开发者在主动评估。
- **分析**: 中国厂商的旗舰闭源模型在编码这一最硬的赛道连续刷榜，意味着「Claude/Codex 不再是唯一选择」的局面已成立；OpenAI/Anthropic 兼容 API 大幅降低迁移成本，多厂商热切换会成为生产实践；但 SWE-bench Pro 等基准的"刷分 vs 真实工程力"差距仍需独立复测。
- **影响与关注点**:
  1) 在 SWE-bench Pro / Terminal-Bench 上跑独立可复现脚本，对比 Claude Opus 4.7 / GPT-5.3-Codex；
  2) 评估 DASHSCOPE 海外节点（Singapore/US-Virginia）的延迟和合规边界；
  3) 把 Qwen 接入现有 Agent，作为成本敏感场景的兜底/分流模型。

### 4. Moonshot Kimi Vendor Verifier：治理"开源模型在第三方 API 上跑歪"
- **来源**: [kimi.com/blog/kimi-vendor-verifier](https://www.kimi.com/blog/kimi-vendor-verifier) ｜ [GitHub MoonshotAI/Kimi-Vendor-Verifier](https://github.com/MoonshotAI/Kimi-Vendor-Verifier)
- **发生了什么**: 随 Kimi K2.5 发布，Moonshot 开源 KVV——六项关键 Benchmark + 与 vLLM/SGLang/KTransformers 上游联调 + 预发布验证 + 公开 vendor 排行榜，专治第三方推理因解码参数误用导致的精度漂移（K2 Thinking 强制 Temp=1.0、TopP=0.95）。
- **背景**: 开源模型在不同 inference provider 上分数差异巨大，已经损害了"开源模型可信度"这件事本身。
- **分析**: 这是开源生态难得务实的一步——把"模型能力"和"工程实现偏差"切开核算；对所有依赖 OpenRouter/Together/Fireworks 等聚合商的产品都是直接利好。范式上，未来旗舰开源模型大概率都会附带各自的 Verifier。
- **影响与关注点**:
  1) 自建/接入 Kimi K2.5 时，先跑 KVV 再上线；
  2) 把 KVV 思路套到 DeepSeek/Qwen 的多供应商比对，建立内部"推理供应商可信度看板"；
  3) 关注 vLLM/SGLang 后续 patch，对自托管模型同样适用。

### 5. Anthropic Claude Design：原生「设计/原型/Slides」产品线
- **来源**: [anthropic.com/news](https://www.anthropic.com/news)（Apr 17）
- **发生了什么**: Anthropic Labs 推出 Claude Design，与 Claude 协作直接产出设计稿、原型、Slides、One-pager。
- **背景**: 与 Opus 4.7 强化「品味/UI 输出」一脉相承；同期 OpenAI Codex 也加入 gpt-image-1.5 设计能力——两家同周对齐进入 Figma/Canva 腹地。
- **分析**: AI 厂商正在系统性蚕食"轻设计"工具品类，传统 SaaS 的 per-seat 模式被 Headless API + Agent 进一步动摇（参 Simon Willison 转述的"Headless everything"趋势）。
- **影响与关注点**:
  1) 内部所有 PPT/海报/原型产线评估是否 swap 到 Claude Design；
  2) 关注 Anthropic 是否同步开放 API（决定能否入 Agent pipeline）。
