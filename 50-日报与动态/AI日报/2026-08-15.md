## 官方博客与公告

### Anthropic：未来 Claude 文本将默认带 SynthID-Text 水印

Anthropic 8 月 14 日宣布，未来 Claude 模型生成的文本将加入 SynthID-Text 变体水印，以满足欧盟 AI Act 的生成内容标记要求；约 190 个签署方已在 2026 年 7 月签署相关透明度实践准则。Anthropic 会全球同步启用，因为目前无法稳定按地区限制。

机制不是插入固定词，而是在多个合理候选词之间，用密钥和前文决定随机选择，使长文本呈现可验证统计模式。官方称不增加 token，速度影响可忽略，价格不变；检测 API 尚未发布，只说“soon”。

边界很明确：短文本、事实性文本、轻度校对和代码可供水印落点的词较少，检测弱；检测结果只能说明 Claude 很可能参与过，不能证明作者身份，也不能识别其他模型。彻底改写仍可移除信号。图片等支持文件则使用 C2PA 元数据，不是文本水印。

**判断**：这是合规基础设施，不是“AI 测谎仪”。真正能否用于审计，要等检测 API 后实测短文本误报、改写鲁棒性、跨语言和版本兼容；拿它判学生作弊风险很大。

原文：[How Claude’s text watermark works](https://www.anthropic.com/news/claude-text-watermark)（2026-08-14）

> “Future Claude models will generate text that contains a watermark.”
>
> “Watermarking has a negligible impact on the speed of models, and because it produces no extra tokens, the model is the same price to serve and use.”

## 顶级博主

### Simon Willison：先让模型“发明分类”，再映射到现有标签

Simon 的博客有 1,856 个标签，把完整词表塞给模型直接分类既贵又容易受长列表干扰。他转述 Doug Turnbull 的办法：先不给现有标签，让 LLM 生成贴合内容的假想标签；再用 embedding 在既有标签库中找最近项。Prompt 只提供标签层级的格式示例，帮助输出贴近现有 taxonomy。

**判断**：这是 HyDE 思路在分类上的变体。适合词表很大、层级复杂、标签持续变化的系统；但 embedding 最近邻不等于业务标签正确，仍要设距离阈值、允许多标签和人工兜底。

原文：[Don’t classify. Hallucinate!](https://simonwillison.net/2026/Aug/14/dont-classify-hallucinate/)（2026-08-14）

> “Tell the model to output tags without any details of the existing vocabulary, then use vector embeddings against the existing corpus to find the concrete tags that are closest to the ones the model imagined might fit!”

## arXiv（8 月 14 日 new list；首次提交 8 月 12–13 日）

8 月 15 日是周六，没有新工作日批次。以下来自 cs.AI / cs.CL / cs.LG 最新列表，均未经同行评审。

### CAKE：给代码 Agent 一个可验证、可演化的 GPU Kernel IR

- [arXiv:2608.12629](https://arxiv.org/abs/2608.12629)，首次提交 2026-08-12。
- CAKE IR 显式表达 warp 角色、内存搬运、同步和 pipeline；重复失败会沉淀为 verifier rule、IR primitive、cost model 与复用优化策略。
- B200、8000 万 token 搜索预算下，最佳 CAKE IR 为调优 FlashML baseline 的 1.144×；直接生成 CUDA/PTX 只有 0.928×。Agent 生成的 Kimi Delta Attention 相对官方 FlashKDA 几何平均加速 2.05×。

**判断**：模型不是代码 Agent 的全部。中间表示、局部诊断和自动验证才会把一次成功变成可复用能力；数字仍需等代码和独立复现。

### vToken：不改 PagedAttention Kernel，回收 token 级 KV Cache

- [arXiv:2608.13263](https://arxiv.org/abs/2608.13263)，首次提交 2026-08-13。
- 用 token-table 间接寻址分离逻辑存活状态与物理块位置，异步重排存活 token，保持 PagedAttention Kernel 和 CUDA Graph 兼容。
- 作者报告每请求保留 KV 块减少 27.2%–72.3%，SLA 约束吞吐最高 1.37×，受限 KV 预算下最大并发最高 2×；策略接入从 500+ 行降到不足 50 行。

**判断**：这比再做一个 eviction heuristic 更像系统解法。对 vLLM 长上下文服务有直接价值，但收益依赖 workload、block size 和 eviction policy。

### RAGSieve：用局部对比抓 RAG 投毒

- [arXiv:2608.13010](https://arxiv.org/abs/2608.13010)，首次提交 2026-08-13。
- 查询阶段把 top-5 与同次检索第 6–20 名比较；入库阶段比较文档与语义近、字面不同的局部邻居，不要求可信语料或毒化标签。
- 三个 QA 数据集、六种投毒构造中，RSQ 为 95.2% AUROC；联合部署把攻击成功率从 67.4% 降到 14.0%，但干净检索 F1 只有 41.3%。

**判断**：双层防护思路可落地，但 41.3% F1 提醒得很清楚：安全指标好看不等于业务可用，误删和召回损失必须一起测。

### LycheeMemory V2：记忆整理不必每轮都调用 LLM

- [arXiv:2608.12990](https://arxiv.org/abs/2608.12990)，首次提交 2026-08-13。
- 按语义边界把多轮 exchange 聚合成 segment，再编码为上下文独立的 typed memory record，替代逐轮 eager consolidation。
- 使用 GPT-4.1-Mini，作者报告 LoCoMo 89.22%、LongMemEval-S 92.20%；相比 A-Mem，构建 token 分别减少 86.0% 和 75.9%，查询 token 未增加。

**判断**：这条最适合长期 Agent 记忆系统。关键变量不只是存什么，而是什么时候、按多大粒度整理；但它仍是作者基准，真实多用户漂移和遗忘策略没被这些数字回答。
