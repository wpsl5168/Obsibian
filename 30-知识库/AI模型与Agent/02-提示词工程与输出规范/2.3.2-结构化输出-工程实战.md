# 结构化输出 — 工程实战与最佳实践

> 📚 上级页面：[[2.3-结构化数据输出]]

### 4. Pydantic + AI 框架——Python 生态的类型安全方案

Python 生态中，Pydantic 已经成为定义 LLM 输出 Schema 的事实标准：

```python
from pydantic import BaseModel, Field
from typing import Literal

# 定义输出模型——就像 C# 的 record 类型
class CodeIssue(BaseModel):
    severity: Literal["critical", "warning", "info"]
    line_number: int = Field(ge=1, description="代码行号")
    description: str = Field(max_length=500)
    suggestion: str

class CodeAnalysis(BaseModel):
    issues: list[CodeIssue]
    overall_score: int = Field(ge=1, le=10)
    summary: str

# OpenAI 的 Python SDK 直接支持 Pydantic
from openai import OpenAI
client = OpenAI()

completion = client.beta.chat.completions.parse(
    model="gpt-4.1",
    messages=[{"role": "user", "content": "分析这段代码..."}],
    response_format=CodeAnalysis  # 直接传 Pydantic Model！
)
result: CodeAnalysis = completion.choices[0].message.parsed
# result.issues[0].severity → 类型安全访问
```

**主流 AI 框架的结构化输出支持**：

| 框架 | 语言 | 结构化输出方式 | 特色 |
|------|------|--------------|------|
| **OpenAI SDK** | Python/JS/.NET | Pydantic / JSON Schema / Zod | 原生 Structured Outputs |
| **Semantic Kernel** | C# / Python | .NET 类型系统 | 微软生态，与 Azure 深度集成 |
| **LangChain** | Python/JS | `with_structured_output()` | 跨模型统一接口 |
| **Instructor** | Python | Pydantic + 重试机制 | 专注结构化输出，支持多种 LLM |
| **Marvin** | Python | Pydantic + 函数式 API | 轻量级，适合快速原型 |
| **PydanticAI** | Python | Pydantic 原生 | Pydantic 团队出品，2025 年新起 |

### 5. .NET/Semantic Kernel 中的结构化输出实战

对 .NET 开发者，Semantic Kernel 提供了类型安全的结构化输出支持：

```csharp
using Microsoft.SemanticKernel;
using System.ComponentModel;
using System.Text.Json.Serialization;

// 定义输出类型——就像定义 EF Core 的 Entity
public record CodeAnalysisResult
{
    [Description("发现的问题列表")]
    public required List<CodeIssue> Issues { get; init; }

    [Description("总体评分 1-10")]
    public required int OverallScore { get; init; }

    [Description("分析总结")]
    public required string Summary { get; init; }
}

public record CodeIssue
{
    [JsonConverter(typeof(JsonStringEnumConverter))]
    public required Severity Severity { get; init; }
    public required int LineNumber { get; init; }
    public required string Description { get; init; }
    public required string Suggestion { get; init; }
}

public enum Severity { Critical, Warning, Info }

// 使用 Semantic Kernel 获取结构化输出
var kernel = Kernel.CreateBuilder()
    .AddOpenAIChatCompletion("gpt-4.1", apiKey)
    .Build();

var settings = new OpenAIPromptExecutionSettings
{
    ResponseFormat = typeof(CodeAnalysisResult)  // 传入类型
};

var result = await kernel.InvokePromptAsync<CodeAnalysisResult>(
    "分析以下 C# 代码的性能问题：{{$code}}",
    new KernelArguments(settings) { ["code"] = sourceCode }
);

// result.Issues[0].Severity → 强类型访问
// result.OverallScore → int，不是 string
```

> [!tip] 老王特别提示
> Semantic Kernel 的 `ResponseFormat = typeof(T)` 底层会自动将 C# 类型转换为 JSON Schema，传给 OpenAI 的 Structured Outputs API。这意味着你用熟悉的 C# record/class 就能定义 LLM 的输出格式——**跟定义 EF Core 的 Entity 一模一样的体验**。

### 6. 结构化输出的常见陷阱与最佳实践

**陷阱一：Schema 过于复杂导致质量下降**
```
❌ 20 个字段、5 层嵌套的巨型 Schema → 模型忙于凑格式，内容质量骤降
✅ 拆分为多次调用，每次输出简单 Schema → 类似数据库的范式化设计
```

**陷阱二：enum 值拼写不一致**
```csharp
// ❌ 模型可能输出 "Critical"、"critical"、"CRITICAL"
// ✅ 在 Schema 中用 enum 严格限定：
//    "enum": ["critical", "warning", "info"]
//    配合 strict: true，保证大小写一致
```

**陷阱三：数值范围失控**
```csharp
// ❌ "score": {"type": "integer"} → 模型可能输出 -1 或 99999
// ✅ Pydantic: Field(ge=1, le=10)
// ✅ JSON Schema: {"type": "integer", "minimum": 1, "maximum": 10}
// 注意：OpenAI strict mode 目前不支持 minimum/maximum 约束 [待验证]
//       需要在应用层额外校验
```

**陷阱四：忽略 `null` 处理**
```csharp
// 某些字段可能合法地为空
// JSON Schema 中需要用 "anyOf" 处理：
// "suggestion": {"anyOf": [{"type": "string"}, {"type": "null"}]}
// C# 中对应 string? 可空引用类型
```

**最佳实践清单**：
1. **Schema 先行**：先用 Pydantic/C# record 定义好类型，再写 prompt——跟 Database First vs Code First 一个道理
2. **Description 字段不能省**：`description` 是模型理解字段语义的关键线索
3. **测试驱动**：写结构化输出的单元测试，验证 Schema 兼容性
4. **降级策略**：结构化输出失败时 fallback 到纯文本 + 正则解析
5. **版本控制 Schema**：Schema 变更等同于 API Breaking Change，要版本管理

### 7. 结构化输出 vs 其他方案对比

```
方案选择决策树：

需要 LLM 输出结构化数据？
├── 简单 key-value → JSON Mode 就够（response_format: { type: "json_object" }）
├── 复杂嵌套 + 严格合规 → Structured Outputs + strict: true
├── 需要触发下游操作 → Function Calling / Tool Use
├── 多步推理 + 结构化 → Extended Thinking + Tool Use（Claude）
└── 分类/枚举任务 → Gemini enum mode 或 Logit Bias 方案
```
