## 一句话理解 MCP

**MCP 之于 AI Agent，就像 ADO.NET 之于 .NET 应用——一套标准化的数据访问协议。**

在没有 ADO.NET 之前，访问 SQL Server 用一套 API，访问 Oracle 用另一套，访问 MySQL 又是一套。ADO.NET 统一了接口：`IDbConnection`、`IDbCommand`、`IDataReader`，不管底层是什么数据库，上层代码写法一样。

MCP 做的是同一件事：在没有 MCP 之前，接 Claude 用 Anthropic 的 Tool API，接 GPT 用 OpenAI 的 Function Calling，接 Gemini 用 Google 的 Tool 格式。每家 LLM 平台的工具接入方式都不同。MCP 统一了这一切。

Anthropic 在 2024 年 11 月发布 MCP，称之为 **"AI 的 USB-C 接口"**。到 2025 年 3 月，OpenAI 正式宣布支持 MCP（集成到 Agents SDK、Responses API 和 ChatGPT 桌面版），2025 年 4 月 Google 宣布在整个 Gemini 生态系统中部署 MCP，2025 年 12 月 Anthropic 将 MCP 捐赠给 Linux 基金会，使其成为生态中立的开放标准。**2026 年，MCP 已经成为事实上的行业标准，生态系统包含 1000+ 服务器，月下载量达到 9700 万次。**

### MCP 解决的核心问题

传统 Function Calling 的痛点：
1. **M×N 集成问题**：每个 AI 应用 × 每个工具都需要单独适配
2. **上下文碎片化**：工具定义、资源、提示词散落在各处
3. **无状态困境**：每次 API 调用都是独立的，缺乏会话级的上下文管理

MCP 将这些问题统一为标准化的 **Client-Server 架构**。

## 安全模型与授权

### OAuth 2.1 集成

2025 年 3 月版本引入了基于 **OAuth 2.1** 的授权框架（针对 HTTP 传输）：

1. Client 发起请求 → Server 返回 `401 Unauthorized`
2. Client 从 Server 的 `/.well-known/oauth-authorization-server` 获取 OAuth 元数据
3. Client 引导用户完成 OAuth 授权流程（PKCE 必选）
4. 后续请求携带 Bearer Token

> [!warning] 安全提醒
> MCP Server 默认没有沙箱隔离。`destructiveHint: true` 的工具（如删除文件、执行 SQL DELETE）必须在 Host 层实现审批机制。参考 [[4.4-Human-in-the-loop交接机制]]。

### 关键安全原则

1. **最小权限**：Server 只暴露必要的工具和资源
2. **用户确认**：敏感操作需要人工审批
3. **数据隐私**：Host 不应将用户数据在未经同意的情况下传给 Server
4. **Tool Annotation 驱动的策略**：基于 annotations 自动分级管控

## MCP vs 传统 Function Calling

| 维度 | 传统 Function Calling | MCP |
| :--- | :--- | :--- |
| 工具发现 | 硬编码在 API 请求中 | 动态发现 (`tools/list`) |
| 工具数量 | 受上下文窗口限制（通常 < 20） | 理论上无限（按需加载） |
| 有状态性 | 无状态 | 有状态会话 |
| 跨应用复用 | 每个应用单独实现 | 一个 Server 服务所有 Host |
| 标准化程度 | 各厂商 API 不同 | 统一开放协议 |
| 生态 | 碎片化 | 统一生态，共享 Server |

## 当前缺口与展望

MCP 在 2026 年已经成熟，但仍有优化空间：

| 维度 | 2025 年状况 | 2026 年进展 | 仍需改进 |
|---|---|---|---|
| **安全认证** | OAuth 2.1 刚加入 | 企业级认证方案成熟 | 细粒度权限控制 |
| **Server 发现** | 手动配置 | **MCP Registry 上线** | 版本依赖管理 |
| **权限粒度** | 全部工具或断连 | **工具级权限控制** | 数据级权限 |
| **版本管理** | 无版本协商 | **语义化版本支持** | 向后兼容保证 |
| **监控审计** | 缺少标准方案 | **统一审计 API** | 实时监控仪表盘 |
| **性能优化** | 基础连接池 | **批量操作支持** | 智能缓存策略 |

### 2026 年 MCP 重大突破

1. **MCP Registry 上线**：类似 npm/PyPI 的中央仓库，一键安装和版本管理
2. **企业安全框架**：零信任架构、细粒度 RBAC、审计日志
3. **批量操作协议**：单次请求处理多个工具调用，降低延迟 60%
4. **智能路由**：Host 可根据负载自动选择最优 MCP Server 实例

> [!tip] .NET 类比的演进
> 2026 年的 MCP 更像成熟的 .NET 生态——有了 NuGet（MCP Registry）、完善的安全模型（Enterprise Security Framework）、性能监控（Application Insights for MCP），从"能用"进化到了"好用"。
