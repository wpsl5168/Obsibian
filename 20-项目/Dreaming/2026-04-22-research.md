### Bug 隐患

| # | 问题 | 位置 | 根因 | 建议方案 | 优先级 |
|---|------|------|------|---------|--------|
| 1 | 模型切换时旧 `fetch` 未取消，可能 set 到已卸载组件 | pages/model/[id].js:177-199 | useEffect 内 `fetch(...).then(setLdrawCode)` 没有 AbortController；用户在模型 A 加载途中跳到 B，A 的响应回来仍写入 state，会出现"加载新模型却显示旧 LDraw"的竞态 | 用 `const ctl = new AbortController()`，传入 `fetch(..., {signal: ctl.signal})`，cleanup 里 `ctl.abort()`；或在 .then 里检查 `if (cancelled) return` | P1 |
| 2 | `errors` 渲染回退到 `e.toString()`，对象会显示 `[object Object]` | pages/model/[id].js:441-443 | `errors` 数组元素是 `{msg, line, raw}` 形态（见 BrickRenderer/parser），fallback `e.toString()` 触发对象默认 toString，对用户毫无意义 | 改为 `{e.msg \|\| JSON.stringify(e)}`，并在 raw 存在时加 `<code>` 显示行号 | P2 |
| 3 | `handlePlacePart` / `handleHintRequest` 未 useCallback，每次渲染都生成新引用 | pages/model/[id].js:60-70 | 两个函数都被传给 `<PartsTray>` 当 prop；父组件任何 state 改动（step、loading 等）都会让 PartsTray 收到新 prop 触发重渲，沙盒模式下零件多时拖慢交互 | 包 `useCallback([sandboxParts, hintId])`；同理 `handleImageFallback` 也应 memo | P2 |
| 4 | `traverse` 递归用 `new Set([...visited, f])` 复制访问集，O(n²) 内存 | pages/model/[id].js:140-156 | 大型 MPD（嵌套子模型）会触发多次 spread，对 200+ 子模型集合每层都重新分配；同时该写法仍允许"同一文件出现在不同分支"被多次计数（可能是有意，但与 `visited` 名义冲突） | 用全局 `visited` Set + 进入时 add、退出时不删除（DAG 防循环）；或保留分支但显式命名 `pathSet` | P2 |
| 5 | `handleImageFallback` 对 Next/Image 直接改 `target.src` 与 `target.classList` | pages/model/[id].js:76-87 | Next/Image 即便 `unoptimized` 也会管理底层 `<img>`，下一次 React 重渲会用 src prop 覆盖你设置的 fallback URL，导致"短暂显示 fallback、又跳回 404"的闪烁 | 改用 state 存当前 fallback 层级（`useState({})` 以 partName 为 key），src 由 state 决定，不直接 mutate DOM | P2 |
| 6 | 模式互斥用三个独立 boolean，未集中状态机 | pages/model/[id].js:38-42, 402, 413 | `isAssemblyMode` / `isSandboxMode` / `showParts` 各自独立，切换时手动互相 reset；遗漏一个就会出现"放映 + 沙盒同时为 true" 的非法态（目前未遗漏，但脆弱） | 收敛为 `mode: 'view' \| 'assembly' \| 'sandbox'` 单一字段，UI 切换时只改这一个 | P3 |
| 7 | `setStep(s => !isAssemblyMode ? 1 : 0)` 闭包里读外部 `isAssemblyMode` | pages/model/[id].js:402 | functional updater 第一参 `s` 没用，反而读了闭包变量 `isAssemblyMode`（已 stale 风险低，因为同一渲染 commit），但写法误导阅读、未来容易踩坑 | 改为直接 `setStep(isAssemblyMode ? 0 : 1)`（与 `setIsAssemblyMode(v => !v)` 同步即可） | P3 |
| 8 | `lib/pipeline/index.js` 的 `dslTelemetry` 模块级单例，跨请求共享 | lib/pipeline/index.js:7-17 | 在 Node Server 进程内是全局累积计数（用于运维监控也许 OK），但**在 serverless / Edge / Vercel** 部署时会因实例隔离丢失数据；同时不同租户/调试请求互相污染计数 | 区分"全局聚合"和"单次请求"两份；单次返回的 `telemetry` 应该是 snapshot **delta**，否则前端拿到的是历史累计 | P2 |
| 9 | `errors[].msg.includes('字段')` 等用中文字符串判类型 | lib/pipeline/index.js:206 | 错误消息一旦改文案（i18n、错别字订正），分类全乱；与 `error.type` 并存且优先 type，但 fallback 链脆弱 | 在 parser/validator 端统一暴露 `type` 字段，删除 fallback 的字符串嗅探；保留 fallback 为 `'unknown'` | P3 |
