# 模式01：纯云端架构

## 一句话
车上只跑驱动和传感器读取，所有"思考"通过网络上传到云端LLM。

## 架构图

```
┌─────────────────────┐
│  ☁️ 云端 (Azure)    │
│  ┌───────────────┐  │
│  │  Hermes Agent │  │  ← 全部大脑在这
│  │  Claude/GPT-4 │  │
│  │  视觉/规划/对话│  │
│  └───────┬───────┘  │
└──────────┼──────────┘
           │ HTTP/WebSocket/MQTT
           │ (持续上行: 图像/语音/遥测)
           │ (持续下行: 控制指令)
           ↓
┌─────────────────────┐
│  🤖 Pi 5 (哑终端)    │
│  ┌───────────────┐  │
│  │ 串流agent.py  │  │  ← 只做IO代理
│  │ - 摄像头推流  │  │
│  │ - 麦克风推流  │  │
│  │ - GPIO控制    │  │
│  │ - 紧急刹车    │  │
│  └───────────────┘  │
└─────────────────────┘
```

## 工作流程

```
用户: "找一下我的水杯"
  ↓ Pi麦克风采集音频
  ↓ 上传云端 (Whisper STT)
  ↓ 云端Hermes接收 + Camera流
  ↓ Claude规划: "扫视房间→识别水杯→导航过去"
  ↓ 下发动作序列
  ↓ Pi执行 + 持续回传画面
  ↓ 云端实时纠偏
  ↓ Piper TTS → Pi喇叭: "找到了"
```

## 优势

- **能力天花板高**：直接用Claude Sonnet/GPT-4o最强模型
- **开发简单**：复用现有Hermes Skills生态，零重构
- **硬件成本低**：Pi 4B (4GB) 都够，不需要Hailo
- **维护省心**：模型升级在云端，车不用动
- **多车统一**：N台车共享一个云端大脑

## 致命缺陷

- **延迟感人**：往返1-3秒，"前面有障碍物" → 已经撞了
- **断网即砖**：WiFi一断车变铁皮疙瘩
- **隐私崩塌**：你家所有摄像头画面持续上云
- **流量爆炸**：720p视频流 ≈ 3MB/s，10GB流量撑1小时
- **API成本失控**：Claude视觉每张图~$0.01，1Hz就是$36/小时
- **抗干扰差**：Azure海外IP被国内站点风控（你已遇到的坑）

## 适用场景

✅ 室内Demo、CES展示、研究原型
✅ 永远联网的固定环境（仓库巡检车）
✅ 单次任务时间短、对延迟不敏感

❌ 户外/移动场景
❌ 真实"日常陪伴"用途
❌ 要做安全相关动作（刹车/避障）

## 实现要点

```python
# Pi端 (50行搞定)
import paho.mqtt.client as mqtt
import picamera2, smbus

cam = picamera2.Picamera2()
mqtt_client.connect("your-azure-vm")

# 上行: 每秒推一帧
while True:
    frame = cam.capture()
    mqtt_client.publish("rover/cam", compress(frame))
    
# 下行: 接收指令执行
def on_message(_, __, msg):
    cmd = json.loads(msg.payload)

```

## 故障模式

| 故障 | 现象 | 后果 |
|---|---|---|
| 网络抖动 | 指令延迟到3-5秒 | 撞墙/丢任务 |
| Azure被风控 | API 403/超时 | 直接罢工 |
| 云端API限流 | 高峰期排队 | 用户体验崩 |
| WiFi断 | 完全失联 | 车变砖，可能跑飞 |
