# 模式04：分层反射架构

## 一句话
仿生脑科学，分L0-L4五层，反射越快的层级越底层、越简单、越不可中断。

## 灵感来源
- 人脑：脊髓反射(L0) → 小脑(L1) → 边缘系统(L2) → 大脑皮层(L3)
- 经典机器人学：Brooks的Subsumption Architecture (1986)
- Boston Dynamics Atlas的实时控制栈

## 架构图

```
┌─────────────────────────────────────────────────────────┐
│  L4: 元认知层 (Meta-cognition)                          │
│  "我应该重新规划任务吗？"                               │
│  长期记忆/学习/反思 — 异步，分钟级                      │
└────────────────────────┬────────────────────────────────┘
                         ↓ 影响
┌─────────────────────────────────────────────────────────┐
│  L3: 推理规划层 (Reasoning)                             │
│  "找猫并跟随" → [扫视, 识别, 导航, 跟随]                │
│  LLM (本地3B或云端) — 秒级                              │
└────────────────────────┬────────────────────────────────┘
                         ↓ 下发子任务
┌─────────────────────────────────────────────────────────┐
│  L2: 行为决策层 (Behavior)                              │
│  "执行扫视": 360°旋转+视觉采样                          │
│  状态机/行为树 — 100ms级                                │
└────────────────────────┬────────────────────────────────┘
                         ↓ 输出动作意图
┌─────────────────────────────────────────────────────────┐
│  L1: 协调控制层 (Coordination)                          │
│  PID/MPC控制器, 平滑加减速, 编队                        │
│  ROS控制器 — 10ms级                                     │
└────────────────────────┬────────────────────────────────┘
                         ↓ 电机指令
┌─────────────────────────────────────────────────────────┐
│  L0: 反射层 (Reflex) ★永远在线，可打断一切              │
│  超声波<20cm急停 / IMU倾角>30° / 过流保护               │
│  纯C/C++或MCU — 微秒级                                  │
└─────────────────────────────────────────────────────────┘

向上抑制 (Subsumption): 下层可打断上层
  L0 急停 → L1/L2/L3/L4 全部暂停
  L1 PID饱和 → L2 调整目标
```

## 核心原则：Subsumption (包含/抑制)

Rodney Brooks 1986年的核心思想：
> 高层不直接控制电机，只给低层"建议"。低层有否决权。

举例：
- L3说"前进2米去找杯子"
- L1接收，开始PID控制
- L0检测到前方20cm有障碍 → **打断L1**，原地停
- L0通知L2 → L2触发"避障行为"
- L2上报L3："路径阻塞"
- L3重新规划

## 各层技术选型

### L0 反射层
- **硬件**: 独立MCU (ESP32/STM32) 或 Pi GPIO中断
- **语言**: C/C++ (确定性延迟)
- **逻辑**: 纯规则，不超过50行代码
- **看护**: systemd或硬件Watchdog

```c
// L0 伪代码 (运行在MCU上)
void loop() {
    if (sonar_distance() < 20) emergency_stop();
    if (imu_tilt() > 30) emergency_stop();
    if (battery_voltage() < 10.5) start_homing();
    pwm_output(commanded_pwm);  // 默认透传上层指令
}
```

### L1 协调控制层
- **典型工具**: ROS 2 control, ros2_controllers
- **算法**: PID (轮速)、MPC (轨迹)、IMU融合
- **频率**: 100-200Hz
- **可选**: 直接用Pi跑，或独立Pico W

### L2 行为决策层
- **典型工具**: BehaviorTree.CPP, py_trees, SMACH
- **粒度**: 一个行为 = 一个子任务 (避障/跟随/扫视)
- **频率**: 10-50Hz
- **接口**: 暴露给L3作为"原子能力"

### L3 推理规划层
- **典型工具**: LLM Agent (Hermes) + Skills
- **职责**: 把自然语言/高层目标拆解为L2行为序列
- **频率**: 按需，秒级

### L4 元认知层 (可选)
- **职责**: 复盘任务、更新KB、调整策略
- **频率**: 任务结束后或定时
- **可放云端**

## 工作流程示例: "去厨房看炉子关了没"

```
[L3] LLM规划:
  → goto("厨房") → look_at("炉子") → check_state() → report

[L2] 执行 goto("厨房"):
  → 查询SLAM地图 → 生成路径 → BT节点: NavigateToPose

[L1] 接收路径:
  → MPC控制器跟踪轨迹 → 100Hz下发轮速

[L0] 持续监控:
  → 第3秒: 检测到前方有人(超声+视觉)
  → 急停！抑制L1
  → 通知L2: PathBlocked

[L2] 触发避障行为:
  → BT切换到"等待+绕行"

[L3] 收到状态:
  → 决定: 是绕行还是问主人?
  → 选择: 5秒不动就绕

...任务继续...

[L4] 任务结束:
  → 复盘: "厨房路径常被人挡，下次先问"
  → 更新KB
```

## 优势

- **安全性极强**：L0硬隔离，LLM挂了车也不会撞
- **可解释性好**：问题定位到具体层
- **扩展性强**：每层可独立升级
- **混合时序**：微秒级反射+秒级推理共存
- **工业可靠**：航空/汽车/工业机器人通用模式

## 缺陷

- **复杂度高**：5层接口设计、调试、测试都要做
- **开发周期长**：纯本项目个人玩家可能hold不住
- **过度设计**：玩具车不需要这么严谨
- **跨层调试难**：bug可能在层间接口
- **学习曲线陡**：要懂控制论+行为树+LLM三套体系

## 适用场景

✅ 安全敏感（医疗机器人、自动驾驶）
✅ 已有控制工程背景
✅ 要混合实时+智能控制
✅ 工业级产品

❌ 玩具/Demo (杀鸡用牛刀)
❌ 单人开发周期紧

## 与混合脑(模式03)的关系

**正交不冲突，常组合使用！**

```
混合脑(03) 解决: "大脑放哪？" — 本地 vs 云端
分层反射(04) 解决: "决策怎么分级？" — 反射 vs 思考

最终方案 = 混合脑 × 分层反射
  L0 反射: 纯本地MCU
  L1 控制: 纯本地Pi
  L2 行为: 本地Hermes+BT
  L3 推理: 路由器决定本地/云端 ← 这里是混合脑的战场
  L4 元认知: 云端Hermes (异步)
```

## 实现复杂度估算

| 层 | 工作量 | 关键技术 |
|---|---|---|
| L0 | 1-2周 | C+GPIO中断, Watchdog |
| L1 | 2-3周 | PID调参, IMU融合 |
| L2 | 2-4周 | BehaviorTree, 状态机 |
| L3 | 已有Hermes | Skills开发 |
| L4 | 1周 | 简单复盘脚本 |

**总计**: 6-12周完整实现 (兼职)
