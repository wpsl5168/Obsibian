# 决策矩阵：Pi-Rover 架构选型

## 老王需求回顾 (Source of Truth)

> 1. **Agent级**: 不只是遥控，要"它真的智能"
> 2. **本地优先**: 大脑尽量在车上
> 3. **可联网**: 联网能力可以利用，不强求离线

## 分Phase实施 (5阶段)

### Phase 1: MVP (2周)
- 模式03简化版: 本地Hermes + GPIO控车
- L0反射层 (超声波急停)
- 验证: 语音遥控 + 简单"看到啥"

**架构使用度**: 03 (40%) + 04 (L0+L1)

### Phase 2: 视觉智能 (2周)
- Hailo HAT安装
- 本地YOLOv8 30fps
- Qwen2.5:3B加入
- 验证: "找红色物体"本地完成

**架构使用度**: 03 (60%) + 04 (L0-L2)

### Phase 3: 混合脑路由 (2周)
- 路由器实现 (Qwen1.5B)
- 云端delegate通道
- 共享SQLite events
- 验证: 复杂任务自动上云

**架构使用度**: 03 (100%) + 04 (L0-L3)

### Phase 4: 高级能力 (4周)
- 引入ROS 2 + Nav2 (模式06)
- SLAM建图 + 自动归位
- BT重构L2 (模式05)
- 长期记忆KB

**架构使用度**: 03+04+05+06

### Phase 5: 生态 (持续)
- 更多Skills
- 元认知层 (L4)
- 可选: 多Agent (模式07)

## 一定要踩的坑 (老王必看)

### 坑1: 本地LLM启动慢
- Qwen3B首次加载 30-60s
- **解法**: 开机自启常驻，不要按需启动

### 坑2: Pi 5散热
- Hailo+LLM满载会节流
- **解法**: 主动散热风扇 (¥30) + 大铝外壳

### 坑3: 路由器是命门
- 路错一次用户就觉得"傻"
- **解法**: 默认偏本地，加"用大脑想想"语音命令强制走云

### 坑4: L0安全不能省
- 早期开发想"先跑起来再说"会撞设备
- **解法**: Day 1就装L0，bare minimum也要有超声波

### 坑5: SD卡挂掉
- 频繁写日志会写废
- **解法**: 上NVMe SSD (¥150)，或RAM日志+定时落盘

### 坑6: 海外API被风控
- 你Azure VM已经遇到
- **解法**: 路由器优先选本地，云端调用走Hermes本地代理

## Plan B / 兜底策略

| 情况 | Plan B |
|---|---|
| Hailo买不到/驱动坑 | 用Pi 5 CPU跑YOLOv8n (10fps) |
| Qwen3B太慢 | 降到1.5B或PaddleLite小模型 |
| 云端API超预算 | 关掉云端通道，纯本地兜底 |
| ROS 2学不会 | 跳过Phase 4的ROS化，用Python直接写 |
| 整个项目玩不下去 | 至少保留模式01纯云端Demo |
