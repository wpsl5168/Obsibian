# 模式08：联邦集群 / 多车协同架构

## 一句话
N台小车 + 1个云端"集群大脑"，车之间共享地图/记忆/技能，集体学习。

## 架构图

```
              ┌───────────────────────────┐
              │  ☁️ 云端集群大脑           │
              │  ┌──────────────────────┐ │
              │  │ 共享世界模型 (3D Map)│ │
              │  │ 共享物品KB           │ │
              │  │ 任务调度器           │ │
              │  │ 集体学习 (FedAvg)    │ │
              │  └──────────────────────┘ │
              └───┬─────────┬──────────┬──┘
                  │         │          │
        ┌─────────┴──┐  ┌───┴────┐  ┌─┴──────┐
        │ 🤖 Rover-1 │  │Rover-2 │  │Rover-N │
        │ 客厅       │  │厨房    │  │卧室    │
        │ (本地脑)   │  │(本地脑)│  │(本地脑)│
        └────────────┘  └────────┘  └────────┘
              ↕             ↕            ↕
          P2P (车车直连，地图同步)
```

## 三种联邦模式

### A. 中心化协调
- 所有车上报给云端
- 云端下发任务/地图
- 简单但单点故障

### B. P2P网格
- 车车直连，无中心
- 拜占庭容错
- 复杂但抗故障

### C. 混合 (推荐)
- 云端做长期记忆/学习
- 车车做实时协调

## 核心能力

### 1. 共享地图
```
Rover-1扫了客厅 → 上传 → 其他车直接拿到
新车加入 → 下载完整SLAM地图 → 即插即用
```

### 2. 任务接力
```
用户: "把这本书放回书架"
Rover-1 (在客厅): 抓书 → 走到客厅边界
Rover-2 (在书房): 接力 → 放到书架
```

### 3. 集体学习 (Federated Learning)
```
每台车收集本地交互数据
本地训练增量 → 上传梯度 (不传原始数据)
云端聚合 → 下发新模型权重
所有车一起变聪明
```

### 4. 角色专精
```
Rover-A: 安装机械臂，专门取物
Rover-B: 装大电池，长续航巡逻
Rover-C: 小型敏捷，钻床底
互相调度，不重复造轮子
```

## 优势

- **覆盖广**: 多车并行做事
- **冗余高**: 一台坏了其他顶上
- **越用越聪明**: 集体学习
- **角色专精**: 不同硬件各司其职

## 缺陷

- **复杂度爆表**: 分布式系统所有问题都来
- **同步开销**: 地图/状态同步带宽大
- **冲突解决**: 两台同时去厨房咋办?
- **隐私边界**: 集体学习如何不泄露个人数据
- **成本×N**: 单车就贵，N台更贵
- **个人玩家不现实**: 这是企业/科研级项目

## 适用场景

✅ 仓储机器人 (Amazon Robotics)
✅ 餐厅送餐机器人 (擎朗/普渡)
✅ 多机器人科研
✅ 工业巡检车队

❌ 个人玩具
❌ 单家庭场景 (1台就够)
❌ 预算<¥10K

## 与本项目匹配度

但**值得放到长期Vision**：如果未来想做产品，多车协同是差异化点。

## 一句话评价

**联邦集群是机器人界的"分布式系统"。** 牛但贵且复杂，先单车跑通再说。

- 单车架构必须先选好 (推荐模式03+04)
- 在此基础上加"联邦层" — 增量演进，不替换
