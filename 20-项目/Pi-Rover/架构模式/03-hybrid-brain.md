# 模式03：混合脑架构 ★推荐

## 一句话
本地脑做日常+云端脑做专家，路由器智能分发——默认本地兜底，复杂任务上云。

## 核心思想：三个原则

1. **默认本地，按需云端** — 90%任务本地完成，省钱省延迟
2. **能力分层，智能路由** — 不同复杂度走不同脑
3. **状态共享，不分裂** — 单一事实源 (SQLite events)

## 路由策略详解

### Level 1: 硬规则 (10ms内决策)

```python
SAFETY_KEYWORDS = ["停", "stop", "急停", "刹车"]
SIMPLE_VERBS = ["前进", "后退", "左转", "右转", "转圈"]

def fast_route(text):
    if any(k in text for k in SAFETY_KEYWORDS): 
        return "rules"  # 直接执行，不走LLM
    if any(text.startswith(v) for v in SIMPLE_VERBS):
        return "rules"  # 命令式直接转动作
    return None  # 落到LLM路由
```

### Level 2: LLM路由 (本地小模型判断)

```python
ROUTE_PROMPT = '''
判断任务复杂度：
- simple_local: 单步动作/简单视觉（"看到啥"）
- complex_cloud: 多步规划/深度理解（"找猫并跟随"）
仅返回JSON: {"route": "simple_local"|"complex_cloud", "reason": "..."}
'''
# Qwen2.5:1.5B做路由器，~200ms决策
```

### Level 3: 自适应路由

```python
# 根据历史成功率动态调整
if local_success_rate(task_type) > 0.8:
    route = "local"
elif token_budget_low or offline:
    route = "local"  # 强制
else:
    route = "cloud"
```

## 工作流程示例

### 场景A: "前进半米" (本地秒回)
```
audio → Whisper(本地) → "前进半米"
     → 路由器: SIMPLE_VERBS命中 → rules
     → motor.move(0.5m)
     → 总耗时: ~400ms
     → 成本: ¥0
```

### 场景B: "前面是什么" (本地视觉)
```
audio → Whisper → "前面是什么"
     → 路由器: 简单视觉 → L2本地
     → Hailo YOLOv8(33ms) → ["杯子", "书"]
     → Qwen3B生成: "我看到一个杯子和一本书"
     → Piper TTS
     → 总耗时: ~1.5s
     → 成本: ¥0
```

### 场景C: "找一下我那本红色封面的Python书" (云端救场)
```
audio → Whisper → "找一下..."
     → 路由器: 复杂视觉+长描述 → L3云端
     → 上传当前画面+任务到Hermes云端
     → Claude Sonnet视觉理解+规划
     → 返回动作序列: [扫视→识别→导航→指出]
     → 本地执行+实时反馈
     → 总耗时: ~3-5s
     → 成本: ¥0.05
```

### 场景D: "停！" (反射层)
```
audio → 关键词Spotting (本地<50ms)
     → L0直接刹车
     → 不进任何LLM
     → 总耗时: <100ms
```

## 状态共享机制

```sql
-- ~/rover.db (Pi本地SQLite)
CREATE TABLE events (
  id INTEGER PRIMARY KEY,
  ts REAL,
  layer TEXT,        -- L0/L1/L2/L3/L4
  event_type TEXT,   -- perception/decision/action
  payload JSON,
  source TEXT        -- local/cloud
);

CREATE TABLE memory_short (
  ts REAL, content TEXT, embedding BLOB
);  -- 近10分钟

CREATE TABLE kb_long (
  key TEXT, value JSON
);  -- 长期: 充电桩位置/家人脸/常用物品
```

云端要决策时：拉最近30s事件流(~5KB)+相关KB(~2KB)，决策完写回。

## 优势

- **延迟可接受**：90%任务本地<1s，剩余10%云端3-5s
- **成本可控**：月¥30-50（vs 纯云端¥700）
- **能力上限高**：复杂任务有Claude兜底
- **断网降级**：自动切L2本地，体验下降但不死
- **隐私友好**：默认数据不出车，只在云端任务时上传必要片段
- **复用现有Hermes**：你的Skills生态直接用

## 缺陷

- **架构复杂度高**：要维护两套Hermes实例
- **路由器是关键**：路错了体验崩（云端任务路给本地→搞不定，反之→浪费钱）
- **状态同步坑多**：本地/云端对世界的认知可能脱节
- **调试难**：问题在L0/L1/L2/L3哪层不好定位
- **灰度发布麻烦**：云端Skill升级要保证本地能降级

## 关键设计决策

### 决策1: 本地用多大的模型？
| 选项 | 推荐场景 |
|---|---|
| 1.5B | 路由器+轻量回复 |
| **3B** ★ | 主力模型，平衡 |
| 7B | 能力优先，速度妥协 |

**推荐组合**: Qwen2.5:1.5B做路由器(常驻) + Qwen2.5:3B做主对话(按需加载)

### 决策2: 云端用什么模型？
| 模型 | 单价 | 适用 |
|---|---|---|
| Claude Sonnet 4 | $3/$15 per M | 默认主力 |
| GPT-4o | $2.5/$10 per M | 视觉强 |
| Gemini 2.5 Pro | 中 | 长上下文 |

**推荐**: Claude Sonnet 4 (你已有Hermes现成接入)

### 决策3: 路由器放本地还是云端？
**必须放本地**。云端路由要求"先上云才知道是不是要上云"，悖论。

### 决策4: 视觉理解切分点？
- 物体检测/分类 → 本地 (Hailo YOLOv8)
- 场景描述/属性识别 → 云端 (GPT-4o Vision)
- OCR → 本地 (PaddleOCR Lite)
- 复杂关系推理 → 云端
