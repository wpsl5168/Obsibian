# 海马体测试用例 D1-D5（功能正确性/去重/搜索/性能/数据完整性）

> 📚 上级页面：[[测试方案与用例]]

### D1: 功能正确性（5个场景）

#### T1.1 写入与读取回环

| 项目 | 内容 |
|------|------|
| **目的** | 验证 memory/user 两种 target 写入后可读、可搜 |
| **前置** | 服务正常运行 |
| **步骤** | 1. POST /v1/memories 写入 memory 条目<br>2. POST /v1/memories 写入 user 条目<br>3. GET /v1/memories/hot 验证列表<br>4. POST /v1/memories/search 验证搜索命中 |
| **验收** | status=created; hot列表包含条目; search total>0 |
| **测试数据** | `[T1.1_{timestamp}] Agent学会了使用Docker部署服务` |

#### T1.2 替换

| 项目 | 内容 |
|------|------|
| **目的** | 验证 old_text 匹配后内容完整替换 |
| **步骤** | 1. 写入旧内容（含IP 192.168.1.100）<br>2. POST /v1/memories/replace 替换为新IP<br>3. 验证旧内容消失、新内容存在 |
| **验收** | status=replaced; hot中仅有新内容 |

#### T1.3 删除

| 项目 | 内容 |
|------|------|
| **目的** | 验证 old_text 匹配后条目彻底删除 |
| **步骤** | 1. 写入临时条目<br>2. POST /v1/memories/remove<br>3. 验证hot列表不含该条目 |
| **验收** | status=removed; hot列表无残留 |

#### T1.4 归档与提升

| 项目 | 内容 |
|------|------|
| **目的** | 验证 hot→cold 归档、cold→hot 提升的完整流转 |
| **步骤** | 1. 写入条目<br>2. Archive → 确认从hot消失<br>3. FTS搜索cold → 确认命中<br>4. Promote → 确认回到hot |
| **验收** | 归档status=archived; cold可搜; 提升status=promoted; 重回hot |

#### T1.5 target 隔离

| 项目 | 内容 |
|------|------|
| **目的** | 验证 memory 和 user 两个 target 的数据互不泄漏 |
| **步骤** | 1. 分别向 memory/user 写入专属内容<br>2. 查询 memory hot列表不含 user 内容（反之亦然） |
| **验收** | 各自target只返回自己的数据 |

### D2: 去重机制（4个场景）

#### T2.1 精确去重

| 项目 | 内容 |
|------|------|
| **目的** | 相同内容二次写入应被拦截 |
| **步骤** | 1. 首次写入 → created<br>2. 相同内容再次写入 → duplicate |
| **验收** | status=duplicate, reason=exact_hot |

#### T2.2 标准化去重（带迁移前缀）

| 项目 | 内容 |
|------|------|
| **目的** | 带 `[hermes-mirror]` 等前缀的相同内容应被识别为重复 |
| **步骤** | 1. 写入原始内容<br>2. 写入 `[hermes-mirror] ` + 相同内容 |
| **验收** | status=duplicate（前缀被标准化剥离后SHA256匹配） |
| **涉及前缀** | `[hermes-mirror]`, `[migrated-cold]`, `[migrated-hot]` |

#### T2.3 语义去重（cold层）

| 项目 | 内容 |
|------|------|
| **目的** | 归档到cold后，高度相似的改写内容应被语义去重 |
| **步骤** | 1. 写入并归档原文<br>2. 等待embedding生成(1s)<br>3. 写入改写版本 |
| **验收** | status=similar, distance<0.4 |
| **测试数据对** | 原文: "Python项目使用black格式化代码"<br>改写: "Python项目用black来格式化代码" |

#### T2.4 不同内容不误去重

| 项目 | 内容 |
|------|------|
| **目的** | 内容不同的条目不应被错误识别为重复 |
| **测试数据对** | "项目使用PostgreSQL数据库" vs "项目部署在Kubernetes集群" |
| **验收** | 第二条 status=created |

### D3: 搜索质量（5个场景）

#### T3.1 FTS关键词搜索

| 项目 | 内容 |
|------|------|
| **目的** | 验证FTS5全文索引的精确召回 |
| **步骤** | 归档3条不同主题(Nginx/Redis/Docker)，搜索"Nginx 反向代理" |
| **验收** | 返回结果包含Nginx条目 |

#### T3.2 向量语义搜索

| 项目 | 内容 |
|------|------|
| **目的** | 用自然语言查询，验证语义理解能力 |
| **查询** | "Web服务器的负载均衡配置" |
| **验收** | Nginx/反向代理条目应排名靠前（vec_distance较小） |
| **评估** | 记录Top-5结果的vec_distance分布 |

#### T3.3 混合搜索RRF融合

| 项目 | 内容 |
|------|------|
| **目的** | 验证FTS+Vector两路结果的RRF融合排序 |
| **查询** | "缓存性能优化" |
| **验收** | 返回带rrf_score的有序结果，Redis缓存条目应排名靠前 |

#### T3.4 不相关查询（负面测试）⚠️

| 项目 | 内容 |
|------|------|
| **目的** | 完全不相关的查询不应返回高置信结果 |
| **查询** | "量子计算超导体拓扑绝缘体" |
| **验收** | 返回结果的vec_distance应全部>15 |
| **已知缺陷** | **BUG-002**: 无距离阈值过滤，不相关结果仍会返回 |

#### T3.5 Hot搜索关键词匹配

| 项目 | 内容 |
|------|------|
| **目的** | Hot层基于关键词的子串匹配正确性 |
| **步骤** | 1. 写入含"tmux"的条目<br>2. 搜索"tmux" → 命中<br>3. 搜索"kubernetes" → 不命中 |
| **验收** | 精确匹配且不误匹配 |

### D4: 性能基准（4个场景）

#### T4.1 单次写入延迟

| 项目 | 内容 |
|------|------|
| **方法** | 连续10次写入，统计avg/p95/min/max |
| **基准** | avg < 1.0s（含Ollama embedding），p95 < 1.5s |
| **瓶颈** | Ollama embedding调用（约0.5-0.8s/次） |

#### T4.2 搜索延迟

| 项目 | 内容 |
|------|------|
| **方法** | 5个不同查询 × 3种模式(fts/vector/hybrid) |
| **基准** | FTS < 0.1s, Vector < 0.5s, Hybrid < 0.8s |

#### T4.3 并发写入

| 项目 | 内容 |
|------|------|
| **方法** | ThreadPoolExecutor 10线程并发20次写入 |
| **基准** | 0失败, wall time < 5s |
| **注意** | SQLite单写锁，靠uvicorn排队 |

#### T4.4 混合读写并发

| 项目 | 内容 |
|------|------|
| **方法** | 10线程交替读写各10次 |
| **基准** | 全部200 OK, 无死锁 |

### D5: 数据完整性（3个场景）

#### T5.1 特殊字符处理

| 测试数据 | 验证点 |
|----------|--------|
| 单引号、双引号 | JSON序列化不破坏 |
| 换行符、制表符 | 存储和读取保持一致 |
| 中文emoji🧠🦛、日文カタカナ | Unicode正确处理 |
| SQL注入 `'; DROP TABLE hot_memory; --` | 参数化查询防护 |
| JSON特殊字符 `{"key": "value\n"}` | 嵌套JSON不冲突 |
| 超长URL (500+ chars) | 大字段存储正常 |

#### T5.2 空/边界输入

| 输入 | 预期 |
|------|------|
| 空字符串 content | 应拒绝（400/422） |
| 10KB超长内容 | 应正常存储 |
| 无效target | 应返回422/500 |

#### T5.3 归档数据一致性

| 项目 | 内容 |
|------|------|
| **目的** | 归档前后内容完全一致，无截断/编码变化 |
| **方法** | 写入→归档→从cold读取→逐字比对 |
