# [[20-项目/海马体/需求/项目需求文档(PRD).md|OpenHippo]] 架构审查 v0.2

> 审查人：小虾（架构师视角）  
> 审查日期：2026-04-20  
> 基线版本：v0.2.0 (commit `483fdb1`)  
> 代码量：2045 LOC / 10 Python 模块  
> 测试基线：55 用例（实测发现 **19 个线程安全 fail**，下文 P0-2 现场证据）

---

## 一、审查结论

**架构骨架对路**：SQLite 单文件 + 抽象 embedding + REST/MCP 双协议 + 一键导出，方向是隐私优先 + 零锁定的正解。

**三大要害必须立即修**：
1. **并发不安全** — 单 connection 跨线程 + WAL 解决不了写事务交叉
2. **多租户 schema 没预留** — `target` 硬编码成 CHECK 约束，未来加 `agent_id/scope/session_id` 是惨案
3. **Dream 缺位** — 核心差异化 P0 功能未做，没它海马体只是 SQLite 包装

## 二、问题分级清单

### 🔴 P0 阻断级（上线前必修）

| # | 问题 | 现场证据 | 修复方案 |
|---|------|----------|----------|
| P0-1 | 多租户 schema 先天不足 | `target IN ('memory','user')` CHECK 约束 + 13 个未开始的 F11/F12/F13 | cold_memory 先加 `agent_id, scope, session_id` 列（NULL 允许），写入路径预留参数；migration 脚手架同步落地 |
| P0-2 | SQLite 连接非线程安全 | 当前 server 上 `vec_search` 报 `OperationalError: unknown error`，55 测试有 19 fail | `threading.local` 连接池，每线程独立 conn |
| P0-3 | 去重健壮性差 | hot 不参与语义去重；Ollama 挂时静默放行重复 | hot 也走语义去重；embed 失败应 warning + metric，长期失败可阻断写入 |
| P0-4 | 精确去重 O(n) 全表扫 | engine.add 拉全表 Python 循环 hash | cold_memory 加 `content_hash` 列 + (target, content_hash) UNIQUE 索引 |

## 三、做得好的部分

1. **Embedding 抽象层** — Ollama/ST 双后端 + auto 探测，干净
2. **RRF 融合** — FTS+vector 用 Reciprocal Rank Fusion 而非手调权重，工业最佳实践
3. **导出导入对称** — 4 种格式 + schema_version + reembed 选项，"零锁定"承诺真兑现
4. **Bearer auth 用 hmac.compare_digest** — 没踩字符串 == 的常见坑
5. **代码量克制** — 2045 LOC 完成 10/26 功能 + 端到端测试，密度高
6. **PRD 80KB 写得详尽** — 比绝大多数开源项目认真

## 五、风险与回滚

- **migration 脚手架**：每次启动幂等执行 `IF NOT EXISTS / ALTER TABLE ADD COLUMN`，回滚靠 SQLite 文件备份
- **连接池改造**：原有单 conn 改 thread-local，对外接口不变，测试覆盖即可
- **schema 加列**：全部允许 NULL + 默认值，老数据零回填风险

## 附录：审查方法

- 通读 10 个核心模块（engine/storage/embedding/auth/rest/config/import/export/cli/mcp）
- 跑全量测试 → 发现 19 个原本"通过"的测试在 server 上 fail（前次测试可能用 in-memory 模式跳过了线程问题）
- 对照 PRD v2.1 + 开发进度报告做 gap 分析
- 按"会不会出事"严重程度排优先级，不按"好不好做"排
