## 0. 缘起：v0.3 dogfood 暴露的真问题

2026-04-21 修复了两个致命 bug 后做架构师复盘，结论：**当前形态不是"独立无破坏"，而是"低耦合可插拔"**。

| 维度 | 当前现状 | 真相 |
|---|---|---|
| 源码侵入 | 0 处 hermes 业务代码引用 | ✅ 真独立 |
| 进程隔离 | 独立 systemd 服务 | ✅ 真独立 |
| 失败兜底 | 27 处 try/except + WAL 离线队列 | ✅ 真独立 |
| **主链路延迟** | pre_llm_call **同步阻塞 ≤2s** | ⚠️ 破坏用户体验 |
| **prompt 改写** | 注入"🦛 海马体回忆..."banner 到 LLM context | ⚠️ 改变 LLM 输入分布 |
| **协议契约** | 寄生于 hermes hook 签名 + memory tool action 命名 | ⚠️ hermes 改动会悄悄破坏 |
| **多 Agent 支持** | 单 hermes 专用 | ❌ 不通用 |
| **数据主权** | 海马体 DB 是唯一存储，崩了 = 失忆 | ❌ 灾难风险 |

→ v0.4 必须解决后四项。

## 2. 核心架构：三层分离

```
┌──────────────────────────────────────────────────────────────────┐
│  Agent 进程（Hermes / Claude / Cursor / Any）                    │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  本地 SoT (Source of Truth)                                 │  │
│  │  ~/.hippo-sot/<agent_id>/memories.jsonl                     │  │
│  │  追加写，永远是该 agent 记忆的权威副本                       │  │
│  └────────────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  hippo-sdk (薄客户端 < 300 LOC)                             │  │
│  │  • 异步发件箱 outbox.db (SQLite WAL)                        │  │
│  │  • 本地 LRU 召回缓存                                         │  │
│  │  • 健康探测 + degraded 模式                                  │  │
│  │  • 协议转换：agent native → Hippo Wire Protocol v1          │  │
│  └────────────────────────────────────────────────────────────┘  │
└────────────────────┬─────────────────────────────────────────────┘
                     │ HTTP/JSON, X-Agent-ID header, ≤200ms timeout
                     ▼
┌──────────────────────────────────────────────────────────────────┐
│  Hippo Server（独立进程/容器，单一物理存储）                     │
│  • 单池共享 DB，每条记忆带 agent_id + scope 标签                 │
│  • 异步 embedding 队列                                           │
│  • 召回过滤：WHERE agent_id=? OR scope IN ('shared','global')   │
│  • 崩了不影响上游 agent，恢复后从 outbox / SoT 自动补齐         │
└──────────────────────────────────────────────────────────────────┘
```

**设计哲学**：
- **本地是权威，海马体是增强**。海马体永远不持有"agent 没有的记忆"。
- **共享池物理统一，agent_id 逻辑切片**。比严格隔离更灵活，支持跨 agent 协作。

## 3. 数据模型：单池 + 三 scope

### 3.1 表结构改动

```sql
-- 所有记忆表统一加两个字段
ALTER TABLE hot_memory  ADD COLUMN agent_id TEXT;       -- 写入者；NULL=global
ALTER TABLE hot_memory  ADD COLUMN scope    TEXT DEFAULT 'private';
ALTER TABLE cold_memory ADD COLUMN agent_id TEXT;
ALTER TABLE cold_memory ADD COLUMN scope    TEXT DEFAULT 'private';

CREATE INDEX idx_hot_agent  ON hot_memory(agent_id, target);
CREATE INDEX idx_hot_scope  ON hot_memory(scope);
CREATE INDEX idx_cold_agent ON cold_memory(agent_id);
CREATE INDEX idx_cold_scope ON cold_memory(scope);
```

### 3.2 三个 scope 语义

| scope | 谁能召回 | 写入约束 | 用途 |
|---|---|---|---|
| `private` | 仅写入者 agent_id | 任何 agent | **默认**。私密偏好、个人风格 |
| `shared` | 所有 agent | 任何 agent，UI 高亮提示 | 协作记忆，如"BrickHub 项目状态" |
| `global` | 所有 agent | 任何 agent，带审计 | 通用常识，如"老王是微软顾问" |

**召回 SQL 模板**：
```sql
WHERE (agent_id = :caller OR scope IN ('shared','global'))
  AND ...
```

### 3.3 agent_id 命名规则

- 自由命名（首次 POST 自动登记到 `agents` 表）
- 建议格式：`<owner>-<role>`，如 `pei-小虾`、`pei-小贝`、`team-builder-bot`
- 一个 `agents` 元表记录注册时间、最后活跃时间、累计记忆数

## 4. 关键决策（每条都有取舍）

### D1：本地 SoT vs 海马体作主存
**选**：本地 JSON Lines 作主存。  
**取舍**：磁盘冗余 ↔ **用户主权 + 灾难恢复 + 可审查**。后者远高于前者。

### D2：异步发件箱 (Outbox Pattern)
```
agent 写记忆 → 立即返回 (<1ms)
            ↓
       本地 outbox.db (SQLite WAL)
            ↓
     后台 worker 批量推海马体
            ↓
     海马体挂了 → outbox 堆积
     海马体恢复 → 自动 drain
```
**取舍**：召回有秒级延迟（写入后 ≤5s 可搜）↔ **零阻塞 + 零丢失**。

### D3：双层召回（缓存 + 短超时 + 跳过）
```
Layer 1：本地 LRU 命中 → 0ms
Layer 2：异步预取（上一轮 LLM 输出时预测下一轮 query）
Layer 3：极短 200ms 超时 + 不命中跳过
```
**取舍**：偶尔首次召回不全 ↔ **主链路 P99 < 50ms**。"宁缺勿等"是无感知的关键。

### D4：Hippo Wire Protocol v1（HTTP/JSON）
```http
POST /v1/memories          写入（异步入队）
POST /v1/recall            召回（短超时）
GET  /v1/memories/audit    审查面（分页+筛选）
POST /v1/sessions/snapshot 会话快照
GET  /v1/agents            agent 列表 + 统计
```
- 所有请求带 `X-Agent-ID` header
- 版本协商：`Accept: application/vnd.hippo.v1+json`
- v1 端点至少保留 12 个月，破坏性变更走 v2

**取舍**：HTTP/JSON 比 gRPC 慢 ↔ **人人可调，curl 即可**。

### D5：SDK 而非 Plugin
```python
from hippo_sdk import HippoClient

hippo = HippoClient(agent_id="小虾", server="http://localhost:8200")
hippo.remember("用户喜欢深色模式")          # fire-and-forget
mems = hippo.recall("用户偏好", timeout_ms=200)
```
- **SDK 责任**：发件箱、缓存、协议转换、容灾兜底（约 300 LOC）
- **Agent 责任**：决定何时调（业务逻辑，约 50 LOC 胶水）

适配器层：
- `hermes-hippo-plugin`：当前 plugin 重写为 SDK 包装
- `hippo-mcp-server`：MCP 协议包装，给 Claude Code/Cursor
- `hippo-cli-bridge`：通过 stdin/stdout 给任何 CLI agent

## 5. 四大切片治理 API

### 5.1 过滤召回
```http
POST /v1/recall
X-Agent-ID: 小虾
{
  "query": "BrickHub UI",
  "filter": {
    "agent_id": "小虾",                 // 可选，默认=自己
    "scope": ["private","shared"],     // 可选，默认全部
    "include_global": true,
    "time_range": {"after":"2026-04-01"}
  },
  "limit": 5
}
```

UI 筛选下拉：「全部 / 小虾 / 小贝 / 共享池 / 全局」

### 5.2 导出（按切片）
```bash
hippo export --agent 小虾 --scope private,shared --out 小虾.jsonl
hippo export --all --out full-dump.jsonl
hippo export --scope shared --out 团队共享.jsonl
hippo export --time-range 2026-04-01..2026-04-21 --out 4月.jsonl
```
JSON Lines 格式，每行含 id/agent_id/scope/content/created_at/embedding。导出即审计。

### 5.3 备份（物理 + 逻辑双轨）
```bash
# 物理备份：整库快照（最快，含所有 agent）
hippo backup --type physical --out memory-20260421.db

# 逻辑备份：按 agent 拆分（便于迁移/审查）
hippo backup --type logical --split-by agent --out-dir ./backup/
# 产出：
#   ./backup/manifest.json
#   ./backup/小虾.jsonl
#   ./backup/小贝.jsonl
#   ./backup/shared.jsonl
#   ./backup/global.jsonl
```

物理备份继续走现有 daily cron + GitHub 备份链路（不动）。  
逻辑备份用于迁移、灾难恢复、人工审查。

### 5.4 还原与合并
```bash
# 还原指定 agent 的记忆
hippo restore 小虾.jsonl --agent 小虾 --strategy skip-existing

# Agent 重命名/合并：把 小虾+小贝 都迁到新 agent 小蟹
hippo restore 小虾.jsonl --remap-agent-id 小虾→小蟹
hippo restore 小贝.jsonl --remap-agent-id 小贝→小蟹 --strategy dedup

# Scope 迁移：把私密记忆批量改为共享（团队化）
hippo migrate --from-scope private --to-scope shared --agents 小虾,小贝
```

**合并冲突策略**：
| 策略 | 行为 |
|---|---|
| `skip-existing` | 内容相同跳过（**默认，安全**） |
| `dedup` | 语义相似 > 0.95 视为同一条，保留较新 |
| `keep-both` | 都保留，标记冲突，交人工审查 |
| `overwrite` | 强制覆盖（谨慎，需 `--force`） |

## 6. 容灾矩阵（最关键的一节）

| 故障场景 | v0.3 行为 | v0.4 行为 |
|---|---|---|
| 海马体进程崩了 | plugin 报错被吞，召回为空，新记忆走 WAL | SDK outbox 持久化，agent 主链路完全无感，恢复自动补齐 |
| 海马体磁盘满了 | 写入失败 | outbox 堆积告警，agent 继续跑 |
| 海马体所在机器宕机 | 网络超时 2s 阻塞每条消息 | SDK 探测 unhealthy，进入 degraded 模式（召回返回空，写入入 outbox） |
| 海马体 DB 损坏/误删 | **全部记忆永久丢失** | **本地 SoT 仍在**，`hippo rebuild --from-sot` 重建 |
| Agent 进程崩了 | 内存中未写入的丢失 | outbox 是 SQLite，重启后自动 drain |
| 多 agent 并发竞争 | SQLite 锁等待 | 每 agent 独立 outbox，server 端 WAL 模式，QPS 100+ 无压力 |
| 海马体被删库勒索 | 数据丢光 | 本地 SoT + GitHub 物理备份双重保险 |

**核心保证**：**记忆主权归 agent**。海马体只是"加速器/增强器"，不是"持有者"。

### 本地 SoT 目录结构
```
~/.hippo-sot/
├── agents.json                    # 注册的 agent 元数据
├── 小虾/
│   ├── memories.jsonl             # 全量记忆，追加写，永不删
│   ├── outbox.db                  # 待推海马体的发件箱（SQLite WAL）
│   ├── recall_cache.db            # 本地召回缓存
│   └── snapshots/
│       ├── 20260421-1200.jsonl    # 周快照（容灾）
│       └── ...
├── 小贝/
│   └── ...
└── shared/
    └── memories.jsonl
```

## 实施进度

### ✅ 2026-04-21 — Quick-wins 落地（v0.2 SDK）

**背景**：架构师复核给出 ROI 优先级清单，决定先做"立竿见影 + 防灾"四件事，v0.4 大重构推迟到 dogfood 数据攒齐后再启动。

**落地清单**：

1. **召回延迟从 2000ms → 500ms 硬上限**（client 默认 + env 可调 `HIPPO_SEARCH_TIMEOUT`）
2. **LRU + TTL 召回缓存**（256 entries / 60s TTL，env 可关 `HIPPO_CACHE_CAPACITY=0`）
   - 实测：cache hit p50 = 0.05ms，cache miss p50 = 7ms（快），首次新 query p95 ≈ 430ms
3. **HippoMetrics 全链路指标**（counters + 延迟 p50/p95/p99 + cache hit rate）
   - 暴露通过 `client.stats()`，agent 可任意 render 到 dashboard / 日志
   - 关键指标：`recall_count`, `recall_cache_hit/miss`, `recall_timeout`, `memories_injected_total`, `write_wal_fallback`
4. **OpenHippo memory.db 每日自动备份**
   - 仓库：[wpsl5168/hippocampus-backup](https://github.com/wpsl5168/hippocampus-backup)（private）
   - 脚本：`~/hippocampus-backup/backup.sh`（sqlite3 .backup crash-safe）
   - cron job_id: `413a686c307b` 每日 UTC 18:00 = 北京 02:00
   - 保留：30 天 daily snapshots + latest 永久
   - 用了现成 skill `sqlite-github-backup`

**SDK 文件结构变更**：
```
clients/hippo-sdk-python/src/hippo_sdk/
├── __init__.py    # bumped to 0.2.0
├── client.py      # +cache integration +metrics hooks
├── config.py      # +cache_capacity/cache_ttl_sec, search_timeout 默认 0.5s
├── cache.py       # NEW — RecallCache (LRU+TTL, thread-safe)
├── metrics.py     # NEW — HippoMetrics (counters + percentile latencies)
├── transport.py   # 不变
├── wal.py         # 不变
└── types.py       # 不变
```
