## 1. 问题陈述（不变）

OpenHippo 当前所有"删除"语义走物理 DELETE。F5 零信任铁律：**never hard delete, only mark dormant**。三处现存物理删点：

| 文件 | 行 | 路径 |
|---|---|---|
| `core/storage.py` | 256 | `hot_remove()` |
| `core/storage.py` | 389 | `cold_delete()` |
| `core/dream.py` | 562 | forget 路径独立写 dormant（不算物理删但绕过统一入口） |

---

## 2. 设计目标（修订）

**所有软删收口于 `storage._mark_dormant`；唯一物理删收口于 `dream.purge_overdue_dormant`；中间留分级审查窗口（按 marked_reason 差异化）。**

### 核心原则（v0.3 修订）

1. **唯一软删入口** = `_mark_dormant`：用户 remove / API delete / dream forget / 测试 teardown 全部经此
2. **唯一物理删入口** = `purge_overdue_dormant`：周期性消费过期 dormant
3. **可追溯**：dream_actions append-only，details JSON 含 actor/reason/source_tier
4. **可恢复**：审查窗口内走 `/v1/dream/restore/{id}`
5. **召回过滤 dormant**：cold_search / vec_search / hybrid 三路径全过滤（默认 False）
6. **禁后门**：pattern 删除必须走 `_mark_dormant`

## 4. 实现细节

### 4.1 storage._mark_dormant（B2/B3/M6 修正）

```python
def _mark_dormant(self, memory_id: str, *, actor: str, reason: str,
                  source_tier: str, original_id: str | None = None,
                  dream_run_id: str | None = None) -> dict:
    """统一软删入口。所有 mark dormant 必经此函数。

    dream_run_id: 可选。dream pipeline 已有 run_id 时透传；
                  manual 调用（用户 remove / API delete）时内部生成 synthetic run。
    """
    conn = self._get_conn()
    now = _iso(time.time())

    # FK 约束: dream_run_id 必须存在于 dream_runs，否则 INSERT 失败
    if dream_run_id is None:
        dream_run_id = f"manual:{uuid.uuid4().hex}"
        conn.execute(
            """INSERT INTO dream_runs
               (id, started_at, finished_at, status, config_snapshot,
                candidates_count, clusters_count, consolidated_count, forgotten_count)
               VALUES (?, ?, ?, 'manual', '{"manual":true}', 0, 0, 0, 0)""",
            (dream_run_id, now, now),
        )

    conn.execute(
        "UPDATE cold_memory SET dream_status='dormant', last_dream_at=? WHERE id=?",
        (now, memory_id),
    )
    conn.execute(
        """INSERT INTO dream_actions
           (dream_run_id, action, memory_id, details, created_at)
           VALUES (?, 'mark_dormant', ?, ?, ?)""",
        (dream_run_id, memory_id,
         json.dumps({"actor": actor, "reason": reason,
                     "source_tier": source_tier, "original_id": original_id}),
         now),
    )
    conn.commit()
    return {"id": memory_id, "status": "dormant", "dream_run_id": dream_run_id}
```

### 4.3 dream.purge_overdue_dormant（M3/M7 修正 + v0.3 hotfix）

```python
# Retention 按 marked_reason 差异化（reason 名严格对齐 §4.2 改造点）
RETENTION_DAYS = {
    "legacy_test_residue": 0,    # backfill 残渣立即清
    "hot_remove": 14,            # 用户 remove → archive→cold→dormant
    "cold_delete": 7,            # API DELETE /v1/memories/{id}
    "forget_decay": 30,          # dream 自然衰减
    "consolidate": 30,
    "_default": 14,
}

class Dream:
    def purge_overdue_dormant(self, batch_size: int = 100) -> dict:
        """全系统唯一物理删入口。"""
        conn = self.storage._get_conn()
        now = time.time()

        # 0. 建 purge run（满足 008 FK），全函数共用一个 run_id
        run_id = f"purge:{uuid.uuid4().hex}"
        now_iso = _iso(now)
        conn.execute(
            """INSERT INTO dream_runs
               (id, started_at, finished_at, status, config_snapshot,
                candidates_count, clusters_count, consolidated_count, forgotten_count)
               VALUES (?, ?, ?, 'purge', '{"purge":true}', 0, 0, 0, 0)""",
            (run_id, now_iso, now_iso),
        )

        # 1. 取候选 + 最新一条 mark_dormant action 的 reason
        rows = conn.execute("""
            SELECT cm.id, cm.last_dream_at,
                   (SELECT json_extract(da.details, '$.reason')
                      FROM dream_actions da
                     WHERE da.memory_id = cm.id AND da.action = 'mark_dormant'
                     ORDER BY da.id DESC LIMIT 1) AS reason
              FROM cold_memory cm
             WHERE cm.dream_status = 'dormant'
             LIMIT ?
        """, (batch_size,)).fetchall()

        purged = []
        for row in rows:
            reason = row["reason"] or "_default"
            retention = RETENTION_DAYS.get(reason, RETENTION_DAYS["_default"])
            last = _parse_iso(row["last_dream_at"])
            if (now - last) < retention * 86400:
                continue

            # 2. 物理删 —— 单事务包裹，禁止内嵌已 commit 的辅助函数
            #    vec_delete() 内部有 conn.commit() 会破坏事务，必须改用内联 SQL
            try:
                conn.execute("BEGIN")
                conn.execute("DELETE FROM cold_memory_vec WHERE memory_id=?", (row["id"],))
                conn.execute("DELETE FROM cold_embeddings WHERE memory_id=?", (row["id"],))
                # cold_memory 主表删除 → cold_memory_ad trigger 自动级联 FTS
                conn.execute("DELETE FROM cold_memory WHERE id=?", (row["id"],))
                conn.execute(
                    """INSERT INTO dream_actions
                       (dream_run_id, action, memory_id, details, created_at)
                       VALUES (?, 'purge_dormant', ?, ?, ?)""",
                    (run_id, row["id"],
                     json.dumps({"reason": reason, "retention_days": retention}),
                     _iso(time.time())),
                )
                conn.execute("COMMIT")
                purged.append(row["id"])
            except Exception:
                conn.execute("ROLLBACK")
                raise

        # 3. 完整性兜底
        chk = conn.execute("PRAGMA integrity_check").fetchone()[0]
        if chk != "ok":
            raise RuntimeError(f"DB integrity broken after purge: {chk}")
        return {"run_id": run_id, "purged": len(purged), "ids": purged}
```

**关键约束**（v0.3 hotfix 沉淀的血教训）：
- `vec_delete()` 在 `storage.py:618` 内部 `conn.commit()`，**禁止**在事务里调用，必须内联 SQL
- `run_id` 必须在循环外生成且对应 `dream_runs` 真实行存在（FK 强约束）
- 函数挂在 Dream 类上，签名为 `(self, batch_size=100)`，不是裸函数
