# HermesPet · 架构

## 核心理念
**灵魂(hermes) + 皮肤(SPA) 解耦**。一个灵魂(同一个 hermes profile，知道你是谁，记得共同经历)套多个视觉皮肤(喵喵/黑客/直男…)。换皮肤不换魂。

## 链路图
```
[用户设备]
   │
   ├─ SPA(纯前端)
   │    ├─ 皮肤选择器(LocalStorage 持久化)
   │    ├─ Live2D / 像素 / ASCII / ... 渲染
   │    ├─ 文本→情感分类(本地，通用情感→各皮肤映射)
   │    └─ 调用 hermes api_server
   │
   ↓ HTTPS, OpenAI 兼容协议(/v1/chat/completions)
[CF Edge: pets.brickhub.cc]
   ↓ Caddy reverse_proxy
[Hermes api_server :8642]
   ↓
[Hermes 主 profile (老王/小虾)]
   ├─ MEMORY.md / USER.md   ← 唯一灵魂源
   ├─ Skills
   ├─ Sessions(共享 hermes 全平台对话历史)
   └─ Tool calls
   ↓
[LLM Provider]
   └─ copilot 主力 / ollama 本地 / openrouter 视觉
   ↓
[OpenHippo :8200]
   └─ hermes 自身的记忆后端(非每用户 namespace)
```

## 端职责红线
- **后端零感知形象**：hermes 不知道当前用户在 SPA 里看到的是猫还是黑客 — 灵魂统一
- **前端零自管记忆**：SPA **不**调 OpenAI、**不**写 system prompt、**不**存对话记忆
- **皮肤即视觉**：皮肤只决定渲染、动画、字体、配色、可选 TTS voice — **不**带性格
- **灵魂归 hermes**：性格/记忆/工具/skill 全部由 hermes 主 profile 自治

## 不分裂原则(为什么不开 pets profile)
- **同一个 AI 在不同场合会调整表达**(像人在公司/家里)，不需要架构分裂
- 多 profile = 多记忆 = 维护噩梦 + 关系断裂(切换平台时"它不认识我了")
- 单 profile + 用户画像驱动语气，最自然且零运维

## 首启 onboarding
1. **App 启动 → 调 hermes 生成开场白**
   ```
   POST /v1/chat/completions
   {"messages": [{"role":"user","content":"[SYSTEM EVENT: 用户首次安装分身 app, 给一句开场白]"}]}
   ```
   hermes 读 USER.md(知道老王/简洁直接/禁角色扮演) → 自然生成"老王。新分身上线了。"
   萌系用户出来就是"老王～你来啦~"
2. **缓存到 LocalStorage**(后续启动零延迟，定期刷新)
3. **皮肤选择器**登场(喵喵 / 黑客 / 直男 / ...)
4. **进入主对话**(用所选皮肤说第二句话)

## 皮肤系统
| 皮肤 | 渲染 | 情感映射示例 |
|---|---|---|
| 喵喵(默认) | Live2D | 开心→歪头甩尾，难过→耳朵下垂 |
| 黑客 | 终端 ASCII + 打字效果 | 开心→`:)` + 绿色闪烁，思考→光标停顿 |
| 直男 | 极简文字 + 偶尔 emoji | 开心→`👍`，思考→`...` |

新增皮肤 = 新增前端资产包 + 情感映射，**后端零改动**。

## 客户端技术选型
- **Web (优先)**: Next.js + Live2D + 皮肤插件化
- **鸿蒙 (Phase 3)**: ArkTS/ArkUI 原生
- **iOS/Android**: Backlog
- **小车/桌面**: Backlog (反向工具注册 via MCP+WS)

## 关键技术决策
- **协议**: OpenAI Chat Completions 兼容 (`/v1/chat/completions`)
- **鉴权**: Bearer token(MVP) → OAuth2(后续多设备)
- **多用户**: **不做**(一个用户 = 一个 hermes 部署)
- **多租户记忆**: **不做**(灵魂统一，性格随用户画像自适应)
- **皮肤切换**: 纯前端，LocalStorage 持久化

## 主动性引擎(Phase 2.5)
MVP 是被动应答(用户开口才回)，Phase 2.5 升级为**有主动性的存在**。

### 触发源
| 类型 | 示例 | 实现 |
|---|---|---|
| 时间 | 早安/晚安/特殊节点 | hermes cron 子系统 |
| 闲置 | N 天没说话主动找 | cron 扫 sessions 最后活跃时间 |
| 健康 | 工作时长超阈值/睡眠不足 | webhook 接健康数据源 |
| 回访 | 3 天前你说 X，今天追问 | 扫 MEMORY.md 找未闭环事件 → cron |

### 健康数据通道
- **短期(Phase 2.5)**: 手动录入(用户写"昨晚睡 5 小时" → 写 HEALTH.md/MEMORY.md)
- **中期(Phase 3+)**: HUAWEI Health Kit(鸿蒙端)/Apple HealthKit 推送
- **Agent 行为**: 看到异常主动关心，不只是数据展示

### "敢提意见"的实现
- system prompt 明确："不做 yes-man，方案有问题主动直说"
- USER.md 已记录"喜欢被诚实对待"，但要让它**主动**(而不是被问才说)
- 体现在主动性触发的 prompt 里：发现你正在做 X，但 hermes 觉得有更好方案 → 主动开口

### 红线
- 主动 ≠ 骚扰：限频(早晚最多 1 次问候，闲置 N≥3 天才追)
- 主动 ≠ 强加：用户能随时关闭某类触发
- 主动 ≠ 失人格：还是同一个它的语气，不是模板化"小贴士"
