## 一、Mecabricks 级高级渲染（Three.js PBR）

目标：在 WebGL/Three.js 中实现逼真的乐高 ABS 塑料质感。

### 1.1 乐高 ABS 塑料的 PBR 材质参数
乐高积木使用的是 ABS（丙烯腈-丁二烯-苯乙烯共聚物）塑料。在 Three.js 中，我们使用 `MeshPhysicalMaterial` 或 `MeshStandardMaterial` 来模拟：

- **Color (BaseColor):**  直接读取 LDraw 的颜色值（需转至 sRGB 色彩空间）。
- **Roughness (粗糙度):** 约 `0.1` - `0.3`。全新积木粗糙度低（偏光滑，约 `0.15`），旧积木粗糙度变高。
- **Metalness (金属度):** 除非是特殊金属件（如金、银色），普通 ABS 积木的 Metalness 设为 `0.0`。
- **Clearcoat (清漆层):** （可选且关键）ABS 塑料有一层微妙的表面反光。将 `clearcoat` 设为 `0.5 - 1.0`，`clearcoatRoughness` 设为 `0.1 - 0.2` 可以极大地提升质感。
- **IOR (折射率):** ABS 塑料的 IOR 通常在 `1.54` 左右。

**参考代码片段：**
```javascript
const absMaterial = new THREE.MeshPhysicalMaterial({
    color: ldrawColor,
    roughness: 0.15,
    metalness: 0.0,
    clearcoat: 0.8,
    clearcoatRoughness: 0.1,
    ior: 1.54
});
```

### 1.2 表面细节与微瑕疵 (法线贴图 Normal Map)
完美的表面是不真实的。Mecabricks 的真实感很大程度上来源于表面瑕疵。

- **指纹与微划痕贴图：** 准备几张无缝平铺的（Seamless）指纹、灰尘或微小划痕的法线贴图（Normal Map）和粗糙度贴图（Roughness Map）。
- **UV 映射：** 积木通常使用简单的 Box Projection 或 Triplanar Mapping 来映射这些瑕疵贴图，避免为每个复杂形状手动展 UV。
- **在 Three.js 中的应用：**
```javascript
// 加载贴图并设置平铺
const normalMap = textureLoader.load('path/to/fingerprints_normal.png');
normalMap.wrapS = normalMap.wrapT = THREE.RepeatWrapping;

absMaterial.normalMap = normalMap;
absMaterial.normalScale.set(0.5, 0.5); // 控制瑕疵的明显程度
```

### 1.3 边缘倒角（Bevel）处理
现实中的乐高积木边缘不是绝对锐利的 90 度，而是有微小的倒角（约 0.1mm - 0.2mm），这使得边缘能捕捉到高光（Edge Highlight）。

**实现路径：**
1. **模型预处理（推荐方案）：** 在导入阶段或资产准备阶段，使用 3D 软件（如 Blender）或脚本为基础 LDraw 零件库生成倒角后的几何体（Bevel Geometry）。虽然这会增加顶点数，但在现代 WebGL 性能下，使用 InstancedMesh 渲染大量零件是可行的。
2. **法线烘焙贴图（Baking）：** 使用带有倒角法线信息的贴图。
3. **屏幕空间倒角着色器（Screen-Space Bevel Shader）：** 技术难度较高，通过修改材质的 Shader 动态计算边缘法线，性能开销较小但效果不如真实几何体。

### 1.4 凸起（Stud）上的 LEGO Logo 高亮
乐高凸起顶部的 "LEGO" 字样是标志性特征。如果用真实模型构建这个极小的字样，多边形数量会爆炸。

**实现路径（法线贴图方案）：**
- 制作一张包含 LEGO Logo 凸起效果的法线贴图。
- 仅将此材质应用于凸起（Stud）的顶部平面。
- 在 LDraw 的 Three.js 解析器中，通常可以将 Stud 的顶面分离出来，赋予一个独立的材质（带有 Logo Normal Map）。

## 二、动态分步图纸生成算法（对标 LPub3D）

目标：根据 LDraw 数据自动生成拼搭图纸。

### 2.1 拼搭步骤（Steps）的自动拆解

**基于 `0 STEP` 指令（显式步骤）：**
LDraw 格式本身支持在文件中插入 `0 STEP` 作为步骤分隔符。如果原文件（如 MPD 文件）已经包含了良好的步骤信息，最直接的方法是：
- 解析器在读取文件时，遇到 `0 STEP` 就划分出一个新的步骤对象。
- 每个步骤对象包含该步骤新增的零件列表，以及当前模型的完整状态。

**基于拓扑与碰撞依赖的自动分层（隐式步骤 - 高级方案）：**
如果 LDraw 文件没有包含 `0 STEP`，我们需要自动推导步骤：
1. **Z 轴高度排序：** 最基础的启发式算法。优先放置 Y 轴（LDraw 中向下的轴）较小的零件（即底部的零件）。
2. **包围盒干涉与连接分析：** 构建零件间的依赖图（Dependency Graph）。如果零件 A 必须插在零件 B 之上，则 A 依赖 B，B 必须在 A 之前的步骤拼搭。
3. **分组策略：** 每次将 5-10 个无相互依赖且位置相近的零件归为一个 Step。

### 2.2 最佳摄像机视角计算（防遮挡）

在生成每一页图纸时，摄像机需要清晰展示**当前步骤新增的零件**。

**算法路径：**
1. **初始视角设定：** 通常图纸使用固定的等轴测视角（Isometric View，例如俯仰角 30 度，偏航角 45 度）。
2. **遮挡检测（Raycasting）：**
   - 从摄像机向当前步骤“新增的零件”的中心点发射射线（Raycast）。
   - 如果射线击中了“已存在的旧零件”，说明新增零件被遮挡。
3. **视角的自适应旋转：**
   - 当检测到遮挡时，围绕模型的中心水平旋转摄像机（例如每次增加 45 度），重新进行遮挡检测，直到找到一个射线不被遮挡的视角。
4. **包围盒自适应缩放（Frustum Fitting）：** 计算当前已拼搭模型的总体包围盒（Bounding Box），调整摄像机的 `zoom` 或 `position`，确保整个模型正好充满视口，且留有边距供 BOM 使用。

### 2.3 动态生成零件清单（BOM / Callouts）

每个步骤需要一个悬浮的清单（Callout）展示本步骤需要的零件类型和数量。

**实现路径：**
1. **数据提取：** 对于当前 Step，遍历新增零件列表，按照 `零件ID（Part Number）` 和 `颜色（Color）` 进行分组统计（Group By）。
   - `[{ partId: '3001.dat', color: 4, count: 2 }, ...]`
2. **2D 渲染输出：**
   - **方案 A（离屏渲染）：** 在后台启动一个小的隐藏 WebGL 上下文，加载这些单个零件，调整好光照和等轴测视角，渲染出 2D 缩略图（Data URL / PNG），再与数量文本结合渲染到 Canvas 或 DOM 上。
   - **方案 B（预渲染图库）：** 提前渲染好所有 LDraw 零件各颜色的缩略图存放在服务器/CDN，前端直接通过 URL 拼接请求图片进行排版。（推荐，速度最快，对标 Rebrickable 的体验）。
3. **布局（Layout）：** 在前端图纸画布的角落（通常是左上或右上），使用 DOM/React 组件将缩略图和数量（如 "2x"）组合排列。
