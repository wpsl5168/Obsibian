## 0. 摘要（Executive Summary）

2024–2026 的 [[AI Agent]] 热点正在从“能跑的 demo”转向“可控、可观测、可复现、可部署”的工程体系。主线可以概括为三句话：

1) **控制流显式化**：从单体提示词驱动 → **Graph/Workflow**（分支、循环、重试、checkpoint、长任务）。
2) **连接标准化**：从每接一个工具写一次适配 → **协议化/生态化**（[[MCP]] 一类）
3) **质量门禁化**：从“看起来能用” → **Tracing/Evals/HITL/Guardrails** 成为上线必需品。

如果你只想记住一个落地原则：

> 先把“产物（artifact）”定义清楚，再给每个产物配一个负责到底的 agent；让 agent 通过**契约（结构化输入输出）**沟通，而不是聊天。

## 2. 适用范围（你会用到它的场景）

- 你要做：AI 助手 / [[AI Agent]] 工作流 / 多 agent 协作系统
- 你要落地到：真实业务系统（有数据、有权限、有成本、有风控）
- 你要优化：稳定性、可观测、成本、以及“能持续迭代”

不适用（或需要额外方法）的场景：
- 纯学术对话型多智能体（侧重博弈/群体行为建模）
- 完全离线、无工具调用、无外部系统对接的单轮生成任务

## 主题 1：编排从黑盒到显式工作流（Graphs / Workflows） {#theme-1}

### 1) 概念
- 用“图/工作流”显式表达 agent 系统的控制流：
  - **分支（branch）**：根据意图/风险/分类走不同路径
  - **循环（loop）**：直到满足条件或达到预算上限
  - **重试（retry）**：工具失败、限流、临时错误
  - **子图（subgraph）**：把可复用子流程封装成模块
  - **durable execution / checkpoint**：可恢复、可回放

### 2) 解决了什么问题
- 单 agent 纯提示词：
  - 对长任务不稳定（上下文漂移、越做越偏）
  - 难以 debug（失败时只能“再试一次”）
  - 难以引入审批点（HITL）

### 3) 关键思路/落地要点
- **把“思考”与“流程”分离**：让 LLM 负责局部决策，把全局控制交给 workflow。
- **为每个节点定义输入输出 schema**（哪怕是简单 JSON）：可测试、可复现。
- **预算与停止条件**：迭代次数、工具调用次数、token/cost ceiling。

### 4) 常见坑
- 把图写成“另一种 prompt”：节点仍然做太多事，导致 debug 仍然困难。
- 没有状态模型（state）与持久化：线上宕机就丢上下文。

### 5) 一手来源
- LangGraph 官方：https://www.langchain.com/langgraph
- LangGraph GitHub：https://github.com/langchain-ai/langgraph
- Harrison Chase 公开视频入口（YouTube）：https://www.youtube.com/watch?v=DSdyqPzdlQU

## 主题 2：多 [[AI Agent]] 通讯走向异步消息与事件驱动 {#theme-2}

### 1) 概念
- 多 agent 不再是“串起来对话”，而是通过 **异步消息（async messaging）** 协作：
  - request/response
  - event-driven（广播/订阅）
  - long-running & proactive agent

### 2) 解决了什么问题
- **动态工作流**：中间结果决定下一个步骤（而不是固定流水线）。
- **规模化协作网络**：从 2-3 个 agent 扩展到更复杂拓扑。
- **可观测/追踪**：天然适配 tracing。

### 3) 工程实践建议
- 定义 message envelope：`task_id / parent_id / state_ref / budget / deadline`。
- 失败策略：超时、重试、幂等、降级（fallback）。

### 4) 一手来源
- Microsoft Research AutoGen：https://www.microsoft.com/en-us/research/project/autogen/
- AutoGen GitHub：https://github.com/microsoft/autogen

## 主题 4：工具/数据接入标准化：[[MCP]]（Model Context Protocol） {#theme-4}

### 1) 概念
- [[MCP]] 是连接 AI 应用与外部系统的开放协议。
- 类比“USB-C”：统一接口让工具/数据源可复用，降低生态碎片化。

### 2) 解决了什么问题
- 每接一个系统写一个 connector，难以维护与规模化。
- 标准化后更容易在协议层做安全与权限控制。

### 3) 典型落地方式
- [[MCP]] Server：暴露数据/工具（GitHub、DB、Drive、Browser 等）
- [[MCP]] Client：你的 agent/应用

### 4) 一手来源
- Anthropic 官方发布：https://www.anthropic.com/news/model-context-protocol
- [[MCP]] 文档 Intro：https://modelcontextprotocol.io/docs/getting-started/intro

## 主题 5：交接（handoff）与分诊（triage）成为标配架构 {#theme-5}

### 1) 概念
- 把能力拆成多个 agent，并明确“谁接手/何时移交”：
  - 入口 triage（分类、风险判断、路由）
  - 专家 agent（检索、代码、数据、写作、合规）

### 2) 解决了什么问题
- 单体 prompt 膨胀与行为不可控。
- 专家角色更容易测试与治理。

### 3) 一手来源
- OpenAI Swarm（handoffs 原语，教育框架）：https://github.com/openai/swarm
- OpenAI [[AI Agent]]s SDK（生产化演进）：https://github.com/openai/openai-agents-python

## 主题 6：SWE [[AI Agent]]：从写代码到修 Issue（基准驱动闭环） {#theme-6}

### 1) 概念
- 目标从“生成代码片段”升级为“完成软件工程闭环”：Issue → 定位 → 修改 → 测试 → PR。

### 2) 解决了什么问题
- 代码生成不能保证可运行、可合并、可回归。
- 工程任务需要：工具调用、环境操作、失败恢复。

### 3) 一手来源

- 论文（arXiv）：https://arxiv.org/abs/2405.15793

## 主题 8：可观测（Tracing）+ 评测（Evals）成为必选项 {#theme-8}

### 1) 概念
- Tracing：把一次 run 的轨迹（思考、工具、状态转移）记录下来。
- Evals：让改动能被量化对比，避免“体感变好了”。

### 2) 解决了什么问题
- 线上偶现错误难以复现。
- 随迭代质量波动难以控制。

### 3) 一手来源
- AutoGen（强调 observability/OTel）：https://www.microsoft.com/en-us/research/project/autogen/

## 主题 9：HITL + Guardrails：安全、合规与可控上线 {#theme-9}

### 1) 概念
- HITL：在关键节点加人工审批/修正。
- Guardrails：输入输出校验、敏感工具限制、策略与合规模块。

### 2) 为什么重要
- [[AI Agent]] 一旦接入“写操作”（发邮件、改配置、下单、删库）风险指数级上升。
- 儿童教育类产品还叠加隐私/内容安全要求。

### 3) 一手来源
- LangGraph（HITL）：https://www.langchain.com/langgraph
- OpenAI [[AI Agent]]s SDK（Guardrails/HITL/Tracing）：https://github.com/openai/openai-agents-python

## 主题 10：方法论常青：ReAct / Reflexion / ToT / SOP 多 [[AI Agent]] {#theme-10}

这类是“思想范式”：框架会变，但方法会长期影响工程实现。

### 10.1 ReAct（Reason + Act）
- 价值：用工具/行动减少幻觉，轨迹更可解释。
- 论文：https://arxiv.org/abs/2210.03629

### 10.2 Reflexion（语言反馈驱动的反思记忆）
- 价值：不微调权重，通过“语言反思 + episodic memory”提升下一轮表现。
- 论文：https://arxiv.org/abs/2303.11366

### 10.3 Tree of Thoughts（探索/回溯式推理）
- 价值：从贪心推理到搜索/回溯，提升规划与策略任务成功率。
- 论文：https://arxiv.org/abs/2305.10601

### 10.4 MetaGPT（把 SOP/组织流程编码进多 [[AI Agent]]）
- 价值：通过 SOP/角色校验减少级联幻觉，更贴近软件团队协作。
- 论文：https://arxiv.org/abs/2308.00352
