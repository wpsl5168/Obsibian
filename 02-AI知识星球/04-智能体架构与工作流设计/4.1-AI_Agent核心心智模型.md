# AI Agent 核心心智模型

## 核心概念

> [!note] 核心定义：AI Agent (智能体)
> 在大语言模型 (LLM) 语境下，AI Agent 是一个将 LLM 作为核心推理引擎（大脑），通过感知当前上下文，自主拆解任务、规划步骤，并调用外部工具执行以改变环境状态的自治系统。

相较于传统的静态 Prompt 问答，Agent 的核心特征在于**闭环的行动与反馈机制**。它能够根据环境返回的真实数据动态调整后续策略。

## 主流心智框架解析

目前工业界与学术界主流的智能体推理框架主要分为三种：ReAct、ToT 与 Reflexion。它们在复杂度与适用场景上有着显著差异。

### 1. ReAct (Reasoning and Acting)
ReAct 是由普林斯顿大学与 Google 团队提出的一种交错执行推理与动作的范式。
它强制要求模型在执行任何外部动作（Action）前，必须先输出一段内在的思考过程（Thought），然后观察（Observation）动作结果。这种 `Thought -> Action -> Observation` 的状态机流转极大地提高了动作的准确性。

> [!tip] 最佳实践
> 当任务属于线性依赖且工具调用逻辑较为直接时（如查天气、查库存），优先使用 ReAct 框架。它在延迟与效果之间取得了极佳的平衡。

### 2. ToT (Tree of Thoughts)
ToT 将推理过程建模为一棵搜索树。每一步决策都是树上的一个节点，LLM 需要生成多个候选分支，并使用启发式评估机制（Heuristic Evaluator）对分支打分，通过广度优先搜索 (BFS) 或深度优先搜索 (DFS) 寻找全局最优解。

### 3. Reflexion (反思机制)
Reflexion 引入了长时记忆与自我反思闭环。其架构由 Actor（执行者）、Evaluator（评估者）和 Self-Reflection（反思模块）组成。当任务失败时，反思模块会总结失败原因并存入上下文记忆中，指导下一次重试。

> [!warning] 性能陷阱
> Reflexion 与 ToT 均会产生巨大的 Token 消耗。在工程落地时，需严密监控 API 成本并设置合理的最大重试次数 (Max Retries)。

## 流派横向对比

| 框架范式 | 推理拓扑结构 | Token 消耗 | 核心优势 | 典型适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **ReAct** | 线性序列 (Linear) | 中等 | 延迟低，可解释性好 | 信息检索、基础 [[3.1-函数调用底层机制]] |
| **ToT** | 树状分支 (Tree) | 极高 | 全局寻优能力极强 | 复杂数学证明、多步骤创意写作 |
| **Reflexion** | 环形反馈 (Loop) | 偏高 | 具备纠错能力与经验进化 | 自动化代码修复、长期对弈环境 |
