# 大模型演进与主流架构体系

> [!note] 说明
> 本文档为小贝知识库自动整理和排版。用 .NET/SQL Server 老兵听得懂的语言，讲清楚大模型从何而来、现在走到哪了。

## 核心概念

大语言模型（Large Language Model, LLM）本质上是一个**超大规模的概率函数**——给定一串 Token 序列，输出下一个 Token 的概率分布。如果用 .NET 类比：`Func<Token[], ProbabilityDistribution<Token>>`。

模型的"大"体现在参数规模上。参数就像 SQL Server 里一张超级宽表的列数——列越多，能捕获的特征维度越多，但存储和查询成本也指数级上升。

### Transformer 架构：一切的起点

2017 年 Google 的 "Attention Is All You Need" 论文奠定了 Transformer 架构，它由 **Encoder**（编码器）和 **Decoder**（解码器）两大组件构成。

> [!tip] .NET 类比
> 把 Transformer 想象成一个 ASP.NET Core 的 Middleware Pipeline：
> - **Self-Attention 层** = 一个能"回头看"所有前序中间件输出的智能路由器
> - **Feed-Forward 层** = 每个中间件内部的业务逻辑处理
> - **残差连接** = `try-catch` 后的 fallback，保证信息不会在深层网络中完全丢失

### 架构演化三条路线

| 路线 | 代表 | 类比 | 特点 |
| :--- | :--- | :--- | :--- |
| **Encoder-Only** | BERT, RoBERTa | 像 SQL Server 的全文索引引擎，擅长"理解" | 适合分类、NER 等判别任务 |
| **Decoder-Only** | GPT 系列, Claude, LLaMA | 像一个自回归的 `StringBuilder.Append()`，逐字生成 | 当前主流生成式架构 |
| **Encoder-Decoder** | T5, BART | 像 ETL Pipeline，先 Extract/Transform 再 Load 输出 | 翻译、摘要等 Seq2Seq 任务 |

当前工业界几乎全面收敛到 **Decoder-Only** 架构，原因很简单：Scaling Law 在这条路线上验证效果最好。

## Scaling Law 与训练范式

### Chinchilla Scaling Law

DeepMind 2022 年提出的经验公式：**最优训练需要数据量和参数量同步扩大**。

```
最优数据量 ≈ 20 × 参数量
```

> [!tip] SQL Server 类比
> 这就像 SQL Server 的索引优化——光加内存（参数）没用，如果数据量（训练数据）跟不上，就像给一张只有 1000 行的表建了 20 个索引，纯属浪费。

### 后 Scaling Law 时代的新趋势

1. **Test-Time Compute Scaling**：不再只在训练时堆算力，而是在推理时通过"思考更久"来提升质量（o1/o3、Claude Extended Thinking）
2. **MoE 稀疏激活**：总参数大但每次推理只激活子集（LLaMA 4、Mixtral、DeepSeek-V3）
3. **蒸馏与量化**：大模型指导小模型训练，INT4/INT8 量化部署
