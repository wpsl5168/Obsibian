# 1) 最关键结论（先记住）
- **推理/聊天时：参数不会自动更新**。你输入一句话，模型只是“读取参数做计算”。
- **只有训练/微调时：参数才会更新**。必须有 loss、反向传播、优化器 step。

---

# 2) 从“用户输入一句话”开始：参数在哪里、怎么被使用？
以用户输入一句话为例：

## Step A：分词（tokenize）
- 文本被切成 token（子词/片段），变成 token id 序列。
- 这一步主要是规则/词表，**不涉及参数更新**。

## Step B：Embedding（查表）
- 每个 token id 去“词向量表”里取一行向量。
- 这个词向量表里的数字就是**参数的一部分**。

## Step C：多层 Transformer（重复 N 次）
每层大概两块：

### C1) Attention：在上下文里找关联
- 用权重矩阵把向量投影成 Q/K/V（这些矩阵是参数）
- 计算注意力后再投影回去（也是参数）

### C2) FFN/MLP：信息加工
- 用更大的矩阵做非线性变换（参数大头通常在这里）
- MoE 通常就是把这块替换成“多个专家 FFN + router”

## Step D：输出层（logits）
- 通过输出矩阵把隐藏向量映射到“词表分数（logits）”
- 采样/取最大值得到下一个 token

> 以上全程：参数被**读取**并参与矩阵乘法，但**不会被改写**。

---

# 3) 参数是什么？一句话定义
**参数（parameters）= 模型里可学习的数值（权重/偏置），训练会把它们调到更合适的位置。**

---

# 4) 参数什么时候会“自动更新”？（训练/微调流程）
要更新参数，必须出现下面这条链路：

1) Forward：按当前参数算出输出
2) Loss：拿输出和“目标答案/标签”对比，得到误差
3) Backward：算每个参数对误差的贡献（梯度）
4) Optimizer step：用梯度更新参数（例如 Adam）

**缺任何一步，参数都不会更新。**

---

# 5) 很容易混淆的三件事（务必分清）

## 5.1 参数 ≠ 上下文（context）
- **参数**：模型的长期记忆（训练后固定，推理时只读）
- **上下文**：本次对话临时给的信息（短期记忆，用完就没）

## 5.2 参数 ≠ 训练数据
- 训练数据是教材
- 参数是“学完后脑子里的连接强度/习惯”

## 5.3 参数（parameters）≠ 超参数（hyperparameters）
- 参数：训练学出来的
- 超参数：人手动设定的（学习率、batch size、层数、MoE expert 数、top-k 等）

---

# 6) “模型记住东西”的三种方式（工程落地版）

1) **上下文记忆**：把信息塞进 prompt（立刻生效，但受窗口限制）
2) **外部记忆 / RAG**：信息存知识库，检索后再喂给模型（可更新可删除可审计）
3) **微调/再训练**：把知识/风格写进参数（成本高、不可控、难删除）

---

# 7) 一个判断题：你的输入会不会被写进参数？
- 如果系统只是“聊天推理”：**不会**
- 如果系统明确执行了训练/微调流水线：**才会**

实操检查清单（只要看有没有）：
- label/目标答案
- loss
- backward
- optimizer step

---

# 8) MoE 补充：为什么要区分总参数 vs 激活参数
- **总参数（Total params）**：所有专家权重加起来
- **激活参数（Active params）**：一次 token 实际走到的 top-k 专家权重

因此 MoE 常见现象：总参数很大，但单次计算量不按总参数线性增长。
