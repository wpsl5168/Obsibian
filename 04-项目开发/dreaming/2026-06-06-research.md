## 待老王确认(P1)

| # | 位置 | 问题 | 风险 | 建议 |
|---|------|------|------|------|
| P1-1 | `validateGeometry` (488-618) | **零单测覆盖**,整个 88 LDU 阈值 + 8 角点 AABB 变换 + 碰撞/悬空判定无任何 unit test,仅 LDrawRenderer.report.test.js 间接调用 | 修一行阈值/坐标转换静默回归,LLM 重试反馈链路输出错误 | 补 5-10 个 fixture:平铺、合规叠层、xy 边缘相切、压重叠、悬空、旋转后 footprint 修正 |
| P1-2 | `MAX_PER_TYPE = 5` (491) | **静默吞错策略**:碰撞/悬空各只报前 5 条,超过完全丢弃。无 telemetry,无计数上报 | LLM 重试 prompt 拿到"看似已修"信号但实际仍有 N-5 处错误 → 用户看到坏模型 | (a) 在 errors 末尾加 `{ type:'meta', truncated:N }` 让 LLM 知道还有多少;(b) console.warn / pipeline metrics 加 `geometry_errors_truncated` 计数 |
| P1-3 | `validateGeometry` O(N²) (562-583, 591-604) | 大模型(>500 砖)双层嵌套 + `brickInfos.some(...)` → ~500² × 2 = 50 万次比较。无空间索引 | 100% LDraw 官方 .dat 模型(数千砖)pipeline 超时,validateGeometry 跑 1+秒卡 UI 主线程 | 提前构建 XZ grid bucket 或 KD-tree,O(N log N);或 N>1000 时跳过校验 + 标记 unverified |
| P1-4 | `resolvePartId` fallback `1x1` (393) | "Full-library compatibility: allow official .dat parts even if not in local alias table" → **任何未识别 .dat 都当 1x1 砖块渲染**。无 telemetry | 用户上传 5000 砖模型,4500 个被静默降级成 1x1 小方块,看起来"乱码 LEGO" | (a) 改 fallback 时 errors.push('未识别零件已用 1x1 替代');(b) pipeline 监控 fallback 率 >5% 触发告警 |
| P1-5 | `LDRAW_COLORS` 颜色码 `Medium Orange` 重复 (34, 95) | code=37 和 code=462 都叫 'Medium Orange',hex 也不同 (#F7AD29 vs #FFA70B),`mapPbrByLDrawMeta` name-based 匹配会撞 | 颜色名歧义,LDraw 官方应只有一个 462 是 Medium Orange 462,37 是 Bright Orange / Light Yellow | 核对 ldraw.org 官方表 → 37 重命名为正确名(可能是 "Light Orange Yellow"),保留 462 |

### 关键发现:Three.js r178 已发布
- WebGPU 在 Three.js 中是主流路径(2026)
- 一行迁移 `WebGLRenderer` → `WebGPURenderer`
