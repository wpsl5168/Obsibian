## P0/P1 报告项(需老王决策)

### P1-1: 大段文档"漂浮"在文件顶层(line 126-400 + line 145-163)
`buildSystemPrompt` 在 line 123 `\`;` + line 124 `}` 已闭合,但 line 126 起的 "## VERIFIED EXAMPLE / FORBIDDEN / MINIFIGURE PARTS / Hair Styles..." 整段(约 280 行)以 markdown 形式直接挂在 JS 文件顶层。
- 不报语法错(`node --check` pass、eslint pass),因为这些行被 JS 当成"标签 + 表达式语句"勉强解析(`##` 不是,但 `1 4 10 0 10 ...` 这种数字行被当成`1`、`4`、`10` 一堆 Number 字面量丢弃)。
- **运行时无效果**:这段文档**没人读到**,LLM 也看不到 — 它没在任何模板字符串里。
- 但有 LDraw 示例行如 `1 4  10 -8  10  1 0 0  0 1 0  0 0 1  3020.dat`,被 JS parser 拒了——实测 `node --check` 居然过(数字表达式语句是合法 ASI),完全静默。
- **业务影响**:VERIFIED EXAMPLE(3 层小房子完整 LDraw)+ FORBIDDEN 反例 + MINIFIGURE 零件表 — 这些本应在 LLM 看到的 prompt 里,现在全部失踪。
- **建议**:把 line 126-400 这段(止于 line 399 `...` 结尾的 build 函数前)合并进 `buildSystemPrompt` 的模板字符串,或拆成独立 markdown 文件 + import。涉及 LLM 输出契约,老王拍板。

### P1-2: `buildSystemPrompt` 与 `buildDSLSystemPrompt` 大段重复(VEHICLE/BUILDING/FIGURE 等 8 类目+ANTI-FLOAT+颜色码)
两个函数共写了 ~600 字重复 prompt 文本。任何分类规则变动需双改,易漂移。已观察到:`buildSystemPrompt` 颜色提示用"4(Red/primary), 7(Gray chassis)",`buildDSLSystemPrompt` 用"red=4, blue=1, ..., purple=22"(line 830)— 颜色码列表事实上已经不一致。
- **建议**:抽 const CATEGORIES / COLOR_CODES / ANTI_FLOAT_RULE 顶层常量,两个函数都引用。重构动 LLM 输入,留老王在 PR 里 review。

### P1-3: `buildSystemPrompt` 末尾 prompt 截断(line 122)
模板字符串收尾是 "Now, please generate the JSON DSL inside <DSL> tags." 但函数命名暗示输出 DSL JSON,而前文 `## DSL SYNTAX GUIDE`(line 56-95)定义的是基于 `{"name":..., "bricks":[...]}` 的 JSON,**没有任何 markdown JSON example 在 system prompt 里给到完整最终格式**(完整 example 在 buildDSLSystemPrompt 里)。两个 prompt 实际语义在分裂(line 100 retrievalContext 注入逻辑里两者择一)。
- **影响**:走 v6 旧 prompt(buildSystemPrompt)的 fallback 路径时,模型缺最关键的"输出例子",生成质量必降。
- **建议**:确认 v6 prompt 是否还在 prod 路径(grep `buildSystemPrompt` 调用方:`lib/pipeline/index.js:100` 当 `dslMode === false` 时走)。若 v6 已 deprecated → 删除函数;若仍用 → 补全 example。

### P1-4: prompt 内嵌中英文混杂可能触发 LLM 上下文切换
`buildUserMessage` 中文模板 `请为我设计:${userPrompt}`,但 retry hint 全英文(`The previous generation had ... error(s).`)。Claude/GPT 在中英混合 prompt 里输出语言不稳定,可能 LLM 把 comment 字段塞英文导致下游 UI 显示英文。
- **建议**:测一次中文 prompt 触发 retry 时,生成的 `name`/`comment` 字段是英文还是中文,决定是否统一成纯英文。

### 🔥 Next.js 14 安全紧急(P0)
Vercel 2026-05-11 GHSA-c4j6-fc7j-m34r 公告:
- **CVE-2026-44578 SSRF (8.6 HIGH)**:WebSocket upgrade handler 漏洞,**未认证**攻击者一次 HTTP 请求即可让 Next.js 进程对任何 server 可达 host 的 80 端口发 GET 并读响应 — **cloud metadata 服务暴露**(Azure VM 的 169.254.169.254 直接拿 token)
- **CVE-2026-44580 XSS**:beforeInteractive scripts 路径
- 受影响:**所有 13.4.13+ 自托管 Next.js,无 WAF mitigation**
- Vercel 明确:**v14 不会有 security release**,必须升 15.5.16+ 或 16.2.5+
- BrickHub 自托管在 Azure VM(brickhub.cc),**实打实暴露**

**两条升级路径**:
- 保守 A:`next@^15.5.18`(最低修补版本,React 18 兼容,大概率无 breaking)
- 激进 B:`next@^16.2.6` + R3F v9 + React 19 整套(同时跟齐 R3F,避开二次升级)

建议 A,因 BrickHub 还在 R3F v8 + 自定义 useFrame autofit 路径,跨 React 19 风险高。

### Three.js r184(2026-05)
r183 引入 RenderPipeline 节点式后处理替换旧 EffectComposer。当前未用 EffectComposer 故无影响。r184 安全可升,但留意 r3f v8 peer 上限(需查 package.json,通常 v8 锁 three ≤ r170 区间)。**先验证 peer 再动**。
