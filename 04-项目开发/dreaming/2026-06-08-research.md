## 待老王确认 (P1, 不自动改 — 涉及业务/架构判断)

### P1.1 PartsTray HTML5 draggable 触屏完全不可用 (Pitfall #39)
- 位置: `components/PartsTray.js:34` `<div draggable onDragStart={...}>`
- 现象: iOS/Android 触屏 long-press 默认走系统选择菜单不发 `dragstart`,**儿童 iPad 用户完全不能拖**
- onClick 兜底点击放置 OK,但**画布拖放定位**(沙盒拖到指定位置)移动端零可用
- 修法 (3 选 1):
  - (a) 引入 `react-dnd-touch-backend` 或 `@use-gesture/react`
  - (b) 改"点选+点画布定位"两步交互
  - (c) long-press 自绘 ghost 跟手元素

### P1.2 整页缺 Escape 键退出 + 焦点管理 (Pitfall #28 a11y 三件套)
- 沙盒拖拽中、放映深步骤,键盘用户被困
- 三按钮浮层无键盘焦点指示和快捷键
- 修法: useEffect 监听 keydown,Esc 退出当前模式 + 数字键 1/2/3 切换

### P1.3 errors 红色横幅缺 role='alert' + 无关闭按钮
- 位置: line 438-445
- 解析错误常驻顶部挡视图,屏幕阅读器无法捕获错误更新
- 修法: 加 `role='alert' aria-live='polite'` + dismiss 按钮 + 默认 5s 自动收起

### P1.4 onDrop 缺 schema 校验 (Pitfall #46.b 变体)
- 位置: line 290-296
- `e.dataTransfer.getData('application/brickhub-part')` 拿 uuid 后**零校验**就调 `handlePlacePart`
- 外部脚本/扩展可注入伪 uuid 污染 placedIds state
- 修法: `if (!unplacedParts.find(p => p.uuid === uuid)) return;`

### P1.5 useEffect deps=[model] (Pitfall #38 ref drift 变体)
- 位置: line 199
- `model` 来自 `useMemo([gallery, id])`,gallery 数组身份变化时 useEffect 会重跑(清 sandbox / 重 fetch ldraw)
- 当前 gallery 只 fetch 一次安全,但加 refetch 会触发不必要重置
- 修法: deps 改 `[model?.file, model?.id]`

## 依赖动态 ⚠️ 重要安全发现

### 🔥 Next.js: 双重 CVE 曝光 (P0 安全)
| 项 | BrickHub 现状 | 上游最新 |
|----|---|---|
| `next` | **^14.2.0** | 16.2.6+ / 14.2.x latest patch |

**两批 CVE 命中**:
1. **2026-05 安全发布** (Pitfall #6 Dependency 段已记) — 13 advisories,**14.x 全版本受影响、无 WAF mitigation**,必须升 15.5.18 / 16.2.6
2. **2026-11 新一批 13 CVE** (CVE-2026-23870 / 44572-44582 + 27980) — **14.0-16.1.6 全部曝光**,涵盖 RSC DoS、segment-prefetch auth bypass、SSRF via WebSocket、cache poisoning、CSP nonce XSS 等
- 一周内 GitHub 已有公开 PoC 集合 (next-16.2.4-pocs)
- 升级路径:
  - **A 保守 (低风险)**: 留在 14.x,升到该 minor 最高 patch (查 14.x 是否有 backport,大概率没有)
  - **B 激进 (推荐)**: 升 16.2.6+,但 BrickHub 用了 Pages Router + `next/dynamic` + `next/image`,需测全链路。涉及 React 19 升级,与 R3F v9 联动(见下)

### ⚠️ R3F v8 / three r183 peer drift (Pitfall Dependency 段)
| 项 | BrickHub 现状 | peer 范围 |
|----|---|---|
| `@react-three/fiber` | **^8.18.0** | peer three ≤ r158 |
| `three` | **^0.183.2** | 已远超 R3F v8 peer 上限 25 版 |
| `@react-three/drei` | ^9.122.0 | peer R3F v8 |
| `react` | ^18.3.0 | R3F v9 要求 React 19 |

**问题**: `three@0.183.2` 远超 R3F v8 peer 锁的 r158,理论上会触发 peer warning + 部分 r3f 内部 API drift。当前 BrickRenderer 跑通可能是侥幸或局部 API 没碰到 break。
**对策**:
- 短期: 验证 BrickRenderer 没有调到 r3f v8 不识别的 three r158+ 新 API
- 长期: 跟着 Next 16 升 React 19 同时升 R3F v9 + drei v10,一次性搞定。Next/React/R3F/drei 联动栈"整套一起升或都不升"

### Three.js r173+ 趋势 (低优先,可忽略)
- r173 已发布 (2025-01-30),WebGPU 在 Safari iOS 已落地 (2025-09)
- 迁移路径: `WebGLRenderer` → `WebGPURenderer` 一行改动 + TSL 着色器
- BrickHub 用 LDrawLoader 走 WebGL2,WebGPU 迁移**当前无收益** (LDraw 模型轻量、桌面/iPad 都流畅),可推迟
