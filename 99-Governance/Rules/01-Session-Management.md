# 会话管理（压缩/切会话策略）

目的：避免长会话导致上下文膨胀（模型变笨/忘前文），同时保证关键信息不丢。

## 触发条件（建议）
- Context 使用率 > 50%：开始准备压缩（把关键结论落到 GitHub）
- Context 使用率 > 70%：执行一次会话压缩（/compact 或 summarize）
- Context 使用率 > 85%：新开会话，引用 GitHub 中的“治理/记忆/索引”作为外部真相

## 压缩前必做
- 把当日关键决策/偏好/规则更新写入 Obsidian 仓库：
  - `99-Governance/Rules/`
  - `99-Governance/OpenClaw-Memory/`

## 压缩方式
- 优先：总结最近 N 条对话并保留关键事实（角色分工/定时任务/仓库地址/偏好）
- 避免：把大量原始网页内容塞进压缩摘要

## 备注
- 你只需要在飞书里说“压缩一下会话”，我就会执行。
- 默认由大秘根据 context 使用率自动触发。
