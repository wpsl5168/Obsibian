# 配图 / 架构图生成标准（强约束）

> 适用范围：知识库文章中的所有配图、架构图、概念图、流程图（无论是否由 AI 生成）。

## 0. 总原则（三条红线）
1) **必须基于文章内容严谨生成**：图里每个实体、关系、层级，都要能在正文中找到对应依据。
2) **禁止随意发散与脑补**：正文没提到的模块/流程/术语，不得擅自补全。
3) **统一风格**：高级、极简、学术白板风（参考 Google NotebookLM），不做卡通/写意。

## 1. 视觉与风格规范（固定模板）
- **画风**：现代极简 / 学术白板
- **色彩**：黑白灰为主，少量科技蓝点缀（用于强调关键节点或主链路）
- **线条**：细线条、直角连接为主；尽量避免曲线与花哨阴影
- **元素**：只用方框/圆角框/箭头/分组框/编号
- **文字**：少而准，避免大段描述；禁止出现与正文不一致的术语
- **禁用**：卡通人物、拟物图标、复杂插画、背景纹理、摄影风、过度装饰

## 2. 内容对齐规范（生成前检查）
生成任何图之前，先从文章里提取并确认：
- [ ] **主体实体清单**（组件/模块/角色/系统）
- [ ] **关系类型**（调用/依赖/数据流/控制流/权限边界）
- [ ] **分层结构**（例如：Client/Host/Runtime/Tools/Infra）
- [ ] **边界与约束**（权限、审批点、HITL、沙箱、审计）

若以上任一项无法从正文明确得到 → **不要画**，先补正文或向老王确认。

## 3. Prompt 工程纪律（必须包含 4 块）
当你需要“自动构思生成 Prompt”时，Prompt **必须显式包含**：
1) **[主体实体]**：列出实体名称（仅来自正文）
2) **[构图结构与连接关系]**：明确分组、层级、箭头方向、关系语义
3) **[风格约束]**：NotebookLM 风格、极简、黑白灰+蓝点缀、白板框图
4) **[禁止项]**：不含无关元素、不含错误文字、不发散、不卡通

## 4. 推荐 Prompt 模板（可复制）
> 使用时把 { } 替换成文章已确认的信息。

**Prompt：**
- 主题：为《{文章标题}》生成一张架构图/概念图。
- 主体实体（仅限正文出现）：{实体1}、{实体2}、{实体3}…
- 构图结构与连接关系：
  - 分组/层级：{分组A: 包含…}；{分组B: 包含…}
  - 连接：{实体1} → {实体2}（{关系语义：调用/数据流/审批/观测}）；{实体2} → {实体3}（…）
  - 强调主链路：用少量科技蓝标出 {关键链路/关键节点}
- 风格约束：现代极简、学术白板、类似 Google NotebookLM；黑白灰为主，少量科技蓝点缀；细线条、清晰对齐、留白充足；无渐变无阴影。
- 禁止项：不含卡通/插画风元素；不添加正文未出现的模块/术语；不生成无意义装饰；不出现拼写错误或不一致文字。

## 5. 质量门槛（生成后验收）
- [ ] 图中所有实体都能在正文定位到（可引用段落/小节）
- [ ] 所有箭头关系语义清楚（调用/数据/控制/审批）
- [ ] 没有“看起来很对但正文没写”的脑补组件
- [ ] 风格统一：白板框图、黑白灰+蓝、无花哨元素
