# 配图标准（强约束：禁止 AI 生图）

> 适用范围：知识库文章中的所有配图、架构图、概念图、流程图。
> 
> **红线更新（永久生效）：禁止使用 AI 生图模型生成技术配图。**
> 原因：当前生图模型在文字精细度与复杂架构逻辑表达上不可靠，容易引入错误与歧义。

## 0. 总原则（三条红线）
1) **必须基于文章内容严谨生成**：图里每个实体、关系、层级，都要能在正文中找到对应依据。
2) **禁止随意发散与脑补**：正文没提到的模块/流程/术语，不得擅自补全。
3) **统一风格**：高级、极简、学术白板风（参考 Google NotebookLM），不做卡通/写意。

## 1. 视觉与风格规范（固定模板）
- **画风**：现代极简 / 学术白板
- **色彩**：黑白灰为主，少量科技蓝点缀（用于强调关键节点或主链路）
- **线条**：细线条、直角连接为主；尽量避免曲线与花哨阴影
- **元素**：只用方框/圆角框/箭头/分组框/编号
- **文字**：少而准，避免大段描述；禁止出现与正文不一致的术语
- **禁用**：卡通人物、拟物图标、复杂插画、背景纹理、摄影风、过度装饰

## 2. 内容对齐规范（配图前检查）
在为文章配图之前，先从正文里提取并确认：
- [ ] **主体实体清单**（组件/模块/角色/系统）
- [ ] **关系类型**（调用/依赖/数据流/控制流/权限边界）
- [ ] **分层结构**（例如：Client/Host/Runtime/Tools/Infra）
- [ ] **边界与约束**（权限、审批点、HITL、沙箱、审计）

若以上任一项无法从正文明确得到 → **先补正文或向老王确认**，不要为了配图而脑补。

## 3. 配图工作流（唯一允许的方式：Web Search 找权威图）
当文章需要配图时：
1) 使用搜索引擎（Web Search）查找：
   - 官方架构图 / 官方文档插图
   - 权威概念图（论文、标准组织、官方博客）
   - 业内高质量博客的插图（以引用规范、图清晰、内容准确为优先）
2) **原封不动下载**图片文件（不做 AI 重绘、不做“生成版”替代）。
3) 将图片保存到知识库内的 `assets/`（建议子目录按 topic 命名，如 `assets/claude-code/`）。
4) 在 Markdown 文章中用**相对路径**引用，例如：
   - `![[assets/claude-code/official-architecture.png]]`（Obsidian 内链）
   - 或 `![caption](../assets/claude-code/official-architecture.png)`（标准 Markdown）
5) 在图片附近标注来源（URL + 访问日期），并尽量说明该图对应正文的哪个小节。

## 4. Prompt 纪律（已废止）
- 由于“永久禁止 AI 生图”，本仓库不再为生图模型维护 Prompt 模板。

## 5. 质量门槛（验收）
- [ ] 图片来自官方/权威来源（或明确标注为“业内高质量博客”，并附来源链接）
- [ ] 图片内容与正文一致（实体/关系/术语不冲突）
- [ ] 图片清晰可读（文字可辨认，必要时选矢量 SVG 或高清 PNG）
- [ ] 已在文中标注来源 URL + 访问日期
- [ ] 使用相对路径引用，文件已落在 `assets/` 下并随 git 提交
