### 1. Google DeepMind 一周连发：Gemini 3.1 全家桶 + Gemma 4 + Nano Banana 2 + Veo 3.1
- **来源**:
  - [Gemini 3.1 Pro](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-1-pro)
  - [Gemini 3.1 Flash / Flash-Lite / Flash Live / Flash TTS](https://deepmind.google/discover/blog/)
  - [Gemma 4](https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/)
  - [Nano Banana 2](https://blog.google/innovation-and-ai/technology/ai/nano-banana-2)
  - [Veo 3.1](https://blog.google/innovation-and-ai/technology/ai/veo-3-1-ingredients-to-video/)
  - [Gemini Robotics-ER 1.6](https://deepmind.google/blog/gemini-robotics-er-1-6/)
- **发生了什么**: DeepMind 在过去一周一口气更新了 Gemini 3.1 Pro/Flash/Flash-Lite/Flash Live/Flash TTS、Deep Think、Gemma 4 开源、Nano Banana 2 图像、Veo 3.1 视频、Lyria 3 Pro 音乐、Robotics-ER 1.6，并发了 AlphaEvolve 影响力总结和 "AGI 认知框架"白皮书。
- **背景**: 自 Gemini 3 Deep Think 在数学/科研 benchmark 拿下 SOTA 之后，Google 把节奏切到"一周一新模型"的窗口期；正好卡在 OpenAI 上次旗舰发布（GPT-5.5）和 Anthropic Opus 4.7 之间的中场。
- **分析**: 这是典型"先 burst 再固化"的产品节奏——Flash 系列三档分层(Pro / Flash / Flash-Lite)说明 Google 已经把多模态推理彻底产品矩阵化，开发者按延迟/价格取档；Gemma 4 的"byte for byte 最强开源"表述对标 Llama 4 / Qwen 系列；Veo 3.1 + Nano Banana 2 + Lyria 3 Pro 把视频/图/音乐做齐，明显是冲着 Sora 2 的影响力去的。最值得关注的是 AlphaEvolve——Gemini-powered 的"科学发现 agent"已经能在多领域产生可发表成果，这是 agent 范式从 coding 外溢到科研的第一波。
- **影响与关注点**:
  - 跑评测的同学：把 Gemini 3.1 Flash-Lite 加入 LLM 路由的"廉价档"候选，可能性价比超过 GPT-5.3 Instant。
  - 视频/图像方向：Nano Banana 2 和 Veo 3.1 的 API 价格、可商用条款一出马上对比 Sora 2。
  - 关注 Gemma 4 的 license——如果还是原来那套限制商用规模的条款，开源圈接受度会打折。

### 2. DeepSeek-V4-Flash 让"steering vectors / 激活向量"重新成为工程话题
- **来源**: [DeepSeek-V4-Flash means LLM steering is interesting again — Sean Goedecke](https://www.seangoedecke.com/steering-vectors/) (HN 270pts/75 评论)
- **发生了什么**: DeepSeek-V4-Flash 发布后，Sean Goedecke 的长文分析了为什么这个模型的 activation 结构让经典的 "steering vector"（在 residual stream 上加方向向量来引导输出）方法变得实用。HN 上集中讨论。
- **背景**: Steering vector 是 2023-24 年的小众 interpretability 技术，后被 RLHF / DPO / GRPO 等"训练时对齐"主流盖过；这次因为 V4-Flash 的 MoE + 小专家结构让"推理时干预"成本变低，重新被提起。
- **分析**: 这是一个被低估的工程信号——它意味着"廉价、可热插拔的 alignment"可能回归。对中小团队尤其重要：不需要重训，只要找到目标方向向量就能调风格/降毒/加约束。如果 V4-Flash 的开源权重 + 配套 toolkit 真能跑起来，会出现一波"个人微调"小工具复兴。
- **影响与关注点**:
  - 内容安全/品牌一致性场景：评估 steering 替代 fine-tune 的成本节省。
  - 关注接下来一两周 GitHub 上是否出现 deepseek-v4-steering / activation-patch 类小工具。

### 3. NVIDIA 开源 SANA-WM：2.6B 世界模型，单张 H100 跑 1 分钟 720p 视频
- **来源**: [SANA-WM 项目页](https://nvlabs.github.io/Sana/WM/) (HN 394pts/152 评论)
- **发生了什么**: NVIDIA Labs 发布 SANA-WM，2.6B 参数的开源"世界模型"，能从动作序列生成 1 分钟 720p 一致性视频，并且能在单卡 H100 上推理。
- **背景**: 世界模型赛道之前由 DeepMind Genie / OpenAI Sora 这种闭源大模型占据；SANA 系列一直走"小而快"路线（去年 SANA-1 就主打 4K 出图 0.6 秒）。
- **分析**: 2.6B 的尺寸意味着 4090 / 5090 级别消费卡也能跑得动推理，等社区量化版出来基本可以本地玩——这才是世界模型真正落地交互式游戏/具身仿真的门票。开源 + 单卡可跑 + 1 分钟时长这三个条件凑齐，意味着接下来 1-2 个月会有一批基于 SANA-WM 的"小型 game engine / sim env"项目冒出来。
- **影响与关注点**:
  - 具身/机器人方向：可以考虑用 SANA-WM 做廉价 dreamer-style 训练环境。
  - 评估是否能 fine-tune 出特定领域的 world model（驾驶、手术、工业流程）。

### 4. OpenAI × 马耳他：把 ChatGPT Plus 卖给一整个国家
- **来源**: [Malta partnership 官方公告](https://openai.com/index/malta-chatgpt-plus-partnership/) (HN 319pts/329 评论)
- **发生了什么**: OpenAI 宣布与马耳他政府合作，向全体公民免费提供 ChatGPT Plus 订阅。
- **背景**: OpenAI 上月刚成立 "OpenAI Deployment Company" 专门做企业/政府部署；马耳他 ~55 万人口，是欧盟成员国但体量小，正好适合做"主权 AI"试点。Anthropic 这周宣布与 PwC、Blackstone/Hellman & Friedman/Goldman 合资 enterprise AI 公司、与 Gates Foundation $200M 合作；两家都在抢同一类大客户。
- **分析**: 这一步比表面看起来更重要——它把"AI 订阅"从 to-C/to-B 升级到 to-G（to-government），把欧盟数据合规和"国民级 AI 福利"两个老大难一起捆绑解决。如果马耳他模式能跑通，下一个目标大概率是爱沙尼亚、卢森堡这种小国。但这也加剧了 Mistral CEO 同一天发声的"欧洲两年内变美国 AI 附庸国"的恐慌（HN 108pts），欧洲监管反弹值得跟踪。
- **影响与关注点**:
  - 关注欧盟委员会接下来对"主权 AI 协议"的态度——会不会出反制法案。
  - to-G 销售模式正在成型，国内做 AI 中台/政企 SaaS 的可参考其条款结构。

### 5. Agent Skill 生态在 GitHub 起飞 + 工程师圈的"反 AI 进度"长文
- **来源**:
  - [yetone/native-feel-skill](https://github.com/yetone/native-feel-skill) (一周 1.3k⭐)
  - [DenisSergeevitch/agents-best-practices](https://github.com/DenisSergeevitch/agents-best-practices) (776⭐)
  - [gi-dellav/zerostack — Rust 写的极简 coding agent](https://github.com/gi-dellav/zerostack) (621⭐, HN 549pts)
  - [I don't think AI will make your processes go faster — Frederick Van Brabant](https://frederickvanbrabant.com/blog/2026-05-15-i-dont-think-ai-will-make-your-processes-go-faster/) (HN 607pts/410 评论)
- **发生了什么**: provider-neutral 的 "Agent Skill" 概念（一段 markdown + scripts + assets 让 agent 跨 Codex/Claude Code/Hermes 等 harness 复用）一周内爆出多个高星仓库；同时 HN 顶帖是一篇 anti-hype 长文，论点是"AI 让单点写代码变快，但不会让整体流程变快"。
- **背景**: Agent Skill 概念最早是 Anthropic 的 Claude Skills，被 Hermes Agent / Codex 等多家 harness 采纳，现在被社区抽象成"跨 harness 通用契约"。
- **分析**: 两件事拼在一起很有意思——一边是 agent 工具链快速标准化，一边是工程师圈对 "AI = 提效"的祛魅讨论登顶 HN。这意味着第二阶段（"agent 真正进生产流程"）的天花板不在模型而在流程编排：测试、CR、部署、合规这些非编码环节是瓶颈。对我们做 hermes-agent / skills 的方向是正反馈：Skill 这个抽象已经被市场验证了。
- **影响与关注点**:
  - 把 hermes-agent 现有 skills 跟 native-feel-skill / agents-best-practices 对齐，看是否能反向贡献。
  - 关注 zerostack 这种 "Rust 写 agent harness"路线——会不会比 Python/Node 更适合本地长跑。
