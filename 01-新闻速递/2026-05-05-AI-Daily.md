# AI Daily — 2026-05-05

## 一句话总览
今日两大主线：基础设施侧 OpenAI 公开了支撑 9 亿周活语音 AI 的 WebRTC 重构方案；用户权益侧 Chrome 被曝静默下载 4GB Gemini Nano 模型引发 GDPR/ePrivacy 合规风暴。

## 重点事件

### 1. OpenAI 公开低延迟语音 AI 架构（WebRTC 重构）
- **来源**: [OpenAI Blog](https://openai.com/index/delivering-low-latency-voice-ai-at-scale/)（HN 413 pts / 129 评论）
- **发生了什么**: 5/4，OpenAI 工程团队（Yi Zhang & William McDonald）发布长文，解释如何把基于 Pion 的单体 Go WebRTC 服务重构为可在 Kubernetes 上水平扩展、服务 900M 周活的实时语音栈。
- **背景**: ChatGPT Voice 与 Realtime API 的核心痛点是 ICE/DTLS 会话状态化、UDP 端口分配与 K8s 动态调度天然冲突，且需要全球低首跳延迟。
- **分析**: 这是少见的一线 RTC × AI 大规模工程经验披露。重点是把 ICE/DTLS 的 stateful 终结从 pod 抽离，用统一边缘 ingress + session affinity 路由。对所有要做实时语音 agent 的团队都是教科书级参考；侧面也证实 OpenAI 当前实时业务的瓶颈已经不是模型，而是网络面。
- **影响与关注点**:
  - 若我们要做语音 agent，优先评估 LiveKit / Cloudflare Calls / Pion + 自研 ingress 三条路；不要再走 per-session UDP port 模式。
  - 关注 OpenAI 是否会把 Realtime API 的 SLA 与价格再下调一档。

### 2. Chrome 被曝静默下载 4GB Gemini Nano，疑违反 GDPR
- **来源**: [thatprivacyguy.com 原文](https://www.thatprivacyguy.com/blog/chrome-silent-nano-install/)（HN 293 pts / 296 评论）
- **发生了什么**: 5/5，隐私研究者 Alexander Hanff 实测发现 Chrome 在用户无任何提示/同意的情况下，向本地写入 `OptGuideOnDeviceModel/weights.bin`（Gemini Nano 模型权重，4GB）；用户删除会被自动重新下载。
- **背景**: Google 一直在推 `window.ai` Prompt API，需要本地模型支撑；但默认开启 + 强制写盘 + 不可关闭，使其落入 ePrivacy Directive Art.5(3) 与 GDPR Art.5(1)/Art.25 的合规问题。
- **分析**: 这件事的"工程恶心点"和"合规炸点"同样大——10 亿+ 设备静默推一次 4GB，作者按云推算碳排在 6k–60k tCO2e。即便 Google 法务能接住，这也会成为反 on-device AI 默认开启的标志性案例，并直接影响 Edge / Brave / Arc 的差异化叙事。中国区 Chromium 衍生浏览器需要确认是否受影响。
- **影响与关注点**:
  - 检查我们自己的产品如果嵌 Chromium，要看是否带 OptGuide 模型推送（可在配置里 disable `OptimizationGuideOnDeviceModel`）。
  - 跟踪 EU DPA（特别是 noyb / 爱尔兰 DPC）是否立案；如立案，会形成"AI 模型 = 个人数据处理工具"的判例方向。

### 3. Anthropic Claude Opus 4.7 GA，重押"长跑 coding agent"
- **来源**: [Anthropic News](https://www.anthropic.com/news/claude-opus-4-7)
- **发生了什么**: Opus 4.7 正式可用，强调 long-running coding 任务的严谨性、自验证、指令字面化执行；视觉端支持 ~3.75MP 图像（2576px 长边）；文件系统式 memory 改进。
- **背景**: Opus 4.6 → 4.7 是渐进升级，但官方明确警告"老 prompt 可能跑出意外结果——4.7 会逐字执行"。
- **分析**: 这是 Anthropic 把 Claude Code / 长跑 agent 路线进一步坐实的信号，定位与 GPT-5.5 + Codex 形成正面对位。视觉分辨率提升对 computer-use agent（屏幕截图 OCR/定位）是真硬升级。"指令字面化"反过来说明此前 Opus 在松散执行——这对 agent 框架作者是好消息，对裸调 chat 用户是坑。
- **影响与关注点**:
  - 我们若有基于 Opus 的 agent harness，立刻 regression 跑一遍 prompt，特别检查"未明示但默认会做"的步骤是否被忽略。
  - 屏幕截图类工作流（自动化测试、UI 复现）可以考虑切 4.7。
