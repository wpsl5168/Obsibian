# AI Daily — 2026-04-25

## 一句话总览
GPT-5.5 全量上线（API 于 4-24 开放）与 Claude Opus 4.7 + Claude Code 质量回归事件并列本周双主线，工程师圈对 Claude 订阅价值的不满情绪显著升温。

## 重点事件

### 1. OpenAI 发布 GPT-5.5 / GPT-5.5 Pro，API 4-24 上线
- **来源**: [OpenAI Blog](https://openai.com/index/introducing-gpt-5-5/) ｜ [API Changelog (HN 241p)](https://developers.openai.com/api/docs/changelog) ｜ [System Card](https://openai.com/index/gpt-5-5-system-card/)
- **发生了什么**: 4-23 OpenAI 发布 GPT-5.5，定位"agentic 工作下一代基座"；同时上线 Bio Bug Bounty 安全计划。次日（4-24）GPT-5.5 与 GPT-5.5 Pro 进入 API，HN 单帖 1547 分 / 1029 评论。
- **背景**: 上一代 GPT-5.4 主打速度，agentic coding 与 computer use 上跟 Claude Sonnet/Opus 4.x 拉锯。OpenAI 这次明确把"长链路任务自驱动"列为主战场。
- **分析**: 官方强调 per-token latency 持平 5.4 但智能上一档，且 Codex 同任务 token 消耗显著下降——这意味着实际 \$/task 下降，对预算敏感的 agent harness（Codex/Cursor/我们自家的 Hermes）是直接利好。Bio Bug Bounty + 推迟 API 一天的节奏说明 frontier safety 流程已成发布默认动作，未来新模型 day-1 API 概率会更低。Simon Willison 拿到预览，"ask it to build things and it builds exactly what I ask for"，这种"可信度 step-up"比跑分更值得关注。
- **影响与关注点**:
  - Hermes 默认 model 列表加入 gpt-5.5 / gpt-5.5-pro，跑一遍 Codex skill 和 plan skill 做回归
  - 关注 API 端 token 计费曲线（efficiency 改进是否传导到价格）
  - Computer-use / 长任务场景做 A/B 对比 Opus 4.7

### 2. Anthropic 公开 Claude Code 质量回归 postmortem
- **来源**: [Anthropic Engineering (HN 923p)](https://www.anthropic.com/engineering/april-23-postmortem)
- **发生了什么**: 4-23 Anthropic 罕见发布工程 postmortem，承认 3-4 ~ 4-20 期间 Claude Code/Agent SDK/Cowork 质量下降是三个独立变更叠加导致：3-4 默认 reasoning effort 从 high 降到 medium；3-26 thinking 清理逻辑出 bug，每轮都清；第三个未完整披露。API 链路未受影响，已在 v2.1.116 全部回滚。
- **背景**: 过去一个月 r/ClaudeAI、HN、X 上"Claude 变笨"的抱怨持续发酵，本身就和 Opus 4.7 发布节奏撞在一起。
- **分析**: 这是难得的"模型没动、harness 改动导致体感劣化"的实锤案例——之前社区每次怀疑模型被偷偷量化，厂商都以"未变更"反驳，但用户体感是真的。Anthropic 这次把锅认在 default 配置和 cache bug 上，态度坦诚但也暴露 agent 产品的脆弱面：UI 默认参数 = 事实模型。对做 agent infra 的人是教训：harness 层任何 default 修改都要走灰度+回归基线。
- **影响与关注点**:
  - Hermes 自身的 reasoning effort / context 截断策略加进 release notes 模板
  - 给 Claude Code 用户：明确指定 `--reasoning high`，别吃默认值
  - 跟踪 Anthropic 是否真落地承诺的"行为变化基线测试"

### 3. "I cancelled Claude" 千分热帖：订阅价值争议爆发
- **来源**: [nickyreinert.de (HN 881p)](https://nickyreinert.de/en/2026/2026-04-24-claude-critics/) ｜ [Claude Code 是否要从 Pro Tier 移除（HN 679p）](https://bsky.app/profile/edzitron.com/post/3mjzxwfx3qs2a)
- **发生了什么**: 一位德国开发者长帖控诉 Claude Haiku 两次小问询就把 token 配额打到 100%，AI 客服无效、人工客服模板回复，最终退订。同时 Pro Tier 是否会移除 Claude Code 的传闻发酵。
- **背景**: Anthropic 3 月给非高峰期加额度，但 Claude Code 真实用量远超预期；OpenClaw（第三方 CLI 走订阅 backdoor）4 月被封又解封，加剧用户对计费透明度的不满。
- **分析**: 这不是单点 bug，是订阅商业模型与 agent 真实 token 消耗不匹配的结构性矛盾。Claude Code 一个 long-running agent 任务可能轻松吃掉数万 token，固定月费玩家的边际成本被严重摊薄；Anthropic 要么涨价、要么限额、要么 Pro 砍 Claude Code——三选一都伤口碑。Cursor 早期踩过同样的坑。
- **影响与关注点**:
  - hermes-gateway 额度策略要考虑"agent 任务 = 非线性多 token"
  - 短期可能催生从 Anthropic 流向 OpenAI Codex / 自部署的迁移潮
  - 关注 Anthropic 5 月是否调整 Pro Tier 包含项

### 4. Claude Desktop 被指安装"未披露的 native messaging bridge"
- **来源**: [letsdatascience.com (HN 96p)](https://letsdatascience.com/news/claude-desktop-installs-preauthorized-browser-extension-mani-4064fb1a)
- **发生了什么**: 研究者发现 Claude Desktop 安装时会写入 Chrome/Edge 的 native messaging manifest，相当于预授权一个浏览器扩展通道，文档里没有明确说明。
- **分析**: 不一定恶意，但 desktop AI 客户端越来越多伸手到浏览器是趋势（Claude / ChatGPT app / Comet 都在做）。企业环境下这等于旁路 SSO/DLP 控制面。AI 工具采购清单应加入"客户端安装权限审查"这一项。
- **影响与关注点**:
  - 个人机器装 Claude Desktop 后检查 NativeMessagingHosts 目录
  - 写一份"AI 桌面客户端权限自查"短 skill
