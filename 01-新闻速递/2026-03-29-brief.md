## 1) OpenClaw（官方）

### 1.1 OpenClaw 最新 Release（2026-03-29 01:34 UTC）
- 官方 Release：<https://github.com/openclaw/openclaw/releases>
- 我关注的变化（摘重点）：
  - **插件审批能力增强**：plugins/hooks 增加 `requireApproval`（before_tool_call 可拦截并走统一 /approve 机制）——这对“能写/能改/能执行”的 agent 安全上线是关键。
  - **CLI backend 统一**：把 Claude/Codex/Gemini CLI 的默认推理后端迁移到插件面；并统一日志开关（`--cli-backend-logs`），降低“不同 CLI 后端行为不一致”的维护成本。
  - **ACP 绑定能力增强**：支持把当前会话直接绑定到 ACP（无需开子线程），更适合在同一个聊天窗口里直接切换到 Codex/Claude Code 等编码执行环境。

**我的理解（怎么用）**
- OpenClaw 这一波核心方向是：把“工具调用/副作用”纳入统一的**审批与可审计**链路。
- 如果你后面要做“每天 18:00 自动生成并提交到 GitHub”，强烈建议把：
  - 写文件、push、外部 API 写入
  - 这些动作都放到一个可审计的 workflow 里，并在关键节点加 approval（尤其是首次上线阶段）。

## 2) Claude Code（官方）

### 2.1 Claude Code 官方文档概览
- 官方 Docs：<https://code.claude.com/docs/en/overview>
- 官方 GitHub：<https://github.com/anthropics/claude-code>

**我的理解（怎么用）**
- Claude Code 的定位是“终端/IDE 里的 agentic coding 工具”：能读代码、改文件、跑命令、串开发工具。
- 和 OpenClaw 的关系：
  - OpenClaw 更像“多渠道 + 工作流 + 权限治理 + 运营化”的 agent 宿主；
  - Claude Code 更像“编码执行体验很强”的专用执行器。
  - 结合方式就是：OpenClaw 负责编排/审批/投递，Claude Code 负责在受控 workspace 里真正把代码改出来。

## 3) [[MCP]]（官方 + 生态）

### 3.1 [[MCP]] 是什么（官方 Intro）
- [[MCP]] 官方介绍：<https://modelcontextprotocol.io/docs/getting-started/intro>
- Anthropic 官方发布：<https://www.anthropic.com/news/model-context-protocol>

**我的理解（为什么重要）**
- [[MCP]] 正在成为“agent 连接外部系统”的事实标准：让工具与数据源的接入从“每家自定义插件”变成“协议化生态”。
- 对 OpenClaw/Claude Code 这类 agent 宿主来说，[[MCP]] 的意义是：
  - 你不必为每个系统重复造轮子；
  - 你可以把权限、安全、审计放在协议/宿主层统一处理。

## 5) 安全专题（高质量长文，偏工程团队可执行）

### 5.1 Martin Fowler：[[AI Agent]]ic AI and Security
- 原文：<https://martinfowler.com/articles/agentic-ai-security.html>

**我的理解（要点）**
- 这篇的核心是：一旦 agent 能读外部不可信内容 + 能调用工具产生副作用，就会暴露在 prompt injection 等系统性风险里。
- 对我们要做的“自动汇总+自动写入 GitHub”的场景：
  - 任何来自网页的内容都要当作“不可信输入”；
  - 写入仓库前要有校验/人工抽检机制（至少上线初期）。
