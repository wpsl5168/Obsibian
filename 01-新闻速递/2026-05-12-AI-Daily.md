## 重点事件

### 1. Thinking Machines Lab 提出"Interaction Models"——把交互性内嵌进模型本身
- **来源**: [thinkingmachines.ai/blog/interaction-models](https://thinkingmachines.ai/blog/interaction-models/) （HN 229 pts，今日工程类最高）
- **发生了什么**: Mira Murati 团队发文主张：当前 LLM 都是"轮替制"接口（你说完我说），真正的人机协作需要原生支持音/视/文的实时双向流。靠外挂 VAD、harness 等脚手架，扩展性追不上模型本身扩展速度。
- **背景**: 行业把全部资源压在 autonomous agent 上，但很多用户反馈"实时手动协作时反而不如旧模型"——Anthropic 自己 model card 都承认了这点。学界引用 Clark & Brennan 1991 的 copresence/contemporality/simultaneity 三要素佐证。
- **分析**: 这是给 agent-everything 叙事的一次有分量的反向声音，且来自 ex-OpenAI CTO 团队，分量不轻。技术上对应 OpenAI 同周发布的 Realtime-2，但比 OpenAI 走得更激进——把交互当成 first-class 训练目标而不是 API 形态。如果这条路径真做出来，UI/agent harness 这一层的中间件公司会被吃掉一大片。
- **影响与关注点**:
  - 我们做 voice/agent 产品时，开始评估"原生交互模型 vs harness 拼接"两条路径的成本曲线
  - 关注 TML 后续是否放出权重或 API
  - 重新审视自家 agent 中"等用户说完才响应"的 turn-based 假设

### 2. Google 拦截首例 AI 驱动的 0-day 漏洞利用，攻防 AI 化进入实战
- **来源**: [AP News](https://apnews.com/article/google-ai-cybersecurity-exploitation-mythos-926aea7f7dc5e0e61adce3273c55c6d4) ｜ [NYT](https://www.nytimes.com/2026/05/11/us/politics/google-hackers-attack-ai.html)（HN 193 pts）
- **发生了什么**: Google 威胁情报披露：某犯罪团伙用某 LLM 自动发现一款流行运维工具的 0-day（可绕过 2FA），被 Google 在造成损失前拦下并通知厂商和执法。所用模型既非 Gemini 也非 Claude Mythos，未点名。
- **背景**: 上月 Anthropic 发布 Mythos 时声称其攻击能力强到只能小范围放出，业界普遍预测"几个月内会看到真实事件"，结果一个月就到了。Project Glasswing（Anthropic+AWS+Apple+Google+JPM 等）就是为这类场景准备的应对联盟。
- **分析**: 这是 AI 武器化从"PoC"跨进"实战"的标志事件，意味着 vuln discovery 自动化的成本/速度曲线对攻击方倾斜。Google 高管罕见公开支持监管，说明大厂判断防守侧短期吃亏。对企业而言，"补丁周期 ≥ AI 利用周期"的时代窗口正在关闭。
- **影响与关注点**:
  - 自家服务暴露面盘点，重点是运维管理类工具（被攻击的同类）
  - 提速 patch 自动化和 SCA 扫描频率
  - 跟进 Project Glasswing 是否会放出共享情报/工具

### 3. OpenAI 上线 GPT-Realtime-2/Translate/Whisper：语音侧迈入 GPT-5 时代
- **来源**: [OpenAI Blog](https://openai.com/index/advancing-voice-intelligence-with-new-models-in-the-api/)
- **发生了什么**: 三模型同时发布。Realtime-2 是首个带 GPT-5 级推理的语音模型，Big Bench Audio +15.2%，上下文从 32K 扩到 128K；Translate 支持 70 语种输入、13 语种输出实时同传；Whisper 流式 STT 走低延迟路线。
- **背景**: 紧接 Anthropic Mythos / Claude Opus 4.7 之后的卡位回应；同周 Thinking Machines 在交互模型上发声，三方在"实时多模态"赛道开始正面对线。
- **分析**: 128K 上下文 + 推理能力让"长会议/长客服会话"在不断流的前提下可做了，这是之前 Realtime API 最大的工程痛点。Translate 的 70→13 语种结构暗示是面向 B 端客服/旅游/政企，而非消费级翻译耳机。
- **影响与关注点**:
  - 客服/会议场景把 STT+LLM+TTS 三段式管线替换成 Realtime-2 评估一遍延迟与成本
  - 对中文/小语种场景，先小流量灰度对比 Gemini Live / 自家 ASR

### 4. Interfaze：CNN/DNN + Transformer 混合架构在确定性任务全面爆杀 flash 档
- **来源**: [interfaze.ai blog](https://interfaze.ai/blog/interfaze-a-new-model-architecture-built-for-high-accuracy-at-scale)（HN 150 pts）
- **发生了什么**: 自称在 9 项 OCR/视觉/语音/结构化输出 benchmark 上击败 Gemini-3-Flash、Claude-Sonnet-4.6、GPT-5.4-Mini、Grok-4.3。OCRBench V2 70.7% vs 次高 55.8%；VoxPopuli WER 2.4% vs 4.0%。1M 上下文，多模态 IO，task-specific adapter。
- **背景**: 一个反潮流的赌注——Transformer 通吃的叙事下，他们押"OCR/翻译这种确定性活儿就该用专用网络"。和 2018 年 ResNet/CRNN-CTC 的工程智慧重新被打捞。
- **分析**: 数字漂亮但只对比 flash/mini 档，不敢上 Pro 档对线，说明定位很清晰：批量、低成本、确定性。对中后台文档处理、爬虫提取这类业务，Reducto / Mistral OCR / 自托管 Whisper 的位置真有压力。需警惕：自报数据，等第三方复现。
- **影响与关注点**:
  - 文档处理/PDF 抽取流水线试跑 Interfaze API
  - 关注是否开源或可私有化部署
