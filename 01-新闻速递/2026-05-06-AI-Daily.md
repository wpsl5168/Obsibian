# AI Daily — 2026-05-06

## 一句话总览
Google 用 MTP drafter 给 Gemma 4 加速 3 倍，OpenAI 公开 9 亿周活背后的 WebRTC 重构；与此同时 Chrome 被曝静默下载 4GB Gemini Nano、PyTorch Lightning 中毒成蠕虫源头——基础设施和供应链正在同步进入"AI 默认开"的高风险时代。

## 重点事件

### 1. Google 发布 Gemma 4 多 token 预测 drafter，推理提速 3x
- **来源**: [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/multi-token-prediction-gemma-4/)
- **发生了什么**: Google 为 Gemma 4 系列发布 MTP（Multi-Token Prediction）drafter 模型，配合 speculative decoding 把 tokens/s 拉高最多 3 倍，质量与推理逻辑无下降；Apache 2.0 许可。
- **背景**: 单 token 自回归生成是 memory-bandwidth bound，speculative decoding 用一个轻量 drafter 一次猜多个 token，大模型并行验证。Meta、DeepSeek、vLLM 此前都做过类似事，但这是 Gemma 官方一手优化。
- **分析**: 第一，开源端侧模型的有效推理成本被官方层面再压一截，本地部署 Gemma 31B 这一级正在变得"可日常用"。第二，MTP drafter 是和主模型耦合训练的，自家发的命中率会显著高于第三方拼凑方案。第三，这等于变相承认"端侧 LLM 体验差距来自系统优化而非参数量"。
- **影响与关注点**:
  - 自建 LLM 服务的，把 Gemma 4 + MTP drafter 列入下个迭代的 baseline 评估。
  - 关注是否会有 Llama / Qwen 跟进发布官方 drafter。

### 2. OpenAI 公开 9 亿周活下的低延迟语音架构
- **来源**: [OpenAI Blog](https://openai.com/index/delivering-low-latency-voice-ai-at-scale/)
- **发生了什么**: OpenAI 发文详解 ChatGPT Voice / Realtime API 的 WebRTC 栈重构：从单个 Pion Go 服务，改为 Split Relay + Transceiver 的拆分架构，解决 K8s 上 one-port-per-session、stateful ICE/DTLS、全球路由三大瓶颈。
- **背景**: WebRTC 原本是为浏览器点对点通话设计，套到 Kubernetes 多租户大规模服务上各种水土不服。9 亿周活意味着每个不优雅的细节都会乘以一个巨大的常数。
- **分析**: 这篇文章的工程价值远高于"又一个发布"。第一，它把"AI = 模型"的迷雾再次拨开——真正决定语音体验的是网络和媒体面而不是模型 token 速度。第二，OpenAI 把这种内部踩坑公开，本身是在和 Google/xAI 抢实时语音赛道的开发者心智。第三，对国内做实时语音 Agent 的团队（豆包、元宝、Kimi）是一份免费 RFC。
- **影响与关注点**:
  - 做语音 Agent 的，重点抄作业：媒体面无状态化 + ICE 状态外置。
  - 跟踪 Realtime API 是否随之降价或放开更高并发。

### 3. Chrome 被曝静默下载 4GB Gemini Nano，无同意无 opt-out
- **来源**: [That Privacy Guy](https://www.thatprivacyguy.com/blog/chrome-silent-nano-install/)（HN 1468 分热帖）
- **发生了什么**: 研究者在干净 macOS profile 上验证：Chrome 自动下载并安装 4GB 的 `weights.bin`（Gemini Nano 权重）到本地，用户没有任何 prompt；删了会自动补回，唯一办法是关 chrome://flags 或卸载 Chrome。
- **背景**: 此前 Anthropic Claude Desktop 也被曝出过类似静默安装行为。"AI 默认开"成为巨头标准做法。
- **分析**: 第一，端侧模型常态化但治理为零，4GB 占用对中低端机型是真实的盘和带宽成本。第二，欧盟 DMA / GDPR 视角下这是新的合规炸药桶，预计今年内会有正式投诉。第三，对开发者意味着可以更自由地调用浏览器内置 LLM（Prompt API），但用户信任债越累越多。
- **影响与关注点**:
  - 评估在产品中调用 Chrome 内置 Prompt API 的可行性（成本=0，但兼容性受 flag 影响）。
  - 关注欧盟监管反应、企业版 Chrome 是否给出关闭开关。

### 4. PyTorch Lightning 2.6.2/2.6.3 被植入"Mini Shai-Hulud"蠕虫
- **来源**: [Semgrep Blog](https://semgrep.dev/blog/2026/malicious-dependency-in-pytorch-lightning-used-for-ai-training/)
- **发生了什么**: 4 月 30 日发布的 `lightning` 2.6.2 / 2.6.3 包含 `_runtime` 隐藏目录，import 即执行混淆 JS payload，窃取凭证、token、环境变量、云密钥，并尝试污染 GitHub 仓库。Dune 主题命名（EveryBoiWeBuildIsaWormBoi）与之前 npm 上的 Shai-Hulud 同源。
- **背景**: 这是首次看到从 PyPI 入口、JS payload、再向 npm 蠕虫扩散的跨生态供应链攻击。AI 训练库因为常在拥有 GPU/云密钥的 CI 环境运行，价值密度极高。
- **分析**: 第一，AI 项目正在成为供应链攻击的头号目标——回报曲线最陡。第二，跨生态（PyPI→npm）攻击意味着单一 ecosystem 的防御已不够。第三，CI 上 `pip install` 即激活，传统 SCA 扫描（依赖表）抓不到，需要运行时 sandboxing。
- **影响与关注点**:
  - 立即检查任何 CI / 训练机上 `lightning==2.6.2` 或 `2.6.3`，pin 到 2.6.1 或更早。
  - 在训练环境强制使用一次性 token + 短期凭证，禁用长期 AWS/GCP key。
  - 把 pip 安装放进无 secret 的初始化容器层。

### 5. Uber 4 个月烧光 2026 全年 AI 预算，主要给了 Claude Code + Cursor
- **来源**: [Briefs.co](https://www.briefs.co/news/uber-torches-entire-2026-ai-budget-on-claude-code-in-four-months/)
- **发生了什么**: Uber 95% 工程师每月使用 AI 工具，70% 的提交代码来自 AI，单工程师月均 API 成本 $500–$2000，提前 8 个月烧光 2026 AI 预算。
- **背景**: Claude Code 2025 年 12 月引入，2 月用量翻倍，4 月封顶。
- **分析**: 第一，"AI 编码工具贵但停不下来"已经从 demo 变成大厂 P0 事实。第二，70% 提交来自 AI 这个数字真实性可议（很多是 boilerplate / refactor），但订单方向无误。第三，对 Anthropic 是利好——企业愿意为 Claude Code 单独立项，议价权进一步抬升。
- **影响与关注点**:
  - 个人/团队侧：尽快建立 token 预算和分账机制，否则下半年财报会哭。
  - 评估 Gemini CLI / Codex CLI 作为多模型对冲。
