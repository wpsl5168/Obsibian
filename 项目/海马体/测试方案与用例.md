# 🦛 OpenHippo 记忆系统测试方案与用例

> 本文档定义海马体记忆系统的完整测试体系，覆盖8大验证维度、27个测试场景，用于系统性评估功能正确性、性能、稳定性和生产就绪度。

## 1. 测试目标

作为 Agent 记忆系统，OpenHippo 需满足以下行业标准：

| 能力要求 | 说明 | 对应维度 |
|----------|------|----------|
| **记忆准确性** | 写入即可读，替换/删除立即生效 | D1 功能正确性 |
| **去重能力** | 精确去重 + 语义去重，防止记忆膨胀 | D2 去重机制 |
| **检索质量** | 关键词精确匹配 + 语义理解 + 混合排序 | D3 搜索质量 |
| **响应性能** | 写入 <1s，搜索 <0.5s，支持并发 | D4 性能基准 |
| **数据安全** | 特殊字符不破坏存储，SQL注入防护 | D5 数据完整性 |
| **容量治理** | 热记忆有上限管控，自动淘汰 | D6 容量管理 |
| **生命周期** | 创建→更新→归档→检索→提升→删除 全链路 | D7 生命周期 |
| **容错恢复** | 异常输入优雅处理，重启不丢数据 | D8 异常恢复 |

## 2. 系统架构概览

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   MCP Tool   │  │  REST API   │  │     CLI     │
└──────┬───────┘  └──────┬──────┘  └──────┬──────┘
       └────────────┬────┘────────────────┘
            ┌───────▼────────┐
            │   Core Engine   │
            │  ┌───────────┐  │
            │  │ Hot Memory │  │  ← 每轮注入，快速读写
            │  ├───────────┤  │
            │  │Cold Memory │  │  ← FTS5全文 + Vec向量搜索
            │  ├───────────┤  │
            │  │  Dedup 🔒  │  │  ← SHA256精确 + 余弦语义
            │  └───────────┘  │
            └───────┬────────┘
            ┌───────▼────────┐
            │ SQLite+FTS5+Vec │
            └────────────────┘
```

**关键参数：**
- Hot Memory 容量上限：memory=4400 chars, user=2750 chars
- 语义去重阈值：L2 distance < 0.4（≈ cosine > 0.92）
- Embedding 模型：nomic-embed-text (768维)
- 混合搜索算法：RRF (Reciprocal Rank Fusion, k=60)

## 4. 测试维度与用例

### D1: 功能正确性（5个场景）

#### T1.1 写入与读取回环

| 项目 | 内容 |
|------|------|
| **目的** | 验证 memory/user 两种 target 写入后可读、可搜 |
| **前置** | 服务正常运行 |
| **步骤** | 1. POST /v1/memories 写入 memory 条目<br>2. POST /v1/memories 写入 user 条目<br>3. GET /v1/memories/hot 验证列表<br>4. POST /v1/memories/search 验证搜索命中 |
| **验收** | status=created; hot列表包含条目; search total>0 |
| **测试数据** | `[T1.1_{timestamp}] Agent学会了使用Docker部署服务` |

#### T1.2 替换

| 项目 | 内容 |
|------|------|
| **目的** | 验证 old_text 匹配后内容完整替换 |
| **步骤** | 1. 写入旧内容（含IP 192.168.1.100）<br>2. POST /v1/memories/replace 替换为新IP<br>3. 验证旧内容消失、新内容存在 |
| **验收** | status=replaced; hot中仅有新内容 |

#### T1.3 删除

| 项目 | 内容 |
|------|------|
| **目的** | 验证 old_text 匹配后条目彻底删除 |
| **步骤** | 1. 写入临时条目<br>2. POST /v1/memories/remove<br>3. 验证hot列表不含该条目 |
| **验收** | status=removed; hot列表无残留 |

#### T1.4 归档与提升

| 项目 | 内容 |
|------|------|
| **目的** | 验证 hot→cold 归档、cold→hot 提升的完整流转 |
| **步骤** | 1. 写入条目<br>2. Archive → 确认从hot消失<br>3. FTS搜索cold → 确认命中<br>4. Promote → 确认回到hot |
| **验收** | 归档status=archived; cold可搜; 提升status=promoted; 重回hot |

#### T1.5 target 隔离

| 项目 | 内容 |
|------|------|
| **目的** | 验证 memory 和 user 两个 target 的数据互不泄漏 |
| **步骤** | 1. 分别向 memory/user 写入专属内容<br>2. 查询 memory hot列表不含 user 内容（反之亦然） |
| **验收** | 各自target只返回自己的数据 |

### D2: 去重机制（4个场景）

#### T2.1 精确去重

| 项目 | 内容 |
|------|------|
| **目的** | 相同内容二次写入应被拦截 |
| **步骤** | 1. 首次写入 → created<br>2. 相同内容再次写入 → duplicate |
| **验收** | status=duplicate, reason=exact_hot |

#### T2.2 标准化去重（带迁移前缀）

| 项目 | 内容 |
|------|------|
| **目的** | 带 `[hermes-mirror]` 等前缀的相同内容应被识别为重复 |
| **步骤** | 1. 写入原始内容<br>2. 写入 `[hermes-mirror] ` + 相同内容 |
| **验收** | status=duplicate（前缀被标准化剥离后SHA256匹配） |
| **涉及前缀** | `[hermes-mirror]`, `[migrated-cold]`, `[migrated-hot]` |

#### T2.3 语义去重（cold层）

| 项目 | 内容 |
|------|------|
| **目的** | 归档到cold后，高度相似的改写内容应被语义去重 |
| **步骤** | 1. 写入并归档原文<br>2. 等待embedding生成(1s)<br>3. 写入改写版本 |
| **验收** | status=similar, distance<0.4 |
| **测试数据对** | 原文: "Python项目使用black格式化代码"<br>改写: "Python项目用black来格式化代码" |

#### T2.4 不同内容不误去重

| 项目 | 内容 |
|------|------|
| **目的** | 内容不同的条目不应被错误识别为重复 |
| **测试数据对** | "项目使用PostgreSQL数据库" vs "项目部署在Kubernetes集群" |
| **验收** | 第二条 status=created |

## 6. 测试执行指南

### 前置检查清单

- [ ] OpenHippo 服务运行中 (`curl localhost:8200/health`)
- [ ] Ollama 可用 (`curl localhost:11434/api/embeddings -d '{"model":"nomic-embed-text","prompt":"test"}'`)
- [ ] 单元测试基线通过 (`cd ~/OpenHippo && .venv/bin/python -m pytest tests/ -v`)
- [ ] 记录测试前 stats 快照

### 测试数据规范

- 每轮测试使用**时间戳tag**: `[T{维度}.{场景}_{timestamp}]`
- 测试后**必须清理**测试数据，避免污染生产环境
- 清理标识前缀: `[T1.`, `[T2.`, ..., `[T8.`, `[perf_`

### Pitfalls

1. **Ollama冷启动**: 首次embedding请求可能>2s，测试前发预热请求
2. **测试数据污染**: 不清理会导致hot memory持续膨胀（已有BUG-001）
3. **FTS5语法**: 特殊字符(引号、括号)需转义，否则静默回退LIKE
4. **并发假象**: SQLite单写锁，uvicorn排队，非真并行
5. **语义去重依赖Ollama**: Ollama宕机时embedding返回None，语义去重静默跳过
