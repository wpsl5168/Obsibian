## 一、竞品全景分析

### 1. Mem0 — 赛道领跑者

| 维度 | 数据 |
|------|------|
| **GitHub Stars** | ~45K（赛道最高） |
| **融资** | $24M（YC S24 → Series A，投资方：Peak XV、Basis Set） |
| **团队规模** | 5人（2024年） |
| **营收** | $1M ARR（2024年6月达成） |
| **是否盈利** | 大概率未盈利（VC驱动增长阶段，24M融资远超1M收入） |
| **License** | Apache 2.0（开源核心 + 云平台商业化） |
| **社区活跃度** | ⭐⭐⭐⭐⭐ — 45K stars，Q3 2025达186M API调用，30% MoM增长 |
| **是否轻量** | ⚠️ 中等 — 自部署需3个Docker容器（FastAPI + PostgreSQL/pgvector + 配置），依赖外部embedding API |
| **定价** | Free tier → Pro ~$1000/年 → Enterprise自定义 |
| **核心能力** | 智能记忆提取/更新/检索，Graph Memory，多平台SDK |
| **弱点** | 云优先（数据在别人服务器）、自部署不够轻量、依赖外部LLM/embedding |

**关键洞察：** Mem0用5人团队做到$1M ARR + 45K stars，证明了"AI Agent记忆层"赛道的PMF。但其云优先架构是隐私敏感用户的痛点。

### 2. Zep AI (Graphiti) — 知识图谱派

| 维度 | 数据 |
|------|------|
| **GitHub Stars** | Graphiti ~24.6K（主项目），Zep CE单独仓库 |
| **融资** | $2.3M（种子轮 + 可转债，2023-2024） |
| **团队规模** | ~5人 |
| **营收** | $1M ARR（2024年） |
| **是否盈利** | 未盈利（种子期） |
| **License** | Apache 2.0（Graphiti开源）+ Zep Cloud商业版 |
| **社区活跃度** | ⭐⭐⭐⭐ — Graphiti 12个月内达20K stars，40+ contributors，330+ commits |
| **是否轻量** | ❌ 重 — 依赖Neo4j图数据库 + 外部LLM，部署复杂度高 |
| **定价** | Community Edition免费 → Cloud付费（SOC 2 Type 2/HIPAA认证） |
| **核心能力** | 时序知识图谱（Temporal Knowledge Graph），事实版本追踪，Sub-200ms检索 |
| **弱点** | 架构重（Neo4j依赖），融资规模小，定位偏企业级 |

**关键洞察：** 技术路线独特（时序知识图谱），但部署门槛高，不适合个人开发者/轻量场景。

### 3. Letta (原MemGPT) — 学术派转商业

| 维度 | 数据 |
|------|------|
| **GitHub Stars** | ~37K（MemGPT时代积累，后改名Letta） |
| **融资** | $10M（种子轮，2024年从Stealth出来） |
| **团队规模** | 13人（2025年） |
| **营收** | $1.4M ARR（2025年） |
| **是否盈利** | 未盈利（VC融资期） |
| **License** | Apache 2.0 |
| **社区活跃度** | ⭐⭐⭐⭐ — 高stars但实际开发集中在公司内部，社区贡献一般 |
| **是否轻量** | ⚠️ 中等 — 比Zep轻但比Mem0重，需要运行Letta Server |
| **定价** | 个人免费 → API按token计费（加价底层模型成本） |
| **核心能力** | 有状态Agent平台（不仅仅是记忆，是完整Agent框架），持久化记忆 |
| **弱点** | 定位模糊（Agent平台 vs 记忆服务），锁定效应强，不够"即插即用" |

**关键洞察：** Letta做的是"带记忆的Agent平台"而非纯记忆层，和我们不直接竞争。但其37K stars说明市场对Agent记忆有强需求。

### 4. Memsearch (Zilliz) — Markdown极简派

| 维度 | 数据 |
|------|------|
| **GitHub Stars** | 较新项目，估计 <5K |
| **融资** | Zilliz母公司已融资$113M+（但memsearch是其开源项目之一） |
| **团队规模** | Zilliz内部团队维护 |
| **营收** | 无独立营收（Zilliz的技术布局） |
| **是否盈利** | N/A（母公司项目） |
| **License** | 开源 |
| **社区活跃度** | ⭐⭐⭐ — 活跃开发中，有插件生态（OpenCode等），但社区规模小 |
| **是否轻量** | ✅ 轻量 — Markdown-first，本地文件系统，零外部依赖 |
| **核心能力** | 自动捕获对话→语义索引→混合检索，Plugin架构（Claude Code、OpenCode等） |

**关键洞察：** 最接近我们理念的竞品 — 轻量、本地优先、Markdown。但它只做"存和搜"，没有记忆的智能管理（遗忘、整合、升级）。

## 四、海马体定位与差异化

### 一句话定位

> **"你的AI记忆不该存在别人的服务器上"** — 本地优先、隐私第一的AI Agent记忆引擎

### 目标用户

| 用户画像 | 痛点 | 我们的解法 |
|---------|------|-----------|
| **独立开发者/Hacker** | Mem0要付费、数据上云不放心 | 免费本地部署，pip install一行搞定 |
| **AI Agent框架作者** | 需要即插即用记忆层 | MCP + REST双协议，5分钟集成 |
| **企业安全团队** | 数据不能出内网 | 纯本地，SQLite单文件，零外部调用 |
| **多Agent玩家** | 不同Agent记忆割裂 | GitHub-style repo隔离 + 共享 |

### 核心差异化（vs Mem0）

| Mem0 | 海马体 |
|------|--------|
| 云优先，本地是二等公民 | **本地优先，云是可选增值** |
| 依赖OpenAI embedding | **内置本地7B模型，零API费用** |
| 3个Docker容器 | **单文件SQLite + pip install** |
| 记忆只存不管 | **热冷分层 + 自动遗忘 + 整合** |
| 没有知识库整合 | **原生Obsidian/文件系统整合** |

## 八、风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| Mem0开源版变强，抢走轻量市场 | 高 | 持续在"零依赖+本地模型"上拉开差距 |
| 本地7B模型效果不够好 | 中 | 支持可选连接云LLM，但默认本地 |
| 市场窗口期短（大厂入场） | 中 | 快速迭代，社区绑定，做到"默认选择" |
| 单人/小团队精力有限 | 高 | MVP极简，只做核心功能，社区贡献补齐 |
| 向量搜索在SQLite上性能瓶颈 | 低 | sqlite-vec扩展 + 分片策略 |

## 九、总结判断

### 赛道判断：✅ 值得做

- 市场验证充分（Mem0/Zep/Letta都达$1M+ ARR）
- TAM $9B且38.7% CAGR高速增长
- 没有"本地优先"的强玩家（memsearch最接近但太简单）

### 差异化判断：✅ 有空间

- "隐私+本地+轻量"三角形没人占住
- Mem0的云优先架构是结构性弱点，不是它想改就能改的

### 时机判断：⚠️ 窗口期12-18个月

- AI Agent爆发期，记忆层还没固化标准
- 但Mem0增速很快（30% MoM），拖不起

### 建议路径

> **先做Hermes的记忆引擎（dogfooding）→ 提炼为独立项目 → 开源冲stars → 再考虑商业化**

核心信念：**最好的开发者工具，是创造者自己每天在用的工具。**
