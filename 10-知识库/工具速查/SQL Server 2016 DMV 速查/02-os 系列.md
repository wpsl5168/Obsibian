# 02 - sys.dm_os_* 系列（操作系统层）

> SQLOS 层指标：等待、CPU、内存、线程、ring buffer。性能排查的"温度计"。

---

## sys.dm_os_wait_stats

**用途**：累计等待统计，自实例启动以来按 wait_type 聚合。**性能瓶颈定位的圣杯**。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-wait-stats-transact-sql?view=sql-server-2016

**5 列全用**：

| 列 | 类型 | 含义 |
|---|---|---|
| `wait_type` | nvarchar(60) | 等待类型名 |
| `waiting_tasks_count` | bigint | 累计发生次数 |
| `wait_time_ms` | bigint | 累计等待毫秒（含 signal wait） |
| `max_wait_time_ms` | bigint | 单次最长等待 |
| `signal_wait_time_ms` | bigint | 信号等待（拿到资源后等 CPU 的时间）|

**派生指标**：
- 平均等待 = `wait_time_ms / NULLIF(waiting_tasks_count, 0)`
- CPU 压力 = `signal_wait_time_ms / wait_time_ms`（> 25% 说明 CPU 紧）
- 资源等待 = `wait_time_ms - signal_wait_time_ms`

**实战（Paul Randal 经典脚本简化版）**：
```sql
SELECT TOP 20 wait_type, waiting_tasks_count,
       wait_time_ms / 1000 AS wait_sec,
       (wait_time_ms - signal_wait_time_ms) / 1000 AS resource_sec,
       signal_wait_time_ms / 1000 AS signal_sec,
       wait_time_ms / NULLIF(waiting_tasks_count, 0) AS avg_ms_per_wait
FROM sys.dm_os_wait_stats
WHERE wait_type NOT IN ('CLR_SEMAPHORE','LAZYWRITER_SLEEP','RESOURCE_QUEUE',
                        'SLEEP_TASK','SLEEP_SYSTEMTASK','SQLTRACE_BUFFER_FLUSH',
                        'WAITFOR','LOGMGR_QUEUE','CHECKPOINT_QUEUE',
                        'REQUEST_FOR_DEADLOCK_SEARCH','XE_TIMER_EVENT','BROKER_TO_FLUSH',
                        'BROKER_TASK_STOP','CLR_MANUAL_EVENT','CLR_AUTO_EVENT',
                        'DISPATCHER_QUEUE_SEMAPHORE','FT_IFTS_SCHEDULER_IDLE_WAIT',
                        'XE_DISPATCHER_WAIT','XE_DISPATCHER_JOIN','BROKER_EVENTHANDLER',
                        'TRACEWRITE','FT_IFTSHC_MUTEX','SQLTRACE_INCREMENTAL_FLUSH_SLEEP',
                        'BROKER_RECEIVE_WAITFOR','ONDEMAND_TASK_QUEUE',
                        'DBMIRROR_EVENTS_QUEUE','DBMIRRORING_CMD','BROKER_TRANSMITTER',
                        'SQLTRACE_WAIT_ENTRIES','SLEEP_BPOOL_FLUSH','HADR_FILESTREAM_IOMGR_IOCOMPLETION')
ORDER BY wait_time_ms DESC;
```

**重置**：`DBCC SQLPERF ('sys.dm_os_wait_stats', CLEAR);`

## sys.dm_os_sys_info

**用途**：实例 / 服务器级配置信息（CPU 数、内存、启动时间等）。单行。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-sys-info-transact-sql?view=sql-server-2016

**核心列**：

| 列 | 类型 | 含义 |
|---|---|---|
| `cpu_count` | int | 逻辑 CPU 数 |
| `hyperthread_ratio` | int | 每物理核的逻辑核比例 |
| `physical_memory_kb` | bigint | 物理内存 |
| `virtual_memory_kb` | bigint | 进程虚拟地址空间 |
| `committed_kb` | bigint | SQL Server 已提交内存 |
| `committed_target_kb` | bigint | 目标内存（≈ max server memory） |
| `visible_target_kb` | bigint | 可见目标 |
| `ms_ticks` | bigint | ⚠️ **服务器运行毫秒数（bigint）**，跑 > 24.8 天就 > int 上限 |

**⚠️ ms_ticks 算术溢出陷阱**（v9 客户实测踩到）：
```sql
-- ❌ 错误：DATEADD 第2参数被隐式转 int
DATEADD(ms, -1 * (SELECT ms_ticks FROM sys.dm_os_sys_info), GETDATE())

-- ✅ 正确：在 bigint 域做减法，结果落在 int 范围
DATEADD(ms, timestamp - tk.ms_ticks, GETDATE())
FROM sys.dm_os_ring_buffers
CROSS JOIN (SELECT ms_ticks FROM sys.dm_os_sys_info) AS tk
```

## sys.dm_os_memory_clerks

**用途**：内存按用途分桶。排查"内存被谁吃了"。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-memory-clerks-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `type` | clerk 类型（MEMORYCLERK_SQLBUFFERPOOL/SQLCLR/SQLOPTIMIZER…） |
| `name` | 实例名 |
| `memory_node_id` | NUMA 节点 |
| `pages_kb` | 已分配页面（2012+，替代了 `single_pages_kb/multi_pages_kb`） |
| `virtual_memory_reserved_kb` | 保留 |
| `virtual_memory_committed_kb` | 提交 |
| `awe_allocated_kb` | AWE 分配（一般是 buffer pool） |

**实战（找内存大户）**：
```sql
SELECT TOP 20 type, name, SUM(pages_kb)/1024 AS mb
FROM sys.dm_os_memory_clerks
GROUP BY type, name
ORDER BY SUM(pages_kb) DESC;
```

## sys.dm_os_buffer_descriptors

**用途**：每个内存页的描述符。算"buffer pool 里哪个库 / 表占最多页"。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-buffer-descriptors-transact-sql?view=sql-server-2016

**常用 3 列**：
| 列 | 含义 |
|---|---|
| `database_id` | 哪个库 |
| `is_modified` | 1 = 脏页 |
| `allocation_unit_id` | JOIN sys.allocation_units 找表 |

**实战**：
```sql
SELECT DB_NAME(database_id) AS db, COUNT(*)*8/1024 AS mb
FROM sys.dm_os_buffer_descriptors
GROUP BY database_id
ORDER BY COUNT(*) DESC;
```

## sys.dm_os_performance_counters

**用途**：等同 perfmon 里 SQL Server 计数器，但能 SQL 查。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-performance-counters-transact-sql?view=sql-server-2016

**列**：`object_name / counter_name / instance_name / cntr_value / cntr_type`

**实战（Page Life Expectancy）**：
```sql
SELECT cntr_value AS PLE_seconds
FROM sys.dm_os_performance_counters
WHERE counter_name = 'Page life expectancy' AND object_name LIKE '%Buffer Node%';
```

## sys.dm_os_workers + sys.dm_os_threads

**⚠️ v9 第一坑**：`kernel_time` / `usermode_time` 在 **threads** 上，不在 workers 上！

**官方文档**：
- workers: https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-workers-transact-sql?view=sql-server-2016
- threads: https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-os-threads-transact-sql?view=sql-server-2016

**workers 关键列**：`worker_address / thread_address / scheduler_address / state / context_switch_count`

**threads 关键列**：`thread_address / os_thread_id / kernel_time / usermode_time`

**正确 JOIN**：
```sql
SELECT w.state, SUM(t.kernel_time) AS k, SUM(t.usermode_time) AS u
FROM sys.dm_os_workers w
JOIN sys.dm_os_threads t ON w.thread_address = t.thread_address
GROUP BY w.state;
```

## sys.dm_os_ring_buffers

**用途**：内部环形缓冲区，最有用的是 `RING_BUFFER_RESOURCE_MONITOR`（内存压力事件）和 `RING_BUFFER_SCHEDULER_MONITOR`（CPU 利用率）。

**关键列**：
| 列 | 含义 |
|---|---|
| `ring_buffer_type` | 类型 |
| `timestamp` | 事件时间戳（毫秒，相对启动） |
| `record` | XML 内容 |

**实战（最近 CPU 利用率，已修正 ms_ticks 溢出）**：
```sql
SELECT TOP 10
    record.value('(./Record/SchedulerMonitorEvent/SystemHealth/SystemIdle)[1]', 'int') AS SystemIdle,
    record.value('(./Record/SchedulerMonitorEvent/SystemHealth/ProcessUtilization)[1]', 'int') AS SQLCPU,
    100 - record.value('(./Record/SchedulerMonitorEvent/SystemHealth/SystemIdle)[1]', 'int')
        - record.value('(./Record/SchedulerMonitorEvent/SystemHealth/ProcessUtilization)[1]', 'int') AS OtherCPU,
    DATEADD(ms, rb.timestamp - tk.ms_ticks, GETDATE()) AS event_time
FROM (
    SELECT timestamp, CONVERT(XML, record) AS record
    FROM sys.dm_os_ring_buffers
    WHERE ring_buffer_type = 'RING_BUFFER_SCHEDULER_MONITOR'
      AND record LIKE '%<SystemHealth>%'
) rb
CROSS JOIN (SELECT ms_ticks FROM sys.dm_os_sys_info) tk
ORDER BY rb.timestamp DESC;
```
