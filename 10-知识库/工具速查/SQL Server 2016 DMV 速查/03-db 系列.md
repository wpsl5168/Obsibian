# 03 - sys.dm_db_* 系列（数据库与索引）

> 索引使用、碎片、缺失索引、空间。**索引调优的核心数据源**。

---

## sys.dm_db_index_usage_stats

**用途**：自实例启动以来，每个索引的使用统计。**判断索引是否该删的唯一依据**。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-index-usage-stats-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `database_id` / `object_id` / `index_id` | 主键三元组 |
| `user_seeks` | 用户 seek 次数 |
| `user_scans` | 用户 scan 次数 |
| `user_lookups` | 书签查找次数（聚集索引） |
| `user_updates` | 维护成本（INSERT/UPDATE/DELETE 都算） |
| `last_user_seek` | 最后一次 seek 时间 |
| `last_user_scan` | 最后一次 scan 时间 |
| `system_*` | 系统进程（统计信息维护等），通常无视 |

**找"只维护不读"的浪费索引**：
```sql
SELECT OBJECT_NAME(s.object_id) AS table_name, i.name AS index_name,
       s.user_seeks + s.user_scans + s.user_lookups AS reads,
       s.user_updates AS writes
FROM sys.dm_db_index_usage_stats s
JOIN sys.indexes i ON s.object_id = i.object_id AND s.index_id = i.index_id
WHERE s.database_id = DB_ID()
  AND i.type_desc = 'NONCLUSTERED'
  AND s.user_updates > 100
  AND s.user_seeks + s.user_scans + s.user_lookups = 0
ORDER BY s.user_updates DESC;
```

**坑**：
- 实例重启后清零，**至少要观察一个完整业务周期**（一周以上）再判断
- 2012 SP2 之前重建索引会清掉对应行的统计，要小心

## sys.dm_db_index_physical_stats(database_id, object_id, index_id, partition_number, mode)

**用途**：TVF，索引碎片率 + 页数 + 深度。**重建/重组判断依据**。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-index-physical-stats-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `database_id` / `object_id` / `index_id` / `partition_number` | 定位 |
| `type_desc` | HEAP / CLUSTERED / NONCLUSTERED |
| `avg_fragmentation_in_percent` | **逻辑碎片率**，关键指标 |
| `fragment_count` | 碎片段数 |
| `page_count` | 页数（< 1000 页不用管） |
| `record_count` | 行数 |
| `ghost_record_count` | 待清理的幽灵记录 |
| `avg_page_space_used_in_percent` | 页面填充度 |

**调用模式**（mode 决定开销）：
- `LIMITED`（默认）：扫 B-tree 非叶层，最快
- `SAMPLED`：抽样 1% 叶页
- `DETAILED`：全扫，最慢但最准

**实战（业内通用规则）**：
```sql
SELECT OBJECT_NAME(ps.object_id) AS tbl, i.name AS idx,
       ps.avg_fragmentation_in_percent, ps.page_count,
       CASE WHEN ps.avg_fragmentation_in_percent > 30 THEN 'REBUILD'
            WHEN ps.avg_fragmentation_in_percent > 10 THEN 'REORGANIZE'
            ELSE 'OK' END AS action
FROM sys.dm_db_index_physical_stats(DB_ID(), NULL, NULL, NULL, 'LIMITED') ps
JOIN sys.indexes i ON ps.object_id = i.object_id AND ps.index_id = i.index_id
WHERE ps.page_count > 1000
ORDER BY ps.avg_fragmentation_in_percent DESC;
```

## sys.dm_db_stats_properties(object_id, stats_id)

**用途**：TVF，统计信息的更新时间 / 采样比例 / 变更行数。**判断统计该不该更新**。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-stats-properties-transact-sql?view=sql-server-2016

**3 个核心列**：

| 列 | 含义 |
|---|---|
| `last_updated` | 最后更新时间 |
| `rows` | 表总行数 |
| `rows_sampled` | 采样行数 |
| `modification_counter` | 自上次更新后变化的行数 |

**实战（找过时统计）**：
```sql
SELECT s.name AS stat_name, sp.last_updated, sp.rows, sp.modification_counter,
       100.0 * sp.modification_counter / NULLIF(sp.rows, 0) AS modified_pct
FROM sys.stats s
CROSS APPLY sys.dm_db_stats_properties(s.object_id, s.stats_id) sp
WHERE sp.modification_counter > 1000
ORDER BY modified_pct DESC;
```

## sys.dm_db_missing_index_details

**用途**：优化器认为"如果有这个索引就好了"的清单。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-missing-index-details-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `index_handle` | 唯一 ID |
| `database_id` / `object_id` | 哪个表 |
| `equality_columns` | 等值条件列（放索引前置） |
| `inequality_columns` | 范围条件列 |
| `included_columns` | 建议 INCLUDE 的列 |

## sys.dm_db_missing_index_group_stats

**用途**：上面那些"建议索引"的**收益估算**。和 `missing_index_details` 配对用。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-missing-index-group-stats-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `group_handle` | JOIN 用 |
| `user_seeks` | 预计能用到的次数 |
| `avg_total_user_cost` | 平均查询代价 |
| `avg_user_impact` | 改善百分比（越高越值得加） |
| `last_user_seek` | 最近请求时间 |

**实战（生成"值得加的索引"建议）**：
```sql
SELECT
    OBJECT_NAME(mid.object_id) AS table_name,
    migs.avg_user_impact, migs.user_seeks,
    mid.equality_columns, mid.inequality_columns, mid.included_columns,
    'CREATE NONCLUSTERED INDEX IX_' + OBJECT_NAME(mid.object_id) + '_missing'
        + ' ON ' + mid.statement
        + ' (' + ISNULL(mid.equality_columns, '')
        + CASE WHEN mid.equality_columns IS NOT NULL AND mid.inequality_columns IS NOT NULL THEN ',' ELSE '' END
        + ISNULL(mid.inequality_columns, '') + ')'
        + ISNULL(' INCLUDE (' + mid.included_columns + ')', '') AS create_stmt
FROM sys.dm_db_missing_index_details mid
JOIN sys.dm_db_missing_index_groups mig ON mid.index_handle = mig.index_handle
JOIN sys.dm_db_missing_index_group_stats migs ON mig.index_group_handle = migs.group_handle
WHERE migs.avg_user_impact > 50
ORDER BY migs.avg_user_impact * migs.user_seeks DESC;
```

**坑**：
- 这是**建议**不是**真理**。优化器看的是单个查询，没考虑：维护成本、列宽、和现有索引的重叠、行级锁竞争
- 重启清零，要观察足够长的时间
- 单个查询只会触发一条建议，所以 `user_seeks` 不代表全局热度

## sys.dm_db_file_space_usage

**用途**：每个数据文件的空间使用，**专门看 tempdb 哪里满了**。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-file-space-usage-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `unallocated_extent_page_count` | 未分配 |
| `user_object_reserved_page_count` | 用户对象（#temp 表）|
| `internal_object_reserved_page_count` | 内部对象（sort/hash spill） |
| `version_store_reserved_page_count` | 版本存储（RCSI/快照隔离） |

**实战（tempdb 谁占满了）**：
```sql
USE tempdb;
SELECT SUM(user_object_reserved_page_count)*8/1024 AS user_mb,
       SUM(internal_object_reserved_page_count)*8/1024 AS internal_mb,
       SUM(version_store_reserved_page_count)*8/1024 AS version_mb
FROM sys.dm_db_file_space_usage;
```

## sys.dm_db_session_space_usage

**用途**：每个 session 在 **tempdb** 占用多少。配合上面那个找元凶。

**官方文档**：https://learn.microsoft.com/sql/relational-databases/system-dynamic-management-views/sys-dm-db-session-space-usage-transact-sql?view=sql-server-2016

**关键列**：

| 列 | 含义 |
|---|---|
| `session_id` | JOIN 键 |
| `database_id` | 通常 = 2 (tempdb) |
| `user_objects_alloc_page_count` | 分配 |
| `user_objects_dealloc_page_count` | 释放 |
| `internal_objects_alloc_page_count` | 内部分配 |

**实战（揪 tempdb 凶手）**：
```sql
SELECT s.session_id, s.login_name, s.host_name,
       u.user_objects_alloc_page_count*8/1024 AS user_mb,
       u.internal_objects_alloc_page_count*8/1024 AS internal_mb,
       t.text AS current_sql
FROM sys.dm_db_session_space_usage u
JOIN sys.dm_exec_sessions s ON u.session_id = s.session_id
LEFT JOIN sys.dm_exec_requests r ON u.session_id = r.session_id
OUTER APPLY sys.dm_exec_sql_text(r.sql_handle) t
WHERE u.database_id = 2
  AND u.user_objects_alloc_page_count + u.internal_objects_alloc_page_count > 100
ORDER BY user_mb + internal_mb DESC;
```
