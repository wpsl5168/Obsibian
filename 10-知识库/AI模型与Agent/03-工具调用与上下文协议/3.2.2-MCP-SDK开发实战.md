## SDK 与开发实战

官方提供 Python 和 TypeScript 两个 SDK,覆盖90%生产场景。核心设计哲学:**声明式定义 + 类型安全 + Transport抽象**。

### SDK架构对比

| 维度 | TypeScript SDK | Python SDK | 选型建议 |
| :--- | :--- | :--- | :--- |
| **性能** | 单线程事件循环,I/O密集型优秀 | 多进程/异步,CPU密集型可选 | Node.js生态 → TS; ML/数据科学 → Python |
| **类型安全** | 原生TypeScript + Zod校验 | Pydantic模型 | 两者都强,TS编译期检查更严 |
| **生态集成** | npm包丰富,前端工具链成熟 | PyPI包多,AI/ML库一等公民 | 看项目依赖 |
| **部署** | 单文件bundling简单 | 虚拟环境管理稍复杂 | Serverless → TS; 数据管道 → Python |

### 核心概念与机制

#### 1. Server声明与生命周期

**TypeScript SDK**：
```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";

const server = new McpServer({
  name: "my-server",
  version: "1.0.0",
  description: "企业数据分析MCP Server"
});

// 生命周期钩子
server.onStartup(async () => {
  await connectDatabase();
  console.log("数据库连接已建立");
});

server.onShutdown(async () => {
  await disconnectDatabase();
  console.log("清理完成");
});
```

**Python SDK**：
```python
from mcp.server import Server
import asyncio

server = Server("my-server")

@server.on_startup
async def startup():
    await connect_database()
    print("数据库连接已建立")

@server.on_shutdown
async def shutdown():
    await disconnect_database()
    print("清理完成")
```

#### 2. Tool定义的三要素

**必需三要素**：Name(唯一标识) + Description(LLM选择依据) + Input Schema(参数约束)

**反模式与最佳实践**：

| 问题 | 错误示例 | 正确示例 |
| :--- | :--- | :--- |
| Description过于泛泛 | "查询数据" | "从sales表查询指定时间范围的订单总金额,按品类分组。返回JSON数组。" |
| Schema过于宽松 | `{type: "object"}` | 用Zod/Pydantic定义精确类型 |
| 缺少错误处理 | 直接throw | 返回结构化错误:`{type: "error", message: "..."}` |

### TypeScript SDK 示例(生产级)

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "inventory-server",
  version: "1.0.0"
});

// 定义 Tool（带完整错误处理）
server.tool(
  "check_inventory",
  "查询商品库存。传入商品SKU，返回各仓库存量。支持通配符查询(如SKU-*)。",
  {
    sku: z.string().regex(/^SKU-[A-Z0-9]+$/).describe("商品SKU编码,格式SKU-XXXXX"),
    warehouse: z.enum(["east", "west", "all"]).optional().default("all"),
    include_reserved: z.boolean().optional().default(false).describe("是否包含预留库存")
  },
  async ({ sku, warehouse, include_reserved }) => {
    try {
      const result = await queryInventoryDB(sku, warehouse, include_reserved);
      
      if (result.length === 0) {
        return {
          content: [{
            type: "text",
            text: JSON.stringify({
              error: "NOT_FOUND",
              message: `SKU ${sku} 在 ${warehouse} 仓库未找到`
            })
          }]
        };
      }
      
      return {
        content: [{
          type: "text",
          text: JSON.stringify({
            data: result,
            timestamp: new Date().toISOString(),
            warehouse: warehouse
          })
        }]
      };
    } catch (error) {
      // 结构化错误返回
      return {
        content: [{
          type: "text",
          text: JSON.stringify({
            error: "QUERY_FAILED",
            message: error.message,
            retry_after: 5000
          })
        }],
        isError: true
      };
    }
  }
);

// 定义 Resource(动态内容)
server.resource(
  "inventory://daily-report/{date}",
  "每日库存汇总报表。{date}格式: YYYY-MM-DD",
  async (uri) => {
    const date = uri.match(/(\d{4}-\d{2}-\d{2})/)?.[1];
    if (!date) {
      throw new Error("Invalid date format");
    }
    
    const report = await getDailyReport(date);
    return {
      contents: [{
        uri: uri,
        mimeType: "application/json",
        text: JSON.stringify(report)
      }]
    };
  }
);

// 定义 Prompt(可复用的LLM指令模板)
server.prompt(
  "analyze-low-stock",
  "分析低库存商品并生成补货建议",
  {
    threshold: z.number().min(0).max(100).describe("库存阈值(%)"),
    warehouse: z.enum(["east", "west", "all"]).optional()
  },
  async ({ threshold, warehouse }) => ({
    messages: [
      {
        role: "user",
        content: {
          type: "text",
          text: `分析${warehouse || "所有"}仓库中库存低于${threshold}%的商品，
生成补货建议（包括建议订购量、优先级、预估到货时间）。
请以表格格式输出，按优先级排序。`
        }
      }
    ]
  })
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

**关键要点**：
1. **Zod校验**：SDK自动拒绝不符合schema的请求
2. **结构化错误**：用JSON而非异常，LLM可解析重试
3. **Resource动态URI**：支持参数化路径(类似REST API)
4. **Prompt复用**：预定义分析模板，Agent直接调用

### Python SDK 示例

```python
from mcp.server import Server
from mcp.types import Tool, TextContent

server = Server("my-tool-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="calculate",
            description="计算数学表达式",
            inputSchema={
                "type": "object",
                "properties": {
                    "expression": {
                        "type": "string",
                        "description": "数学表达式，如 '2+3*4'"
                    }
                },
                "required": ["expression"]
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "calculate":
        result = eval(arguments["expression"])  # 生产环境请用安全的解析器
        return [TextContent(type="text", text=str(result))]

# 启动：stdio 传输
if __name__ == "__main__":
    import asyncio
    from mcp.server.stdio import stdio_server
    asyncio.run(stdio_server(server))
```

> [!tip] .NET 类比
> 这和写一个 ASP.NET Minimal API 的体验几乎一样——定义路由(`list_tools`)、处理请求(`call_tool`)、启动服务。

### .NET 社区 SDK（非官方）

社区有非官方的 .NET MCP SDK 实现 [待验证]，基本思路：

```csharp
// 概念性示例：用 Attribute 声明 MCP Tool
public class WeatherMcpServer : McpServerBase
{
    [McpTool("get_weather", "查询城市天气")]
    public async Task<string> GetWeather(
        [McpParam("城市名称")] string city)
    {
        var weather = await _weatherService.GetAsync(city);
        return JsonSerializer.Serialize(weather);
    }
}
```
