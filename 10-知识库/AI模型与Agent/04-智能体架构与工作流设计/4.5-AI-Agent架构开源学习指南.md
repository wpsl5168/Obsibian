## 一、Agent 核心概念速查

在深入源码之前，先把 5 个核心概念对齐。这些概念贯穿所有框架，只是实现方式不同。

### 1.1 ReAct（Reasoning + Acting）

Agent 的基础思考范式。核心是 **Thought → Action → Observation** 的闭环循环：LLM 先思考该做什么，调用工具执行，观察结果，再决定下一步。几乎所有 Agent 框架的底层都是这个循环。

> [!tip] 关键洞察
> ReAct 的本质是把 Chain-of-Thought 和 Tool Use 统一到同一个循环里。"思考"和"行动"不是两个独立模块，而是交替进行的。

### 1.2 Tool Use（工具调用）

Agent 的"手脚"。LLM **不执行**工具，只生成调用指令（函数名 + 参数 JSON），框架负责实际执行并把结果喂回上下文。标准化协议参见 [[MCP规范]]。

### 1.3 Memory（记忆系统）

- **短期记忆**：当前对话的 Context Window，受 token 上限约束
- **长期记忆**：向量数据库 / 持久化存储，通过 RAG 按需检索加载
- **工作记忆**（部分框架支持）：Scratchpad，用于中间推理状态的暂存

详见 [[4.3-记忆机制设计]]。

### 1.4 Planning（规划）

两大范式：
- **ReAct 式增量规划**：走一步看一步，每次只决定下一个 Action
- **Plan-and-Execute**：先生成完整计划，再逐步执行，执行中可动态修正

复杂任务首选 Plan-and-Execute，详见 [[4.2-工作流编排模式]]。

### 1.5 Multi-Agent 协作模式

| 模式 | 核心思想 | 代表框架 |
|---|---|---|
| Handoff（交接） | Agent A 完成后将控制权转给 Agent B | OpenAI Agents SDK |
| 对话驱动 | Agent 之间通过消息传递协商 | AutoGen |
| 角色扮演 | 每个 Agent 有明确的 Role/Goal/Backstory | CrewAI |
| SOP 驱动 | 按标准流程分配角色和阶段 | MetaGPT |
| 图编排 | 用有向图定义 Agent 间的状态流转 | LangGraph |

详见 [[Workflow设计模式]]。

## 二、理论基础（精选 3 个）

### 2.1 huggingface/agents-course ⭐28K

> [!note] 为什么值得看
> HuggingFace 官方 Agent 课程，目前最系统的入门教程。从 ReAct 循环、Tool Use 到 Multi-Agent，有代码有练习，不是纯论文堆砌。

**核心架构洞察：**
- 完整拆解 ReAct 循环的每一步：system prompt 如何引导 LLM 输出结构化的 Thought/Action/Observation
- 演示了 Code Agent 范式——LLM 直接生成 Python 代码而非 JSON 来调用工具，比传统 JSON 调用更灵活
- 配合 `smolagents` 库有可运行的 notebook

**学习建议：** 作为第一站，花 2-3 天过完核心章节。

🔗 `https://github.com/huggingface/agents-course`

### 2.2 xindoo/agentic-design-patterns ⭐3.5K

> [!note] 为什么值得看
> Andrew Ng 推荐的 21 种 Agent 设计模式，中文总结，每个模式一图一例。适合建立设计模式的全局视野。

**核心架构洞察：**
- 将 Agent 模式从简到繁分为 4 大类：Reflection、Tool Use、Planning、Multi-Agent
- 每种模式的适用场景和局限性都有说明，帮你判断"什么时候不需要 Agent"
- 和 Anthropic 的 *Building Effective Agents* 互为补充

**学习建议：** 当速查手册用，遇到具体场景时回来对照选型。

🔗 `https://github.com/xindoo/agentic-design-patterns`

### 2.3 WooooDyy/LLM-Agent-Paper-List ⭐8K

> [!note] 为什么值得看
> 基于 86 页权威 Survey 论文的结构化论文列表。提出 Agent 三大模块模型：**Brain（推理引擎）/ Perception（感知）/ Action（执行）**，是理解 Agent 架构最经典的理论框架。

**核心架构洞察：**
- Brain 模块不只是 LLM 推理，还包括 Knowledge（知识）和 Memory（记忆）的管理
- 将 Multi-Agent 通信分为 Cooperative / Competitive / Debate 三种范式
- 和另一篇 Survey（Paitesanshi/LLM-Agent-Survey）的四组件模型（Profile/Memory/Planning/Action）互补，两篇对照读效果最好

**学习建议：** 不需要通读所有论文，把 Survey 本体的架构图搞懂即可，具体论文按需深入。

🔗 `https://github.com/WooooDyy/LLM-Agent-Paper-List`

## 三、框架源码精读（精选 5 个，从简到繁）

> [!tip] 读源码的正确姿势
> 不要试图读完整个代码库。锁定"一个请求从进入到产出最终回复"的主链路，搞懂核心循环即可。

### 3.1 openai/swarm ⭐21K — 极简起点

> [!note] 为什么值得看
> 整个框架只有 **一个核心文件**（`swarm/core.py`，约 300 行）。OpenAI 官方用最少代码诠释了 Agent 的两个核心抽象：**Agent**（带指令和工具的 LLM 配置）和 **Handoff**（Agent 间的控制权转移）。

**核心架构洞察：**
- Agent 的本质就是 `{instructions, tools, model}` 三元组
- Handoff 的实现极其简单——工具返回另一个 Agent 对象，主循环切换当前 Agent
- `run_loop` 函数是理解所有 Agent 框架的起点：`while tool_calls: execute → append → call_llm`

**学习建议：** 第一个要读的源码。300 行读完，Agent 框架就不再神秘。

🔗 `https://github.com/openai/swarm`

### 3.2 openai/openai-agents-python ⭐21K — 生产级进化

> [!note] 为什么值得看
> Swarm 的正式生产版本。在极简双概念基础上增加了 **Guardrails**（输入输出校验）、**Tracing**（链路追踪）、**Structured Output**（类型安全输出），展示了从 PoC 到生产的完整演进。

**核心架构洞察：**
- Guardrails 架构：tripwire 模式——校验失败时立即中断 Agent 循环，而非等到最终输出
- Tracing 的实现：基于 context var 的 span 嵌套，可无缝对接 OpenTelemetry
- 和 Swarm 对比读，能清晰看到"极简原型"到"生产框架"需要加什么

🔗 `https://github.com/openai/openai-agents-python`

### 3.3 huggingface/smolagents ⭐27K — Code Agent 范式

> [!note] 为什么值得看
> 提出了和传统 JSON Tool Calling 不同的路线：**LLM 直接生成 Python 代码来编排工具调用**。代码可以有循环、条件、变量——表达能力远超 JSON。

**核心架构洞察：**
- Code Agent vs JSON Agent：Code Agent 用 `exec()` 执行 LLM 生成的代码，沙箱隔离是关键挑战
- 工具被注入为 Python 函数，LLM 在代码中直接 `result = search("query")` 调用
- 安全机制：AST 分析 + import 白名单 + 执行超时，理解这些比理解 Agent 循环本身更重要

🔗 `https://github.com/huggingface/smolagents`

### 3.4 langchain-ai/langgraph ⭐29K — 图驱动编排

> [!note] 为什么值得看
> 当 Agent 逻辑超出简单 ReAct 循环时（分支、并行、子流程、人工审批），LangGraph 用**有状态有向图**来建模。是目前复杂 Agent 编排的事实标准。

**核心架构洞察：**
- `StateGraph` 的核心：节点是函数/子 Agent，边是条件路由，状态（TypedDict）在节点间流转
- Checkpointing 机制：每个节点执行后自动持久化状态，支持断点续跑和 Human-in-the-Loop
- `send()` API 实现动态 Map-Reduce：运行时创建并行分支，汇总结果
- 核心抽象可类比 .NET Durable Functions 的编排模式

🔗 `https://github.com/langchain-ai/langgraph`

### 3.5 microsoft/autogen ⭐57K — 对话驱动 Multi-Agent

> [!note] 为什么值得看
> 微软出品，Multi-Agent 领域影响力最大的框架。核心理念：Agent 之间通过**异步消息传递**协作，像群聊一样交流达成共识。

**核心架构洞察：**
- `AgentChat` API：定义了 `on_messages` 接口，所有 Agent 统一消息协议
- `GroupChat` 的 Speaker Selection：用 LLM 或规则决定"谁下一个发言"，这是 Multi-Agent 编排的核心难题
- v0.4+ 重构为 Actor 模型，支持分布式部署
- 和 CrewAI 的角色扮演模式对比：AutoGen 偏"自由讨论"，CrewAI 偏"按剧本演"

🔗 `https://github.com/microsoft/autogen`

## 四、实战项目精读（精选 4 个）

### 4.1 pguso/ai-agents-from-scratch ⭐3.4K — 从零手写 Agent

> [!note] 为什么值得看
> 不依赖任何框架，用纯 Python 从零实现 ReAct Agent、Tool Use、Memory。代码量小（每个模块 100-200 行），是理解底层原理的最佳材料。

**核心架构洞察：**
- 手写 ReAct 循环：`while True: response = llm(messages); if has_tool_call: execute_and_append; else: break`
- 手写 Tool Registry：函数装饰器 + JSON Schema 自动生成，理解框架的工具注册机制
- 手写 Memory：对话历史截断 + 摘要压缩，理解 Context Window 管理

**学习建议：** 读完 Swarm 源码后，自己动手照这个项目复现一遍，效果远超读 10 个框架。

🔗 `https://github.com/pguso/ai-agents-from-scratch`

### 4.2 FoundationAgents/MetaGPT ⭐67K — SOP 驱动的 Multi-Agent

> [!note] 为什么值得看
> 不是让 Agent 自由讨论，而是按**软件工程 SOP（标准作业流程）**分配角色：Product Manager → Architect → Engineer → QA。每个角色有明确的输入输出 Schema。

**核心架构洞察：**
- **Structured Communication**：Agent 之间不传自然语言，传结构化文档（PRD、设计文档、代码）
- **Action 与 Role 解耦**：Action 是可复用的原子能力，Role 是 Action 的编排容器
- **Environment 作为共享黑板**：所有 Agent 通过发布-订阅读写共享状态，而非点对点通信
- 对比 AutoGen 的自由对话模式，MetaGPT 用 SOP 约束大幅减少了"Agent 废话"和无效循环

🔗 `https://github.com/FoundationAgents/MetaGPT`

### 4.3 assafelovic/gpt-researcher ⭐26K — Plan-and-Execute 范式

> [!note] 为什么值得看
> Plan-and-Execute 架构的最佳实战案例。先规划研究大纲（Plan），再并行搜索各子主题（Execute），最后综合生成研究报告。

**核心架构洞察：**
- 两阶段架构：Planner Agent 生成研究计划 → Researcher Agent 并行执行各子任务 → Writer Agent 综合报告
- 搜索结果的去重、排序、摘要压缩——这是 RAG 在 Agent 场景下的实战范本
- Token 预算管理：大量搜索结果需要智能截断，展示了 Context Window 管理的工程挑战

🔗 `https://github.com/assafelovic/gpt-researcher`

### 4.4 bytedance/deer-flow ⭐61K — 长时复杂任务 Agent

> [!note] 为什么值得看
> 字节跳动出品，面向需要长时间运行（分钟到小时级）的复杂研究任务。展示了 Agent 在"超长任务"场景下的架构应对。

**核心架构洞察：**
- 基于 LangGraph 构建，展示了图编排在真实产品中的落地方式
- Research Team 架构：Coordinator → Planner → 多个 Researcher → Reporter，分工明确
- 支持 Human-in-the-Loop：长任务中人工可以在关键节点介入审批或调整方向
- 状态持久化 + 断点续跑：长时任务必备能力，可以学到 Checkpoint 的工程实践

🔗 `https://github.com/bytedance/deer-flow`

## 五、推荐学习路径

```
Week 1：建立概念
  ├─ 通读 agents-course 核心章节（ReAct / Tool Use / Multi-Agent）
  └─ 浏览 agentic-design-patterns 建立模式全景

Week 2：源码拆解
  ├─ 精读 Swarm（300 行理解 Agent 本质）
  ├─ 精读 openai-agents-python（理解 PoC → 生产的差距）
  └─ 精读 smolagents（Code Agent 范式对比）

Week 3：动手复现
  ├─ 跟着 ai-agents-from-scratch 手写 ReAct Agent
  └─ 用 LangGraph 搭一个 Plan-and-Execute 工作流

Week 4：深入 Multi-Agent
  ├─ 读 MetaGPT 源码（SOP 驱动的结构化协作）
  ├─ 读 AutoGen 源码（对话驱动的自由协作）
  └─ 读 gpt-researcher（Plan-and-Execute 实战）
```

> [!tip] 学习原则
> **先窄后宽**：先把一个框架（建议 Swarm → LangGraph）吃透，再横向对比其他框架。看 10 个框架的 README 不如读 1 个框架的核心循环源码。
